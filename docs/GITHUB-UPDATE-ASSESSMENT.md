2026-10-12：下方评估为历史背景。本轮已获用户授权并实现独立公开安装包仓库 `wfjdyhmtr2-glitch/dewu-bluev-releases`；客户端使用 `githubupdates.js`，不恢复旧 COS 更新器。具体行为和验证见 `RELEASE-1.1.1-AUTH-FIX.md`。

## 当前配置

App 的更新 IPC 统一返回 disabled，启动流程不再加载旧更新模块。本地分发记录显示源码仓库为私有，曾上传的安装包 Release 为草稿；本次匿名 API 请求返回 403，响应明确为 API rate limit exceeded、剩余额度为零，不能据此确认当前远端 Release 状态。

## 实现卡点

1. 私有仓库的资产下载需要授权，普通用户不能仅凭 App 登录直接下载私有 GitHub Release。不能把发布者 GitHub token 打包进客户端。
2. GitHub latest API 只选择已发布、非草稿、非预发行版本。需先有对目标用户可访问的正式下载渠道。
3. 版本暂统一为 1.1.1，单比较版本号不能区分不同修复包。需独立构建编号和 SHA-256，以判断同版本号的新构建；发布清单与安装包应一致。
4. GitHub API 及下载受用户网络、访问权限和限流影响；失败应显示暂时无法检查，不能显示已是最新版，也不能影响业务登录。

## 建议落地

源码仓库保持私有。若允许安装包公开，使用独立的公开分发仓库，仅放安装包和版本清单；如果安装包也需私有，增加服务端授权下载接口，由服务器保存 GitHub 凭据，客户端使用 App 会话访问。后一方案需额外服务端实现和下载流量评估。

客户端提供检查更新按钮，并定时读取轻量清单。检测到更新显示版本/构建、说明和下载按钮；用户主动下载，下载后校验 SHA-256，再由用户决定何时安装。默认不自动重启，不中断运行中的任务。

旧 App 必须先手动安装包含新检查入口的安装包，才能收到后续提示。

官方接口说明：https://docs.github.com/en/rest/releases/releases?apiVersion=latest
