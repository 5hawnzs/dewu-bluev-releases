## 1. 另一台设备的卡点

- 现象：5 图图文发布失败，报 `找不到「com.shizhuang.duapp:id/etTitle」；当前可见文本：1 / 5 / 下一步`。
- 用户提供的现场截图：图片编辑页上盖着「正在导出图片 90% / 请不要退出得物」。
- **口径**：这只是同一句报错的一种可能成因，不能据此认定唯一真因。另一种同样常见的是

## 2. 修复内容

### transition.run（src/main/services/transition.js）

- 同一屏签名不变时最多点 3 次，两次之间至少 2.4s；每次点击前都重新抓屏、确认仍只有一颗「下一步」。
- 屏幕出现 `正在导出图片 / 请不要退出得物 / 正在处理图片 / 正在保存图片 / 图片导出中` 时**一次都不点**，
  等下一轮抓屏；遮罩消失后的那一轮立刻点（不额外加固定等待）。
- 点击点恢复按钮 `bounds` 的几何中心（本机 1080×1920 实测 986,1843）。
  之前「按钮高度 35% 处」没有实测证据，已撤回。
- 分段编辑屏（`i / N` + 唯一「下一步」）视为合法来源屏；目标页未到时按上面的限次规则推进。

### publisher（src/main/services/publisher.js）

- `waitId` / `tapId` 等不到目标时，遇到分段编辑屏会调 `advanceStage` 往下推一段，不再干等超时。
- 行级失败不再一律停批：先收回现场（首页/草稿箱）把**这一条**重走一次；仍失败则记这一条失败、
  收回现场后继续下一条。
- 仍然停批的只剩三种：定位表坐标整表不匹配（`UI_COORDINATES`）、现场收不回来
  （正在上传 / 没有「保存并退出」这种不丢内容的出口）、用户取消。
- 相册/媒体就绪段（`albumready`）的错误只记这一条失败、**不重走**：
  第一次尝试可能已经写进 `.nomedia`，第二次会把「隔离已确认」当成放行依据，
  等于把 rm 没删掉的旧素材静默当成清干净（回归用例 `139 且库暂空但物理文件仍在` 盯着这一点）。

### 前端（src/renderer/app.js + styles.css）

- 发布表格里的失败原因只显示一句话（完整原因仍写进运行日志 / 云端日志 / 回写报告），
  单元格最多两行，行高不再被长日志撑开；完整原因放在悬停提示里。
