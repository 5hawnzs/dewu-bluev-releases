六段流水线

一个人当天能跑完的一条链路：每一步的产物就是下一步的输入。

1
素材整理建扁平副本页签 1
产物：扁平副本目录（原素材不动）
  • 先秒级出「待整理清单」（只读元数据），再后台建扁平副本
  • 扁平名用连接符把原层级接起来：8124MT_UWG450159+灰色+达人昵称_1
  • 原素材 不改名、不移动，只建副本
  • 同卷优先硬链接（实测 1692 个 < 2 秒），跨卷自动退化为实体复制
  • 目录被占用（网盘/看图软件）指数退避重试；非法字符 < > : " | ? * 替换为 _
→
2
合规检查判定与处理分离页签 2
产物：合规报告 xlsx（汇总 + 明细）+ csv
  • 图片必须 JPG；边长与体积都只卡下限（上限能力保留，开关 enforceMaxSide / enforceMaxMB 默认关）
  • 边长低于下限 ⇒ 判「需更换图片」交人工（不会标成「等比缩放」—— 缩放函数只缩不放）
  • 垃圾文件隔离到 _rejected 而不是删除；判定与处理分离，只处理可自动项
  • 视频必须 mp4 且 < 600 秒；非 mp4 自动转（先无损转封装、再转码兜底，内置 ffmpeg）
  • 超时长只标红不裁剪（裁剪会改变内容，可能被判非原创）
  • 支持「检查父目录」：每个子文件夹独立出一份报告并分组展示
→
3
文案生成看图写，成句不成标签页签 3
产物：<品牌>_AI内容报告_<时间戳>.xlsx
  • 把这一条素材的前几张实拍图真的发给模型（缩到 imageMaxSide、JPEG base64、不落盘）
  • 标题＝产品词 + 热门词，写成一句念得通的话；+ 一个字都不许出现
  • 10 种句式骨架 T01~T10 按行轮换，每条骨架自带连接字或收尾（结构性防病句）
  • 正文＝4~5 行短句（一行 8~16 字），全篇 1~3 个 emoji 放行尾
  • 话题＝必带话题 + 品牌提示词里的 #话题，逐行进正文末尾的格子
  • 连不上就停下报错，绝不拿本地模板冒充 AI 文案
→
4
货号颜色校验只拦「多色漏填」页签 4
产物：逐行结论（一致 / 告警 / 拦截）
  • 取色来源两种：本地商品池（CSV/TSV/JSON）或接口查询（endpoint + SKU APIKey）
  • 结论口径：颜色匹配 / 单色货号颜色可空 / 多色须指定 / 货号未查到颜色信息
  • 额外用图片实取主色反查目录里填的色名（目录写「冠军白」但图是黑的会被抓出来）
  • ★ 只有「多色货号没填颜色」会拦住发布；查不到、颜色不符都只告警、照常发布
→
5
发布单 / 导入26 列 xlsx 闭环
产物：发布单 xlsx（26 列，结果回写 B/C 列）
  • 导出 26 列，校验未通过的整行标红；也能把「AI 内容报告」反向导入当发布单
  • ★ 独立的「发布单」页签已删除（与「模拟器发布」高度重复）⇒ 导出/导入入口都在「模拟器发布」页
  • 叶子文件夹名写 货号+颜色 ⇒ 报告里空着的货号/颜色自动补齐并写回报告文件
  • 只补空格子；报告值与目录对不上时不补（宁缺勿错）；名字不合法时不猜、点名让人改
  • 回写时 Excel 被 WPS 占用 ⇒ 整批暂存 pending-results.json，下次先补写
→
6
模拟器发布真实通道 / 模拟通道页签 6
产物：publish-log.jsonl + 截图 + 结果回写
  • 真实通道（adb + uiautomator）与模拟通道（mock）两条，界面顶部一眼可见当前走哪条
  • 发布前按 MediaStore 判据清空相册（得物相册是全盘聚合视图）
  • 中文/含空格文案走 ADB_INPUT_B64 精确通道，input 后必回读校验
  • 点完「提交发布」必须确认真的离开发布流程才算成功；失败先截图再 force-stop
  • 固定/随机间隔 + 倒计时；单条记耗时；失败自动回退到干净起点

发布通道：真机 vs 演练

同一条流程代码，两种执行后端；界面顶部一眼可见当前走哪条。

真实通道（adb）模拟通道（mock）
触发条件找得到 adb（手填 > 内置 > PATH）、设备在线、得物包名识别到、uiautomator 可用上述任一不满足
做什么推图到 /sdcard/DCIM/Camera + 触发媒体扫描 → uiautomator dump 抓界面 → 按定位表点击/输入只跑流程：节奏、重试、jsonl 追加、Excel 回写
失败表现报真原因（找不到节点会列出当前可见文本）+ 自动存失败截图随机失败，仅用于演练
更新 & 发版
源
腾讯云 COS 桶根目录（build.publish，编译进包）
通道
正式版读 latest.yml、测试版读 beta.yml；共用同一个安装包
切通道
设置页点一下即可，不用重装；只有管理员能切，普通成员登录时自动收回并落盘
检查 / 下载 / 安装
全部由用户点：无定时轮询、无自动下载、无自动重启
安装闸门
有任务在跑时拦住安装（重启会把跑一半的发布掐断，且没有回滚）

绝不许破的约束

这些不是建议，是踩过坑之后写下来的红线（出处：AGENTS.md §一）。

1
项目目录不许改名 / 移动

配置与构建产物里存的是绝对路径。改名 ⇒ 素材扫不到、发布单回写落到别处。

2
app.js / store.js 不许整文件重写

只许局部替换 —— 这两个文件可能同时有别的会话在改，整文件重写会覆盖别人的在制品。

3
每改一处必须跑回归

node tools/run-all.js。全绿 ≠ 通过：还要答得出「我改掉了哪条判断、哪条断言会变红」。

4
注释与界面文案一律中文

含日志文案、错误提示、按钮名。

5
不许造假成功

取不到就写「取不到」/「—」，未知 ≠ 0；失败必须说清「缺什么」。

6
发布前必须清空设备相册

得物相册是全盘聚合视图 ⇒ 判据是 MediaStore 清空，不是「某个目录为空」。

7
自动更新两条红线

绝不自动重启安装（会掐断正在跑的发布）；不在运行时改源地址（地址编译进包）。

8
凭据绝不入库

.env 已忽略；service_role / secret key 绝不许写进任何前端文件。

9
安装包不进 git

二进制一旦进历史就删不干净 ⇒ 走 Releases / 网盘分发。

版本线

权威源：package.json 的 version 字段变更史（共 17 个版本）。 谁把版本号改成它，就是哪一次提交 —— 不按提交说明猜，所以不会漏（说明里常不写版本号）也不会把「补档文档」当成发布。
