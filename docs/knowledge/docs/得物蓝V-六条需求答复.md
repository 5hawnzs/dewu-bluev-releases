## 〇 总纲｜只有管理员能进测试版（已实现）

**你的原话**：「只有管理员才能登陆测试版，其他用户在登陆正式版时，设置处不能看到有任何测试版、测试版本的字样」

做成了**三层**，缺一层都不算拦住：

| 层 | 做法 | 在哪 |
| --- | --- | --- |
| ① 界面**藏**（不是禁用） | 非管理员在「设置 → 应用更新」里，**连「测试版」这三个字都不渲染** —— 不是 `disabled`、不是置灰 | `app.js#updateHtml()` |
| ② 主进程**拦** | `update:set-channel` 从 `guard()` 提级为 **`guardAdmin()`** | `src/main/ipc.js` |
| ③ ★ **落盘复核** | 通道是**存在 `config.json`** 里的，换人登录必须复核并收回 | `updater.enforceChannelPermission()` + `ipc.syncChannelPermission()` |

**为什么必须有第 ③ 层**（这是实现时才想透的一条）：
管理员把通道切成测试版 → 退出 → **普通成员登录** ⇒ 配置里那个 `beta` 还在，
**他会一直收到测试包，而那个按钮他根本看不见、无法自救**。
所以「不是管理员就收回通道」不能只在「点按钮」那一刻校验，必须在 **`auth:login` 成功之后** 和
**启动时**（勾了「记住我」时启动就已经是登录态）各跑一次。收回时会写一条日志说明是谁被收回的。

⚠️ **诚实说明**：这**不是安全边界**。`config.json` / `auth.json` 就在本机 `%APPDATA%` 下，
能碰这台机器的人**直接改文件**就行。它的作用是 **① 防误收到没验收过的包 ② 让"我这边是正式版"这句话对得上账**，
不是防内部恶意越权。

## 一｜发版节奏（你问的第 1 条）

你的理解**基本对**，但有一处要纠正、一处要补充。

### 正确的节奏

```
你提需求 → 我改代码 → 【必须有人执行一次发版】→ 测试版那台点「检查更新」→ 你验收
                    → 你确认没问题 → 涨成正式版本号 → 再发一次 → 正式版用户才收到
```

| 步骤 | 命令 | 说明 |
| --- | --- | --- |
| 发测试版 | `npm run dist:release:beta` | 打包 + 上传，清单名叫 `beta.yml` |
| 发正式版 | `npm run dist:release` | 打包 + 上传，清单名叫 `latest.yml` |

- ★ **纠正**：「测试版自动更新」**不等于**「我改完你那儿自动就有了」。中间**必须真的跑一次发版命令**
  把包和清单**上传到对象存储**。原因是 electron-updater 的 generic provider **不会替你上传** ——
  漏了这步的症状很隐蔽：**源上还是旧清单，应用永远说「已是最新」，而且不报任何错**（这条实测踩过）。
- ★ **补充**：你说的「点推送」对应的就是 `npm run dist:release`。
- **版本号规则**：发正式版时**不能用测试版号**（如 `1.0.1-beta.1`），脚本会拦下（`channelMismatch` 闸门）；
  反过来（正式号发测试通道）也拦。当前 `package.json` 是 `1.0.1-beta.1`，
  所以下一轮要么 `1.0.1-beta.2`（继续测），要么验收通过后 `1.0.2` 走正式。
- ★ 打包前记得**清掉 `dist/` 里的旧 exe**：electron-builder 不清理 `dist/`，
  新旧两个包并存时上传脚本会拦下（实测踩过）。

### 「测试版和正式版共存并同时开启」——这里要纠正一个可能的误解

| | 能不能 |
| --- | --- |
| 源上两条通道**同时存在** | ✅ `latest.yml` 和 `beta.yml` 就放在桶根**同一层**，互不干扰 |
| 同一台机器**随时切**通道 | ✅ 设置里点一下，不用重装（**源地址不变**，只是换读哪个清单） |
| 同一台机器**同时装**正式版和测试版**两个** | ❌ **做不到** |

最后一条的原因（看了 `package.json` 确认）：`appId` 只有一个（`com.bluev.publisher`）、
`productName` 只有一个、`win.target` 只有 `nsis`（没有 side-by-side 安装）
⇒ **同一个安装目录，后装的会覆盖先装的**。

⇒ 所以「共存」的正确含义是 **两条通道并存于源上 + 客户端随时可切**，
**不是**同一台机器装两份版本。顺便说：测试版和正式版**本来就是同一个安装包**（同一个 exe），
区别只在运行时读哪份清单。

## 二｜批次设置里的「轮换策略」是做什么的

它只管**两样东西**：**标题格式（F01–F10）** 和 **叙事视角** 怎么分配给这一批里的每一篇。

| 选项 | 行为 | 特点 |
| --- | --- | --- |
| **`F01-F10 轮换`（默认）** | 第 i 篇用 `FORMATS[i % 10]`、视角用 `ANGLES[(i*3) % 10]` | **确定性**：同一批素材跑两次结果完全一样；10 种格式按顺序铺开、不扎堆 |
| **`随机`** | 每篇各自 `Math.random()` 挑 | 每篇独立随机，**不可复现** |

- **10 种标题格式**：`F01 细节质感`、`F02 场景代入`、`F03 配色思路`、`F04 季节钩子`、`F05 情绪表达`、
  `F06 穿搭上身`、`F07 材质工艺`、`F08 性价比`、`F09 提问互动`、`F10 清单盘点`
- **10 种视角**：细节质感 / 配色思路 / 穿搭上身 / 材质工艺 / 季节钩子 / 场景代入 / 情绪表达 /
  性价比 / 身材修饰 / 清洗打理

★ **一个容易误会的地方**：**「话题组合」不受这个设置影响**。
话题永远走代码里的去重逻辑（池子容量不够会明确告警），跟「轮换 / 随机」无关。

**怎么选**：想要这一批的标题有节奏、且**能复现** → 用轮换（默认）；
想要每篇更"跳"一点、不在意复现 → 用随机。

## 三｜提示词配置的两个按钮（已实现）

按你选的语义：**「选择」= 本次用它（不落盘）**、**「默认选择」= 设为长期默认（落盘）**。

- **位置**：文案生成 → 提示词配置 → 弹窗里每个品牌那一行、「配置」按钮的右边
- **「选择」**：只改**本次运行**用哪个品牌，重启回到默认；行上带 `本次` 小标
- **「默认选择」**：写进配置 `copy.defaultBrandId`，长期生效；行上带 `默认` 小标
- ★ 两个按钮**故意不是同一件事**，回归里有断言盯着：点「选择」时配置**不许**变，点「默认选择」才变 ——
  万一将来有人把它俩做成同一件事，测试会红。
- ★ 点「选择」后，标题栏那个品牌下拉会**立刻跟着变**（不这样的话你看不出到底生效没）。

## 四｜自检怎么用 · 「导入 UI 表」是什么 · 为什么你这台自检全错

### 4.1 自检是干什么的

模拟器发布页有「自检」：真的去问一遍 adb「认不认得设备、能不能截屏、能不能抓界面结构」，
七项逐条回 ✅/❌。它是**发布前的体检**，不是走过场 —— 真实通道缺任何一项都发不出去。

### 4.2 「导入 UI 表」是什么

就是**「UI 定位表」**（代码里叫 `uiMap`）。为什么需要它 ——
**得物发布页的控件没有可用的文字/描述**（真机实测）：

- 发布入口 `com.shizhuang.duapp:id/ivCamera`：**无 `text`、`content-desc` 为空**
- 整个 App 的 `content-desc` **一律为空** ⇒ `tapDesc` 这类"按描述点"一步都用不了
- 相册格子（`imgThumb`）**连文字都没有**，只有个勾选圈

⇒ 靠"找到文字点下去"这条路走不通，只能**记坐标 / 资源 id**。

**所以流程是**：

1. 在发布页点「**抓取页面结构**」→ 工具 dump 当前界面，输出 `dumps/uiMap-<时间>.json`
   （里面是**按关键词猜出来的一套候选步骤**，带 `${title}` `${body}` `${topic1..5}` `${sku}` 占位符）
2. 你把里面**猜错的坐标改对**
3. 点「**导入 UI 定位表**」
4. 之后发布就按这张表来点

★ **没配就直接报错，不会假装成功**（这条是刻意设计的）。
视频另有一套 `videoSteps` —— 视频发布页和图文发布页**不是同一套界面**，图文那套套不上。

### 4.3 为什么你这台自检全是错误 —— 最可能的原因

我在本机（MuMu 12）实测过：**用对 serial 就是 7/7 全绿**。所以最可能是下面两条之一：

1. ★★ **设备 serial 不对**（我自己也踩过，概率最高）：
   MuMuManager 报的是 `127.0.0.1:16385`，而 adb 真正认到的是 **`emulator-5554`** ——
   **两个字符串不是一回事**。填错 ⇒ 每一项都失败，**看着像设备坏了，其实设备好好的**。
   ⇒ 现在自检**会直接把「应该选哪个」写给你**，照着改即可。
2. **adb 找不到**：以前自检提示里写着「或在设置里填 adb 完整路径」，但**那个配置项根本不存在**
   —— 是一条死路（我的疏忽，已修）。现在「模拟器发布 → **adb 路径**」是**真的**：
   填 `D:\MUMU\MuMuPlayer\nx_main\adb.exe` 这种完整路径即可，**改完立刻生效、不用重启**，
   而且自检第一行会**回显当前用的是哪个 adb**。

另外这几项也会造成失败：设备没启动 / 得物（`com.shizhuang.duapp`）没装 /
没装 ADBKeyboard（中文标题正文靠它输入）。

> **要不要我帮你定位？** 把自检那一页的**第一行（adb）**和**「设备」那一栏**截图发我，一眼就能判。
