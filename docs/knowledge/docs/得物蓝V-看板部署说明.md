## 这一页是什么

- **只读看板**：从 Supabase 读各台机器上行上去的发布结果，按「款 / 机器 / 执行人」聚合。
- 数据来源 = 各台电脑上的 App **自动上行**的记录。**上行是出厂即开的**（`cloud.enabled` 默认 true），
  界面上已经**不再提供开关**（2026-10-08 按用户要求把「云端协作」整块从界面删掉了，功能本身没动）。
- **它改不动任何东西**（数据库只给匿名 key 放行 select）。
- 完整对账请用本机导出的 Excel —— **本机的 jsonl 才是完整账**，看板最多取最近 5000 条。

## ★ 统计口径（2026-10-08 已修）

| | 改之前 | 改之后 |
|---|---|---|
| 成功率分母 | 混进「模拟成功」+ 连通性探针行 ⇒ 显示 33% | **只算真实发布结果**（`发布成功` / `失败`）⇒ 43% |
| 重复行 | 同一台机换过机器标识后重推的行没折叠 ⇒ 款进度一度 59% | 按「时间+篇号+批次+款」**折叠同一件事**，并按**机器名归一** |
| 机器数 | 3（同一台机被算成两台） | 1（同名合并，并标注「含 N 个标识」） |

**模拟行 / 探针行没有删掉**，仍留在「最近明细」里（灰色标签），页脚写明「另有 N 条未计入」——不藏数据。

根因也修了：机器标识改为由 **Windows 机器指纹（注册表 `MachineGuid`）派生**，
重装 / 清配置 / 换 Windows 用户都认得回来；**已有标识绝不迁移**（迁移 = 整本台账以新 id 重推 = 数字再翻一倍）。
⚠️ 这半边要等**下次发版**才对**新机器**生效。

## ★ 四件需要提前知道的事

1. **这是平台给的静态托管地址**，不是我们自己的长期服务器 —— 它能活多久我不能保证。
   要长期稳定或自定义域名，得另找静态托管（产物就是纯静态的两个文件，可以直接搬走）。
2. **拿到这个链接的人都能看**。匿名 key（anon / publishable）本来就是公开设计 ——
   App 安装包里内置的是同一份，数据库策略只放行「读」。
   ⇒ 想要真正的访问控制，得改成**登录后读**（接 Supabase Auth）或走服务端代理；
   **在静态页面上加个口令是挡不住人的**。
3. 看板上的「机器」是**电脑名**（`os.hostname()`），不是模拟器名。
4. 库里目前只有**一台**真机名下的数据，所以「另一台电脑装了能不能统计到」到底行不行，
   机制上成立、**但还没有第二台真机的实测证据**。想验很简单：让同事跑一次真发布，3~30 秒内看板就会多一行。

## 怎么重新部署（改了看板之后）

1. 改仓库里的 `web/board.html`（**改完记得跑 `node tools/run-all.js`**，套件里对看板有断言）；
2. 逐字节复制到 `E:/WORKBUDDY/2026-09-30-17-35-35/board-site/index.html`；
3. 用平台部署通道把 `board-site/` 目录再部署一次（会得到同一个地址）。
   **内容没变就不用重新部署。**
4. 部署完**必须回读核对**：线上字节数要等于本地文件，并且 `cmp` 逐字节一致 ——
   部署工具**报错 ≠ 没传上去**（2026-10-08 实测：它报 `fetch failed`，其实已经传上去了；反过来也要防）。

> 2026-10-08 记录：平台部署工具在本机会偶发报 `fetch failed`，但**内容确实上传成功了**
> （线上与本地逐字节核对过）；COS 桶那条路**不能**用来预览（强制下载，见上）。
> 产物的本质就是纯静态两个文件，丢到任何静态托管都能跑，这是兜底方案。

- 大小：217945 字节
- sha256：`59d39487c3589843b410322d8a3d562ce022aba1e5ccb16898ef3fb2a0da2ecd`
- 来源：`https://cdn.jsdelivr.net/npm/@supabase/supabase-js@2/dist/umd/supabase.js`
