## 二、但确实有一个会丢的场景，而且很容易撞上

**切完皮肤马上关窗口 ⇒ 这次选择永久丢失。**

根因：`store.set` 不直接写盘，它只排一个 **250ms 防抖定时器**（`store.scheduleSave`），
而**进程退出不会等这个定时器**。更糟的是原来 `before-quit` 里那句兜底是 **假的**：

```js
app.on('before-quit', () => { store.set({}); });   // ← 只是把同一个定时器再排一次
```

真机实测（同一步操作，改前 / 改后）：

| | 点「玻璃」→ 60ms 后退出 | 磁盘上 `ui.theme` |
|---|---|---|
| **改前** | 复现 | **`"light"`（丢了）** ❌ |
| **改后** | 同一步 | **`"glass"`** ✅ |

## 三、改了什么（3 个文件，**都是局部替换**）

| 文件 | 改动 |
|---|---|
| `src/main/store.js` | 抽出 `writeNow()`；新增 **`flush()`**（取消防抖定时器 + 当场 `writeFileSync`）并导出 |
| `src/main/index.js` | `before-quit` 里 `store.set({})` → **`store.flush()`**（附长注释说明为什么旧写法是假兜底） |
| `tools/uicheck.js` | 新增 **2 条**断言（见下） |

顺带：所有 250ms 内的配置改动（品牌选择等）在退出时也一起被救回来了。

### 新增的 2 条断言

1. **行为级**：`store.set` 只排队（读到旧值）→ `store.flush()` → 磁盘上**必须已经是新值**。
2. **源码级**：`before-quit` 里必须是 `store.flush()`，且**不许**再出现旧的 `store.set(`。
   —— 只写函数不钉调用点 = 白写（这个项目踩过）。
