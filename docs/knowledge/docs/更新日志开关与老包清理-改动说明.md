## 1. 做了什么

### ① 更新日志开关（解决「瞎眼」）

**问题**：更新这条链上最坑的失败是**静默**的 —— 差分下载失败会**悄悄退回全量**，
进度条照样走完，用户只觉得「慢」，查不出为什么。而那条 error 只由 electron-updater
**自己的 logger** 报出来，代码里原本写着 `up.logger = null` —— 等于把唯一的线索一起吞了。

**做法**（都是最小改动）：

| 位置 | 改动 |
|---|---|
| `src/main/updater.js` | 新增可选的文件日志（默认关）：`setLogEnabled()` / `logStatus()` / `defaultLogFile()`；**开启时才接管** `up.logger`（关着仍然是 `null`，不往控制台刷）；进度按「每跨 10% 或每 2 秒」抽稀；**下载完成时把「这次下了多少字节 + MB」记成硬数字**；文件超 2 MB 自动轮转为 `.1`；**路径打不开时如实报错、绝不假装在记录** |
| `src/main/ipc.js` | 新增 `update:set-log`（**不设 guardAdmin** —— 排障用的，普通成员才是第一现场）；`update:status` 多带一个 `log` 字段 |
| `src/main/store.js` | 偏好落盘 `update.log`（默认 `false`） |
| `src/main/index.js` | 启动时把路径与上次的开关偏好传给 updater |
| `src/preload/index.js` | 暴露 `updateSetLog` |
| `src/renderer/app.js` | 「设置 → 应用更新」多一行：**开启/关闭** + **打开日志文件** + 当前状态；关着时也写明「开了会写到哪」 |

日志落在 `%APPDATA%\<应用名>\logs\update.log`。★ **不违「数据不出本机」**：
里面只有版本号、通道名与字节数，**不含**素材、品牌、SKU、标题（界面上也这么写）。

**怎么用它拿到你要的结论**：开启 → 点「下载更新」→ 看这一行：

```
[downloaded] 新版本 1.0.1 已下载完成：本次共 11534336 字节（11.0 MB）；当前版本 1.0.0
```

- 这里 ≈ **11 MB** ⇒ 差分生效，只下了变化块；
- 这里 ≈ **88 MB** ⇒ 走的是全量（就是上一轮我推断「大概率没生效」的那个结论）。

> 这行代码旁边写了注释说明「对照基准在哪」，就是为了以后别人看到不用猜。

### ② 老包清理（`tools/prune-release.js`，新增）

**问题**：产物名字里带版本号 ⇒ 每次发版天然新增一个约 88 MB 的文件；上传脚本只有「上传」能力、
桶上没有生命周期规则 ⇒ 老包只增不减。**实测：12 个对象 / 4 个 exe 合计 343 MB**。

**做法**：不做「同名覆盖」，做**保留策略**（每条通道各留「当前版本 + 1 个可回滚的历史版本」）：

```bash
npm run release:prune            # 只看：要删哪些、腾多少（**默认 dry-run，一个字节都不删**）
npm run release:prune:apply      # 确认名单没问题后再真删
npm run release:prune -- --keep-more=2   # 每条通道多留几个历史版本
```

★ **为什么不做「同名覆盖」**（最省事、也最容易被想到的那个方案）：
① **回滚没了** —— 正式通道允许降级（用户从测试版切回正式版靠它、出事回退也靠它），包被覆盖就回不去；
② **审计线索没了** —— 「哪次更新对应哪个包」是事后唯一能对上的凭据；
③ 覆盖同版本号会让客户端按版本号比较后判「没有新版本」（上传脚本的 `versionGate` 拦的就是这个）。

★ 三条 **fail-closed 闸门**（源上状态不明时宁可什么都不动）：读不到 `latest.yml` ⇒ 一个字节都不删；
**比当前版本还新**的包 ⇒ 保留（多半是「包传上去了、清单没传成」，删了就没救）；认不出名字的对象 ⇒ 一律保留。

跑完还会**逐个 HEAD 复核**「保留名单里的包一个都没少」—— 说删干净了要拿源上的事实说话。

## 3. ★ 顺手抓到并修掉的一个真问题（不属于你说的 1、2，但必须修）

发版脚本 `tools/upload-release.js` 原来**只认 `--channel beta` 这种空格写法**。
写成 `--channel=beta` 时，参数解析会返回**默认值 `stable`** —— 而且**不报任何错**。

后果：**把测试版包推到正式通道**（`latest.yml` 里写上带 `-beta` 的版本号），
所有正式版用户都会看到「有新版本」，等于把没验收的包推给全公司。这正是你们定的红线里最重的一条。

已修：参数解析抽成纯函数 `argOf`，**两种写法都支持**；`--channel=`（空值）给空串、
**不落回默认值**（宁可让上层报错，也不静默用错通道）。`tools/prune-release.js` 复用同一套，不另写一份。
`releasetest` 加了 8 条断言钉住它，B9 证明拆掉就红。
