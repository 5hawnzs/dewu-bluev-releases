## 四、我补了什么（3 项，都在这轮源码里）

你的两条要求（**货号+颜色**、**多个好物**）靠原来的机制**表达不出来**，所以我补了三处：

### ① 好物 1~3 的货号/颜色进「占位符」
`publisher.js`：发布时把这一行的 `好物1货号/好物1颜色 … 好物3货号/好物3颜色` 放进 `${goods1Sku} ${goods1Color} …`（发布单就是这 6 列，最多 3 个好物）。
没有 `goods` 字段的老数据（本地扫出来的条目）按「主货号/主颜色」兜底 —— 否则定位表里的好物段会对**每一行**都判成「没有好物」而整段静默跳过。

### ② 条件步骤 `when` / `whenNot`（＝「这一步该不该做」）
**为什么非有不可**：「点关联好物 → 搜货号 → 选商品」是**一整套**。发布单里好物 2/3 常常是空的，空着不跳过的话，搜索页会被**打开却不选商品**，后面每一步全崩 —— 而且崩在「界面已经点了一半」的状态上，比不发还难查。

写法（导入时就校验，写错立刻报错，不放行到真机）：

```json
{ "action": "tapId",  "value": ".../tvRelevantProduct", "when": "goods2Sku" }        // 有好物2 才点
{ "action": "tapText","value": "${goods2Color}", "when": "goods2Sku,goods2Color" }  // 两个都非空才点
{ "action": "tapId",  "value": ".../ivProduct", "when": "goods2Sku", "whenNot": "goods2Color" }  // 有好物2 但没颜色
```

**跳过会写进运行日志**（`跳过「好物2 · 点「关联好物」这一行」（占位符 goods2Sku 是空的）`）—— 静默少点一步最难查，所以不许静默。

**顺带修掉一个老缺口**：话题 1~5 也加了 `when` 守卫，现在空的列真的不写（老版本是「配几步写几步」，多出来的列静默不写）。

### ③ 抓结构：带包名 + 找不到节点先重试（这两条是真机撞出来的）
- **抓结构没带包名** ⇒ 发布页（动画页）`uiautomator` 抓不到时**没有 dumpsys 备用通道** ⇒ 真机上按 id 点「关联好物」会直接失败。（「抓取页面结构」按钮那条路一直带着包名，所以这个洞一直没暴露。）
- **找不到节点一次就判失败** ⇒ 结果图墙加载那一两秒会被误判成「页面结构变了」。现在重试 3 次（每次等 0.9s）再报。
- 连带把报错文案收紧了：走备用通道时**那条通道没有文字**，所以按文字找的步骤要**明说**是通道的锅，并给出改法（改成 `tapId` 用 resource-id）。不收紧的话错误会退化成 `找不到「发布」；当前可见文本：（空）`，比原来还难查。

**改动清单**：`src/main/services/uimap.js`（+50 行）、`src/main/services/publisher.js`（+41 行）、`tools/adbtest.js`（+144 行）。**11 个文件的老功能一个没动。**
