# 腾讯云 COS 开通操作指引（手把手）

> 这是**你**要做的那 10 分钟。全程在浏览器里点，不碰命令行。
> 做完之后把「第 8 节 交给我什么」里的 5 个值发我，我就开始改代码。
>
> 目标：让应用有一个**谁都不用登录就能下载安装包**的网址。

---

## 0. 全程地图

| 步 | 在哪做 | 干什么 | 产出 |
|---|---|---|---|
| 1 | cloud.tencent.com | 注册 / 登录 + 实名认证 | 一个腾讯云账号 |
| 2 | COS 控制台 | 开通 COS 服务 | 能建桶了 |
| 3 | COS 控制台 | **建 1 个存储桶** | 桶名 + 地域 |

| 7 | 命令行 | 传个文件匿名拉回来验证 | **通过 / 不通过** |
| 8 | —— | 把 5 个值发我 | 我开始写代码 |

预计耗时：**10~15 分钟**（实名认证如果是新账号，可能要等几分钟审核）。

- ⚠️ 公司要求用企业认证的话就选企业，但要营业执照，慢一些。**本项目个人认证够用。**

## 2. 开通 COS 服务

**网址：<https://console.cloud.tencent.com/cos>**

首次进入会有一个「开通 COS 服务」的按钮，点它，勾同意条款，确认。

- 开通是**免费的**（按量计费，不用不花钱）。
- 开通后系统会自动送**新用户免费额度**：**50 GB 标准存储 × 6 个月**。
  网址可以看：<https://cloud.tencent.com/act/free>
- ⚠️ **这一点必须说清楚**：免费额度**只抵「存储」**，**不抵「流量」和「请求次数」**。
  也就是你放进去的文件不占钱，但别人**下载**要按流量付费。费用见第 9 节。

## 3. 建存储桶（最关键的一步）

**网址：<https://console.cloud.tencent.com/cos/bucket> → 点「创建存储桶」**

按下面填：

| 表单项 | 填什么 | 为什么 |
|---|---|---|
| **名称** | `dewu-bluev-release` | ⚠️ 桶名**全球唯一**，被占用就加后缀（如 `dewu-bluev-release-2`），建完记下来 |
| **地域** | **广州（ap-guangzhou）** | 你在国内，广州最普遍、最稳。选完别改，改了域名就变 |
| **访问权限** | **公有读私有写** | 公有读 = 别人能下；私有写 = 只有你能传 |
| **请求域名** | 默认（虚拟主机样式） | 别勾「静态网站」，不需要 |
| **CDN 加速** | **不开** | 开了要额外花钱，我们这点流量用不着 |
| **版本控制 / 日志** | **都不开** | 开了会产生额外存储费 |
| **数据冗余策略** | **单 AZ 存储** | 见下节 —— 这份数据是可以**重新打包**出来的，多 AZ 白花钱且**开了不能关** |

**另外两项保持默认，不要动：**
- 不要选「私有读写」→ 那样应用就下载不了安装包了；
- 不要选「公有读写」→ 那意味着**任何人都能往你桶里传东西**，绝对不要。

> 建桶时如果找不到「访问权限」这一项（控制台改版），就先建，然后进桶：
> **权限管理 → 存储桶访问权限 → 改成「公有读私有写」**。

### 为什么「数据冗余策略」选单 AZ

| | 多 AZ 存储 | **单 AZ 存储 ← 选这个** |
|---|---|---|
| 数据持久性 | 12 个 9 | 11 个 9 |
| 服务可用性 | 99.995% | 99.99%（年停机约 52 分钟） |
| 存储费 | **较高** | 标准 |
| 支持地域 | 只有北京/上海/广州/中国香港/新加坡 | **全部地域** |
| 功能限制 | 版本控制与回收站不能暂停、不支持对象锁定、不支持 Select、不支持 JSON API 上传下载 | 无 |
| 能不能反悔 | ❌ **开启后不能关闭** | —— |

**决定性理由：桶里放的是你自己打包出来的 exe，不是唯一副本。**
丢了重新 `npm run dist:win` 再传一次就行，源码在 Gitee 仓库里。多 AZ 那 12 个 9 保护的是「全世界只剩这一份」的数据，而这里显然不是。

⚠️ 多 AZ 还是**两段式**：建桶时开「多 AZ 配置」只是第一段，上传对象时**还要把对象存储类型指定为「标准存储（多 AZ）」**才真的存进多 AZ。
electron-builder 上传时不会替你指定，**默认仍是 `STANDARD`**，所以选了多 AZ 却不管上传类型，很可能花了钱没买到效果。
（这条是从官方文档「两步使用」推断的，**我没实测**，别当结论。）

## 4. 在桶里建两个目录

进你刚建的桶 → 点「**新建文件夹**」→ 依次建两个，名字**必须一模一样**（小写、后面不带斜杠，控制台会自己加）：

- `beta` —— 测试版
- `stable` —— 正式版

每条通道一个目录，互不干扰。这就是「双通道」的实现方式。

> 对象存储其实没有真正的目录，这只是个前缀。但**在上传第一个文件之前先把「文件夹」建出来，看目录结构时最清楚**，也避免手误传错层级。

## 5. 抄下「访问域名」

在**桶的概览页**（点桶名进去），找到「**访问域名**」或「**基本信息 → 访问域名**」那一栏。

它长得像这样（**地址格式**）：

```
https://dewu-bluev-release-1250000000.cos.ap-guangzhou.myqcloud.com
                  └─桶名─┘ └─APPID─┘    └───地域───┘
```

**请把这串完整抄下来**（含 `https://`，不含结尾斜杠）。

三条实测到的规则，解释一下为什么必须是这个格式：

1. **必须是「桶名.地域.myqcloud.com」这种写法**（叫 virtual-hosted-style）。
   2024-01-01 之后创建的桶，腾讯云**不再支持** `cos.ap-guangzhou.myqcloud.com/桶名/文件` 那种写法，会直接报 403。用控制台给你的那个准没错。
2. **`内容会被强制下载`**：新桶用默认域名访问时，腾讯云会强行加一个「下载」响应头，浏览器里点了就是下载、不会在线预览。
   → **对自动更新完全没影响**，更新程序本来就是取字节流。对我们只有好处。
3. **`apk` 和 `ipa` 文件不允许下载**（返回 403 DownloadForbidden）。
   → **`exe` 不在禁令里，可以正常下载。** 这一条我在阶段 0 会用实测再确认一次（见第 7 步）。

## 6. 建一个「只能写这个桶」的子账号

**目的**：打包机上传时用这个子账号的密钥。万一密钥泄漏，损失的边界只有这一个桶，动不了你账号里其他任何东西。

**网址：<https://console.cloud.tencent.com/cam>**

### 6.0 先回答四个最容易卡住的问题

**① 「访问方式」那两个勾选框怎么勾？**

它俩是一组**互相独立**的勾选，**不是二选一**：

| 勾选项 | 它会给你什么 | 我们要吗 |
|---|---|---|
| **编程访问** | 一对 `SecretId` / `SecretKey`，给程序和 SDK 用 | ✅ **勾** |
| **腾讯云控制台访问** | 一个**登录密码**，给人登录网页控制台用 | ❌ **不勾** |

**② 「重置密码」「登录保护」「操作保护」怎么设？—— 全部设成"关"，别等它自己变灰**

> ⚠️ **实测更正（2026-10-01）**：我上一版写的是「不勾控制台访问，这四项就会消失或整块变灰」。
> **新版控制台不成立** —— 用户实测：只勾了「编程访问」，「需要重置密码 / 登录保护 / 操作保护」**照样显示，也没变灰**。
> 所以**别等它自己变，手动设**：

| 项 | 选什么 | 为什么 |
|---|---|---|
| **需要重置密码** | ☐ **把勾去掉** | 它只管「下次登控制台必须先改密码」。子账号不登控制台 ⇒ 没意义 |
| **登录保护** | ○ **不开启** | = 登控制台时要求 MFA 二次验证。不登控制台 ⇒ 不需要 |
| **操作保护** | ○ **不开启** | ⚠️ **这项尤其要关**：它是「敏感操作二次校验」，开着会要求绑 MFA。子账号没绑 MFA ⇒ 将来删桶之类的操作会**直接卡住** |

这三项设成"关"对「拿 SecretId/SecretKey 调 API」**没有任何副作用**（它们只管控制台登录与敏感操作二次校验）。

> 顺手确认一下：**「访问方式」那一格的铅笔**点开，确认**只勾了「编程访问」**、没勾「腾讯云控制台访问」。
> 就算没勾对也不致命 —— 只要上面三项按表设成"关"，它就是个纯 API 账号。

**③ 「登录保护」是什么？要不要开？—— 不需要，也开不了**

「登录保护」= 登录网页控制台时要求二次验证（微信扫码 / MFA 动态码）。**它是防「有人拿着密码登控制台」的。**
我们这把密钥只用来调 API、从不登控制台 ⇒ **不需要**。「操作保护」（控制台做敏感操作时的二次验证）同理。

> ⚠️ 官方文档会写一句「建议您开启登录保护和操作保护」—— 那是**针对要登控制台的子账号**说的。
> **别被这句话带偏，回头去把「控制台访问」勾上。**

**④ 顺序：策略和用户，谁先谁后都行**

两种走法等价，**别在顺序上犹豫**：

| 走法 | 怎么做 | 注意 |
|---|---|---|
| **策略先行**（少跳一次页） | 先做 **6.1** 建策略 → 再做 **6.2** 建用户，在建用户的「设定权限 / 用户权限」那一步直接勾中它 | 需要先在「策略」页停留一次 |
| **用户先行**（你已经在建用户页时最省事） | 直接 **6.2** 把用户建出来（权限留空「暂无权限」）→ 再去 **6.1** 建策略 → 回按 **6.3** 补挂 | ⚠️ **千万别忘了补挂**，否则第 7 步验收会 `AccessDenied` |

> 「先建用户、后授权」是标准做法：新建用户的页面里，「用户权限」那一格本来就是**可以先留空**的。

### 6.1 先建这条「只有这一个桶」的自定义策略

**入口：<https://console.cloud.tencent.com/cam/policy> → 点「新建自定义策略」**

1. 弹窗里选「**按策略语法创建**」
2. 模板选「**空白模板**」→ 下一步
3. 策略名称填：`dewu-bluev-cos-upload`
4. 把下面这整段**替换**掉编辑框里的内容，并且**把两个 `【】` 占位符换成你的真实值**：

```json
{
  "version": "2.0",
  "statement": [
    {
      "effect": "allow",
      "action": ["cos:*"],
      "resource": [
        "qcs::cos:ap-guangzhou:uid/【你的APPID】:【你的桶全名】/*"
      ]
    }
  ]
}
```

**两个占位符怎么填（很容易填反，看清楚）：**

| 占位符 | 填什么 | 举例长什么样 |
|---|---|---|
| `【你的APPID】` | **纯数字的 APPID**（在 <https://console.cloud.tencent.com/developer> 或控制台右上角「账号信息」里看） | `1250000000` |
| `【你的桶全名】` | **桶名 + `-` + APPID**（在 COS 控制台的桶列表里看） | `dewu-bluev-release-1250000000` |

⚠️ APPID 要出现**两次**，但**格式不一样**：`uid/` 后面是**裸数字**，桶名后面是**跟着的 `-` 后缀**。别只在桶名里写了、忘了 `uid/` 那个。

5. 保存。

**为什么不用预设策略**：CAM 里那些现成的 COS 策略（如 `QcloudCOSFullAccess`）`resource` 全是 `*`，等于**把你账号下所有桶的钥匙都交出去了**。我们只要一个桶，所以必须自定义。

**`cos:*` 会不会太宽？** 它已经**限定到单桶**了，动不了别的桶；但它**能删这个桶、能改这个桶的配置**。
因为桶里只有你自己打的包（丢了重打一次就有），我认为可以先接受 —— **先跑通最重要**。
真要收紧，用下面 6.1.1 那份。

#### 6.1.1 想收得更紧？（可选，不急）

只给上传/读取/删除，不给改桶配置：

```json
{
  "version": "2.0",
  "statement": [
    {
      "effect": "allow",
      "action": [
        "cos:PutObject", "cos:PostObject", "cos:GetObject", "cos:HeadObject",
        "cos:DeleteObject", "cos:InitiateMultipartUpload", "cos:UploadPart",
        "cos:ListParts", "cos:CompleteMultipartUpload", "cos:AbortMultipartUpload"
      ],
      "resource": ["qcs::cos:ap-guangzhou:uid/【APPID】:【桶全名】/*"]
    },
    {
      "effect": "allow",
      "action": ["cos:GetBucket", "cos:HeadBucket", "cos:ListMultipartUploads"],
      "resource": ["qcs::cos:ap-guangzhou:uid/【APPID】:【桶全名】/"]
    }
  ]
}
```

> 拆两条是因为：**桶级**操作（列对象、列分片）的 `resource` 指向**桶本身**（结尾是 `/`），
> 而**对象级**操作（传、读、删）指向**桶里的对象**（结尾是 `/*`）。混在一条里容易漏。
> 88 MB 的包一定走**分片上传**，所以 `*MultipartUpload*` 那几条一条都不能少，否则传大文件会失败。
> （**这份收紧清单我没实测过** —— 先用 6.1 那份跑通，再按需要换。）

### 6.2 建子用户（只勾「编程访问」，「用户权限」那格先留空）

> **你会遇到两种页面，哪个都行，别纠结：**
> - **A｜「快速创建」版** = 表格三列：`用户名 / 访问方式 / 用户权限`，下面有「新增用户（单次最多创建 10 个用户）」
> - **B｜「自定义创建」版** = 分步向导：填信息 → 设定权限 → 完成
>
> 官方文档把「快速创建」描述成"给管理员用、默认 AdministratorAccess"，**但新版这个页面的用户权限默认就是「暂无权限」**
> —— 页面顶部蓝条明写"**默认没有任何资源的访问权限**"。所以**走 A 也不会误给管理员权限**。

按顺序做：

1. 左侧 **用户 → 用户列表 → 新建用户**
2. 用户名：`dewu-bluev-publisher`（随意，认得出就行；⚠️ 用户名**一经确定不可更改**）
3. **「访问方式」那一格点铅笔** → **只勾「编程访问」**，**不勾「腾讯云控制台访问」**
4. ⭐ **「用户权限」那一格 → 什么都不用填，保持「暂无权限」**
   - 因为我们的 `dewu-bluev-cos-upload` 策略**现在还没建**，这一格确实没东西可选 —— **这是正常的，不是漏填**。
   - **「先建用户、后授权」是标准做法**；官方文档里也有"权限栏显示暂无策略、直接完成"的走法。
   - 想少跳一趟页：另开一个标签页先做完 6.1，再回来点这格铅笔 → 关联策略 → 勾 `dewu-bluev-cos-upload`。**两种顺序都行。**
5. 下面三项按 **6.0 ②** 的表设：**需要重置密码 = 不勾 / 登录保护 = 不开启 / 操作保护 = 不开启**
6. 点「**创建用户**」
7. ⚠️ **创建完必须去 6.1 把策略建出来，再按 6.3 挂到这个用户上** ——
   **不挂策略，第 7 步验收一定报 `AccessDenied`**（用户建出来是白的，没有任何权限）。

### 6.3 拿密钥（只有一次机会看到）

**创建成功页上可能直接显示 `SecretId` 和 `SecretKey`** —— 页面上有「**复制**」和「**下载安全凭证**」（导出 Excel）两个按钮，**用它们，别手抄**。

> ⚠️ **但"快速创建"那条流程的完成页不一定给密钥**。不用纠结，直接走下面这条**一定可行**的路：

**一定可行的拿法（推荐直接用这条）**：

1. <https://console.cloud.tencent.com/cam> → 左侧 **用户 → 用户列表**
2. 点进你刚建的子用户（`dewu-bluev-publisher` / `20261001`）
3. 切到「**API 密钥**」页签
4. 点「**新建密钥**」→ 弹窗里同时给出 **SecretId** 和 **SecretKey**
5. ⚠️ **`SecretKey` 只在这个弹窗里显示这一次** → 立刻复制（或下载），关掉就再也看不到
6. 同一页可以把用不上的旧密钥**禁用 / 删除**（一个用户最多 2 对）

> ⚠️⚠️ **认准是「子用户」的密钥**：主账号的密钥在「账号信息 → API 密钥」里，**别拿错** ——
> 拿主账号密钥等于把整个腾讯云账号交出去，这次做的单桶限制就白费了。

**如果 6.2 第 6 步跳过了授权，现在补挂**：
CAM → **用户 → 用户列表** → 点进 `dewu-bluev-publisher` → 「**权限**」页签 → **关联策略** → 勾中 `dewu-bluev-cos-upload` → 确定。

## 7. 验收：匿名拉一个文件（这一步不能省）

**为什么必须做**：前面第 5 节那三条「默认域名的限制」我是从腾讯云官方文档读到的，**`exe` 不在禁令里是我从条文推断的，还没实测**。这一条不通过，整个方案就得换。

**怎么测**（二选一）：

**用浏览器测（最简单）**
1. 进桶 → `beta` 目录 → 上传**任意一个小文件**（比如随便一个 txt 或一张图）
2. 在桶里点这个文件 → 看有没有「复制链接」/「下载地址」
3. 把链接**贴到一个新开无痕窗口**（模拟"没登录的人"）
4. 能下下来 = 公有读生效 ✅

**用命令行测（更硬，能验 exe）**

把 `[域名]` 换成第 5 节抄下的那串：

```bash
# 看响应头——应包含 content-length，不应有 403
curl -I "https://[域名]/beta/latest.yml"
```

## 9. 花多少钱（说实话，不是"免费"）

**免费的部分**：50 GB 标准存储 × 6 个月（新用户）。

**不免费的部分**——这是真正会产生账单的地方：

| 计费项 | 单价 | 我们的量级 |
|---|---|---|
| 公网下行流量 | **0.5 元/GB 起**（阶梯降价） | 每次发版 × 10 台 × 包大小 |
| 请求次数 | 约 0.01 元/万次 | 每次更新几十次，可忽略 |

算一笔账（按每次发版 10 台、每台拉 88 MB 全量估算）：

```
单次发版流量：10 × 88 MB ≈ 0.88 GB  →  约 0.44 元
每月发 3 次：                        →  约 1.3 元
6 个月后 + 存储费（约 5 GB）：0.5 元/月
```

⇒ **每月 1~2 元量级**，一年**大概 10~20 元**。可以忽略。

⚠️ 三个会导致账单失控的开关，**别开**：
- **CDN 加速**（回源流量另计费）；
- **跨地域复制**（复制一份就是双倍存储 + 流量）；
- **生命周期转归档**（我们这点量没必要，反而增加复杂度）。

另外：免费额度是「**首次开通**」才有的。如果你这个账号以前开通过 COS，就没有这 50 GB 了——**不影响方案，只是存储从第一 GB 起按 0.099 元/GB/月算**，我们总量也就几 GB，约 0.5 元/月。

## 10. 四个坑（已知，提前说）

1. **桶名全球唯一**。`dewu-bluev-release` 可能被人占了，那就换一个能认得出来的名字。
2. **地域选定后不要改**。域名里含地域，改了 = 已装的应用**全部失联**（因为地址是编译进包里的）。
3. **更新源地址将来要改的话，等于所有已装客户端失联**，必须重新发一遍包。所以第 3、5 步**一次选对**，别急着换。
4. **别把密钥写进代码或提交到 git**。密钥只放打包机上的一个本地配置文件（我会加进 `.gitignore`）。
