## 四、我核对时新发现的两个缺口（要你拍板，不是 bug 是设计）

### A. 一条内容有多张图时，现在只能发出去第 1 张

- 程序会把这条的**图片全部**推到设备相册，但定位表里的「选素材」是 `tapId flThumbSelect`
- `tapId` 取的是**第一个**匹配节点 ⇒ **永远点相册第 1 格**，写第二遍还是点同一格（第 2 次点等于取消选中）
- 相册格子**无文字、无描述**（实测），也没有「按坐标点第 N 格」这种动作

⇒ 现状：**图文一条只能发 1 张图**。要发多张，得给定位表加一种新动作（比如「按序号点第 N 格」）。要做的话说一声。

### B. 话题只配了 1 步，但发布单有「话题1~话题5」五列

- 发布单最多写 5 个话题（`sheet.js` 里就是 `话题1`~`话题5` 五列）
- 实测表里只有 1 步 `input ${topic1}` ⇒ **如果这条有 3 个话题，后 2 个会静默不写**
- 两个选法，你挑：
  - **甲**：表里补到 5 步（`${topic1}`…`${topic5}`），一条有几个就写几个 —— 但得让程序在「这个话题是空值」时**跳过那一步**（不然会往输入框里打空串），这需要我改一处代码
  - **乙**：就发 1 个话题，表不动

## 五、顺带：你刚碰到的那个「明明选了品牌却报请先选择品牌」

**已定位、已修、已验（源码级）**：

- 根因：「导入内容报告」是**唯一**一个绕过统一封装、直接调主进程的任务。别的产出类任务（文案生成 / 导出发布单 / 发布）都会自动带上标题栏选中的品牌，它没带 ⇒ 主进程收到空品牌；而你有 **2 个品牌**（TW男装 / BETA），程序不会替你挑，于是报「请先选择品牌」。
- 修法：把补品牌那段抽成一个函数，所有产出类任务都走它；并加了一条**长期守卫断言**（源码里再出现「裸调」就红）。
- 自证：全量回归 **17 套 / 1056 项全绿**（`uicheck` 154→156）；并做了破坏验证 —— 故意把修复拆掉 → **断言真红且点名 `report.import`** → 逐字节还原 → 再绿。

> ⚠ **你机器上现在装的还是旧包，这个 bug 在旧包里还在。**
> 想马上用上，有个不用等新版的办法：到「品牌与权限」把 **BETA 停用**（只剩一个品牌时程序会自动选中，不再报错）。
