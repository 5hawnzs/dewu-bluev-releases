## 一、`emulator-5554` 为什么每次都会回来（这次铲干净了）

查到**两处**来源，缺一不可：

| # | 位置 | 原来是什么 | 现在 |
|---|---|---|---|
| 1 | `%APPDATA%\dewu-bluev-publisher\config.json` | `publish.device = "emulator-5554"`，设备列表里也有一条 `name/serial = emulator-5554` | `publish.device = "127.0.0.1:16384"`，列表项 `name = 本机模拟器`、`serial = 127.0.0.1:16384` |
| 2 | `project.json` | 同一个假串出现 3 处（工程状态 + 陈旧的 probe 快照） | 全部换成真串 |
| 3 | ★ `src/main/services/publisher.js` 的 `run()` | `const serial = … || c.device \|\| '127.0.0.1:5555';` | ★ **兜底整个删掉**，改成 `\|\| ''` + 一条显式报错 |

**第 3 条才是「改完又回来」的元凶**：只要没有任何地方填设备，它就自己去拿一个硬编码串用 —— 先前的 `emulator-5554` 已经被删过一次，但同族的 `127.0.0.1:5555` 还留着，表现一模一样：**没选设备也能「跑起来」，实际拿一台不存在的设备去发，界面和台账却是绿的。**

现在没选设备会当场说清楚：

```
还没选设备：先点「扫描设备」，把模拟器加入列表并点「选用」，再开始发布。
```

改动前后差异（配置文件只动了这 6 行，没有重排格式）：

```diff
  "device": "emulator-5554",      →  "device": "127.0.0.1:16384",
  "name":   "emulator-5554",      →  "name":   "本机模拟器",
  "serial": "emulator-5554",      →  "serial": "127.0.0.1:16384",
（project.json 里 3 处同样替换）
```

### 于是新增了一个动作：`tapCardText`

真机 dump 里的几何关系非常干净（实测数字）：

```
ivProduct    [35,278][354,597]   ← 商品图，319×319，能选中整张卡的就是它
tvCSpuInfo   [278,554][354,597]  ← 颜色文字「本白」，**完全落在上面那张图里面**
```

所以「这个颜色在哪一格」是可以**算出来**的，不用靠标注：

> **`tapCardText` = 找到文字等于颜色的那个节点 → 取「把它包住的那张商品图」→ 点那张图的中心。**

为什么必须取「包住的」而不是「第一张」：同一屏的树里其实有**两套互相重叠**的卡片列表
（「已购」「想要」两个 viewPager 同时在树里，坐标错开 220px），一个点会被两张卡同时包住。
归属判据用「颜色标签贴在卡片**右下角**」这条几何事实：取底边/右边最贴近的那张。

**真机复验**（用 `深咖棕`，故意挑一个不在第一格的坐标）：

| 步骤 | 结果 |
|---|---|
| 跑 `tapCardText` 值=`深咖棕` | 点到第 3 行第 2 列那张卡（中心 540,438），不是颜色标签（661,576） |
| 结果 | 挂上去的商品缩略图是**咖色**的 `UR UR 休闲珠饰落领裙襟木耳边修身T恤` ✔ |

定位表里这 3 步已改成 `tapCardText`（好物 1/2/3），`hint` 里写全了依据与实测数字，
`verified` 从 `false` 改成 `true`。同色多款时（实测一页「本白」出现 3 次）给这一步写 `count` 取第 N 个。

## 三、顺带修掉的一个「会掉到备用通道」的坑

你说了「不要备用通道」。查下来它被触发是有原因的，而且原因是个 bug：

`uiautomator dump` 在得物发布页首屏有时**一个字都不打印**（不是 `could not get idle state`）。
旧代码只把 `could not get idle state` 当成「页面不 idle」，所以**「临时关掉系统动画重试」那条路根本不会走**，
直接掉到 `dumpsys` 备用通道 —— 而那条通道**拿不到文字**。

实测数字：关掉三个系统动画开关后，同一个相册首屏**一次就抓到**（85 个节点）。
现在「一个字都没打印」也当成「页面不 idle」，于是先关动画重试，成功就走正常通道。

## 五、还剩什么没解决（如实说）

1. **有草稿时，「发布新动态」会先落到一屏「草稿箱」**（`DraftActivity`），要点它底部那个「发布新动态」才进相册。
   现在定位表**没有**这一步 —— **你草稿箱里有一条未编辑完的草稿，所以下一次真机发布会卡在这里**。
   我测试时也踩到了（`_真机截图-重进发布页.png`）。
   处理方式要先定：把草稿删掉？还是给定位表加一步「如果在草稿箱就点底部发布新动态」（需要一个条件步骤）。
2. **同色多款**：靠 `count` 取第 N 个，但「第 N 个到底是哪一款」目前没有别的可辨认信息 ——
   商品**名字抓不到**（自绘的，dump 里没有文字），只有商品图能看。要按款选得更准，得想别的办法。
3. **「下一步」按钮** `flNextStep` 的 `clickable=false`（文字节点 `tvNextStep` 才是 true）。
   实测点了没反应过一次（怀疑是选中素材后那一小段布局动画里点偏了）；后来手动点同一点就过了。
   要不要把定位表这一步改成点 `tvNextStep`，可以再定。
4. **相册里的图是空白的**：`screencap` 抓到缩略图区域是白块（图片加载/渲染的截图问题），
   不影响点击（按节点坐标点），但截图证据看不到缩略图内容。
5. **没有提交、没有发版、没有换 asar** —— 都等你放话。改动只在工作区。
