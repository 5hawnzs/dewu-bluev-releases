# 得物 App 安装包：随包内置 + 设置页两个按钮（2026-10-08）

## 一句话

设置页「外部依赖」表里新增一行 **「得物 App 安装包（模拟器商店里搜不到得物时用）」**，
旁边两枚按钮 **「下载到本机」** 和 **「装进模拟器」**，表下写着"把 apk 拖进 MuMu 窗口就会自动安装"。
安装包本身**随 App 一起打进安装包**（按你拍的那条），所以新同事装上工具就有现成的得物安装包。

两枚按钮在**内置那份缺失或大小不对时是灰的**（点下去才发现装不了，比一开始就灰着更气人）。

## 2. 直接回答你问的那个问题

> **「如果用户模拟器本身就有这个 app，这个按钮还能用吗？」**

**能用，而且它不会去动已经装好的那一份。** 点「装进模拟器」时，程序的动作顺序是：

1. 先读设备：`pm list packages` 里有没有得物 → 有的话再读 `dumpsys package`，拿到**设备上那份的真实版本**；
2. **已经装了 ⇒ 一条安装命令都不发**，只回一句：
   「模拟器里已经有得物 6.0.5 —— 我没有动它。确实要覆盖重装，点这一行新出现的「覆盖重装」」；
3. 这时界面上才会多出第三枚按钮 **「覆盖重装」**。你点了它，才真的执行
   `adb install -r -d <apk>`（`-r` 保留应用数据、`-d` 允许降级），装完还会**回读 `pm list` 确认**才算成功。

也就是说：**默认不碰你的得物**（登录状态、本地草稿都还在），要覆盖必须再点一次 —— 这个按钮永远不会替你决定。

另外三种情况的说法也都是明确的，不会"点了没反应"：

| 情况 | 你会看到 |
| --- | --- |
| 还没选设备 | 「还没选设备 —— 先在「模拟器发布」页点「扫描设备」，再从列出来的设备里点「加入并使用」」 |
| 设备名对不上/没启动 | 「设备 xxx 不在线（adb 现在认到的是：…）」 |
| 设备上那份得物和这个包**签名不一样** | 原始报错 + 「只能先在模拟器里把它卸载再装，卸载会清掉登录状态和本地草稿，所以这一步交给人工决定，工具不自动做」 |

## 3. 这个安装包是什么（从包本身读出来的，不是按文件名猜的）

| 项 | 值 |
| --- | --- |
| 文件 | `vendor/dewu/dewu_6.0.5.apk` |
| 大小 | **133,315,131 字节**（127.1 MB） |
| md5 | `50092bccb263498a16e4fbb57762ae5f` |
| 包名 | `com.shizhuang.duapp` |
| 版本 | versionName **6.0.5** · versionCode 1140 · compileSdk 35 |
| **ABI** | **只有 `arm64-v8a` / `armeabi-v7a`，没有 `x86_64`** |

> ★ **ABI 这条要记住**：MuMu 12 是 x86_64 模拟器，这个包只有 arm64 ⇒ 靠 MuMu 自带的 **ARM 兼容层**跑。
> `adb install` 本身不看 ABI（照样返回 Success）⇒ 万一**"装上了却打不开"**，第一嫌疑是这条，不是包坏了。

> ★★ **老实说清楚**：这一份来自**你本机上已有的副本**（两个不同目录、md5 一模一样的同一份），
> **没有跟得物官方渠道对过**。md5 只能证明"发给每个人的都是同一份、且没坏"，**证明不了出处**。
> 要更强的保证，只能去得物官方渠道下同一版本、重算 md5 换掉三处常量。

## 4. 我这轮**没有**做到的事（不许当成已完成）

- **没有在真模拟器上装过一次**。跑回归的时候 MuMu 的 Android 虚拟机没起来
  （`adb connect 127.0.0.1:16384` 被拒绝、`adb devices` 是空的），
  所以「真的装进模拟器」只有**假 adb 上的行为级证据**（命令序列 + 回读逻辑），没有真机证据。
  你哪天把模拟器起来、在「模拟器发布」页选好设备，点一下那枚按钮就能验真。
- 没有真机验证「拖 apk 进 MuMu 窗口会自动安装」这句提示 —— 这是 MuMu 的行为，不是我测出来的。

## 5. 代价（你拍了"随包内置"，这是它的账单）

| 项 | 变化 |
| --- | --- |
| 安装包体积 | **108.7 MB → 约 236 MB**（+127 MB；NSIS 压不动 apk，它本来就是压缩包） |

| 合规 | 得物 App 是第三方商业应用，**按"公司内部装机使用"放进来**；**要对外分发这个安装包，先解决授权**（同 ffmpeg 那条 GPL 提醒的性质） |

## 6. 证据（可复算）

| 套件 | 结果 |
| --- | --- |
| `tools/adbtest.js` | **404 PASS / 0 FAIL**（本轮 +12 条，块号 ⑰） |
| `tools/uicheck.js` | **254 PASS / 0 FAIL**（本轮 +9 条） |
| `node tools/run-all.js` | 见 `_全量回归-dewuapk.txt` |

新增断言里几条关键的（都不是"源码里有这行字"）：

- **设备上已经有得物 ⇒ install 调用 0 次**（读假 adb 的调用日志数的）；
- **新模拟器 ⇒ 真的发 `install -r <apk>`，并且回读 `pm list` 里出现了才算成功**；
- **只有显式 force 才带 `-d`**（且只在覆盖重装那一步）；
- **`installed=null`（读不出来）与 `false`（确认没装）必须分开** —— 后者会一路装下去；
- **界面的负向对照**：把内置目录指到空目录后，两枚按钮**都变灰**、状态变「缺」
  （不然"disabled 跟着状态走"和"写死 disabled"在回归里长得一模一样）；
- **全链路活体**：真点一下「装进模拟器」，自检环境没设备 ⇒ 必须从主进程回「还没选设备」
  （按钮→ACTS→preload→ipc→jobs→dewuapk 断一处，就只会"点了没反应"）。

## 7. 以后要换新版本的 apk

1. 新 apk 放进 `vendor/dewu/`；
2. 改 `src/main/services/dewuapk.js` 里的 `FILE` / `BYTES` / `MD5` / `VERSION` / `VERSION_CODE`；
3. 改 `vendor/README.md` §4 那张表 + `package.json` 里 `extraResources` 的 `filter`；
4. 改 `tools/uicheck.js` 开头 `prov` 列表里的文件名；
5. 跑 `node tools/run-all.js`（uicheck 会核对内置文件的 md5 能不能在 `vendor/README.md` 里对上）。

**三处必须同改**：`vendor/README.md` 台账、`dewuapk.js` 的常量、`uicheck.js` 的 `prov` 列表 ——
少一处，"发给每个人的是不是同一份"就没人能核。
