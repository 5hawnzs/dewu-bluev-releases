## 一句话

## 1. 根因（源码级，可复算）

`web/board.html` 引导段原来是这么写的：

```js
if(cfg.url && cfg.key) connect(); else { $('#main').hidden = true; conn('wait','未连接'); }
//  ↑ 本机存过配置才自动连        ↑ 没存过 ⇒ 只显示「连接设置」卡片，不取数
```

而 **`cfg` 来自 `localStorage`，新访客的浏览器里本来就是空的** ⇒ 一定走 `else` 分支。

所以「第一次打开 = 一张空的连接设置卡片」，这**不是使用者的错，是设计缺陷**：
一个零配置的只读看板，不该先给人一道「点一下」的门槛。
（上一轮我在交付里写「点一次就行」——那句话本身就把缺陷说成了正常步骤，是我的问题。）

已坐实的旁证：`uicheck`/`cloudtest` 里此前**没有任何一条断言**管「打开之后是不是看板」，
所以这个缺陷一路全绿地活到了你打开它为止。

## 2. 改了什么（只改 `web/board.html` 一个文件）

| 之前 | 之后 |
|---|---|
| 本机存过配置才自动连 | **一律自动连**：本机存过的 → 内置的（与 App `clouddefaults.js` 同一份） |
| 首屏挂着「连接设置」卡片 | 卡片**默认 `hidden`**，整块不出现 |
| 顶栏常驻「连接设置」按钮 | 按钮**默认不出现** |
| 自动连会写 localStorage | **只有手点「保存并连接」才写**（见下） |
| 没有出口 | 连不上 / 读不到时**自动露出来并写明原因**；网址后加 **`#setup`** 可手动打开 |

两处是刻意加的，防的是「以后又出怪事」：

1. **自动连不写 localStorage**。否则每台机第一次打开就把内置值存成本机值；
   将来换项目时**本机旧值会盖住新内置值**，表现是「显示已连接、数字却是旧库的」，不报任何错。
2. **`#setup` 打开的设置，连上成功后不会被自动关掉**（`setupPinned`）。
   第一版我漏了这条：连上就无条件收起设置，会把手动打开的东西顶掉。
