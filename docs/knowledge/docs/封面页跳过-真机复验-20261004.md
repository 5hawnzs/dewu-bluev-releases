## 2. 两条硬结论（都是踩出来 / 测出来的）

### ① 封面页必须点左边那颗「跳过」
实测点右边「下一步」**不到编辑页** —— 它进的是**又一屏「编辑封面」**
（文字：`编辑封面 / 封面模板 / 文字 / 下一步`），还要**再点第三下**才到编辑页。

⇒ 你说的「连点两下」= **剪辑页「下一步」+ 封面页「跳过」**，
**不是「同一坐标连点两下」**（我第一版就这么写，跑出 **0/2**）。

### ② ★★ 盲点省掉抓屏，同时也省掉了「天然等待」
- 原来这两步是 `tapId`：**每步先 dump（2085ms）再点** ⇒ 点击之间天然隔着 ~2.1s，顺手把转场等掉了。
- 改成 `tapXY` 是**立即点** ⇒ 上一次的转场还没完就点下一下。
- 实测症状（0/2）：**seq1 连点两下后还停在剪辑页**、seq2 只过一屏；
  报错却落在后面「点标题输入框找不到 `etTitle`」—— **离真因很远**。
- 对策：视频那两步之间**补固定 `wait 1200`**（纯配置，**没改 src**）。
  图文**不用补**：它那步带 `whenOn: edit_panel` 屏幕守卫，守卫的 dump 本身就是等待。

## 3. 改动落点

全部在 `tools/fixuimap.js`（幂等修正脚本，规则 ⑦ / ⑦-b）；**未改任何 `src/`**：

| 目标 | 改成 |
|---|---|
| 视频「剪辑页 · 下一步」 | `tapXY 985,1843` |
| 视频「封面页 · 跳过」 | `tapXY **820,1857**` |
| 图文「图片编辑页 · 下一步」 | `tapXY 985,1843` + **保留** `whenOn: edit_panel` |
| 视频两步之间 | 各插一个 `{action:'wait', value:1200}` |

- 图文那步的守卫**不能删**：单选图没有这一屏，盲点无条件点下去会落到编辑页底部的「发布」上 ⇒ **误发**。
- `fixuimap.js` 新增 `BLUEV_CFG_DIR` 环境变量，回归测试可指到临时目录（不动真实配置）。

1. **一个真现象、但不是本次改动引入**：我实测时把设备停在封面页没退出 ⇒ 得物侧留下
