> 而且目前你的标题有明显的语病，如你生成的『少年感灰针织毛衣』，
> 如果能变成『少年感灰针织毛衣太帅了』+ emoji；或者你上次的『军绿调穿搭夹克』，
> 如果能变成『军绿调穿搭夹克 松弛感拉满』」

---

## 一、结论先说

你指出的**两条**都是真问题，而且**都在我这边**（不在模型）：

| # | 你指出的 | 我错在哪 |
|---|---------|---------|
| ① | `+` 只是「什么类型和什么类型合并」的示意 | 我把它**当成了标题的字**。T01~T10 的示例里全带 `+`，模型照着抄，标题里就真出现了 `+` |
| ② | 「少年感灰针织毛衣」有明显语病 | 词包**直贴**就是标签串 —— `少年感` 贴 `灰针织毛衣`，**没有收尾**，读着不成句 |

**改法一句话**：把「词包公式（A + B）」换成「**句式骨架**（一句念得通的话）」——
每条骨架**自带连接字或收尾**，模型照着填就**结构上出不了病句**。

## 二、新写法长什么样

**改前（上一轮）** —— 形状对了，但 `+` 是字面量、且没有收尾：

```
羽绒服+极简通勤❄️       羽绒服+酒红调慵懒风🍷       少年感+灰针织毛衣 🧶
```

**改后（这一轮）** —— 10 条骨架，每条自带连接字或收尾：

| | 句式 | 形状示例 |
|---|------|---------|
| T01 | 人群感 + 单品 + 夸一句 | `少年感{色}针织毛衣太帅了` |
| T02 | 单品 + 氛围短语 | `{色}调夹克 松弛感拉满` |
| T03 | 风格词 + 的 + 单品 | `简约百搭的羽绒服` |
| T04 | 单品 + 穿出 + 风格 | `{色}毛衣穿出老钱风` |
| T05 | 场景 + 就穿 + 单品 | `通勤就穿{色}夹克` |
| T06 | 季节词 + 单品 + 收尾 | `冬日神器羽绒服，过冬就靠它` |
| T07 | 单品 + ，+ 情绪词 | `{色}夹克，一眼心动` |
| T08 | 色感词 + 单品 + 收尾 | `{色}调穿搭夹克，高级感拉满` |
| T09 | 单品 + 才是 + 场景 + 的答案 | `羽绒服才是过冬的答案` |
| T10 | 单品 + 自带 + 人群感 | `{色}羽绒服自带少年感` |

你给的两句就是 T01 / T02 的形状。**10 条仍是按行轮换**，整批不会只出一种。

**另外补了两件事**：

1. **词库新增「收尾」词组** 12 个 —— `太帅了 / 闭眼入 / 谁穿谁帅 / 真的绝了 / 稳了 / 不出错 /
   很能打 / 安排上 / 直接封神 / 质感在线 / 好看到犯规 / 很难不爱`。你要的「太帅了」本来就该在词库里，
   之前 7 类词（风格/氛围/色感/场景/人群/季节/情绪）里没有这一类。
2. **示例两条铁律**（上一轮踩过其中一条）：示例里 **一个 `+` 都不留**；
   **颜色位一律用 `{色}` 占位**（上一轮示例写死「灰」，真机跑一条酒红的货，模型把「灰」照抄进了标题）。

**提示词三处都写了「标题里一个字都不许出现 `+`」**（system 的看图段、句式清单、每行的 user 消息），
并给了**病句反例 vs 正例**，让模型知道为什么不能直贴。

## 三、核对列（报告里那一列）新增两条

| 新增 | 判据 | 会不会误杀 |
|------|------|-----------|
| ⑧ **标题里出现拼接符号**（`+ ＋ ﹢ & ｜ · •`） | 客观、可数 | **不会** |
| ⑨ **标题是「热词 + 单品」直接贴出来的标签串** | 启发式，三条**同时**成立才报：① 以热词开头 ② 以单品词结尾 ③ 全文无连接字/标点/空格 且 ≥6 字 | **已知会「过报」**：`简约百搭羽绒服` 这种名词短语也会被提醒补收尾 —— 属预期，是提醒不是判决，**不拦发布** |

⑨ 的关键是**反向对照**：你给的两个正例必须**不**被点名 ——
`少年感灰针织毛衣太帅了`（有「太」）、`军绿调穿搭夹克 松弛感拉满`（有空格）都判「一致」。
（只测「病句被报」而不测「正例不报」，等于只验一半。）

## 四、顺手修掉一个**潜伏**的判错（不是这一轮引入的）

写读报告的脚本时撞出来的：

- `hasEmoji` 用的是**带 `g`** 的正则做 `.test()`，而**带 `g` 的 `.test()` 会推进 `lastIndex`**
  ⇒ **同一条标题连判两次一真一假**。实测：单条连判 4 次得到 `true false true false`；
  10 条真机标题**全都带 emoji**，连着判一遍却报出「4 条没有 emoji」。
- 产品里**恰好没露头**（`check()` 里 `hasEmoji` 前面刚调过 `textLen()`，而 `replace(带 g 的正则)` 会把 `lastIndex` 归零）
  —— 但这是**定时炸弹**：任何新调用点连判两次就会判错。
- **已修**：判「有没有」改用不带 `g` 的副本；并补**正反两条**断言
  （带 emoji 连判 4 次都得 true；真没 emoji 连判 4 次都得 false —— 防止修成「恒 true」）。
