## 三步跑起来

1. **建表**：Supabase 控制台 → SQL Editor → 整段贴 `docs/supabase-setup.sql` 跑一次（幂等）。
2. **App 开开关**：每台机器的「高级设置 → 云端协作」打开开关，填同一个**项目地址**和 **anon key**，
   给每台机器起个能认出来的名字（比如「小李-办公室」），点「测试连接」确认通。
3. **看板**：双击 `web/board.html`（或丢到任意静态托管），填同样的地址与 key（存在你自己浏览器里），
   就能看到款进度、按机器/执行人的汇总、最近明细。默认每 30 秒自动刷新。

> 地址和 key 我没有、也没法替你去建——这两项要你从自己的 Supabase 项目里取（Settings → API）。
> **只能填 anon public key**，`service_role` 那个绝对不要填进来。

## 上行的到底是什么（以及不上传什么）

**上行**（18 个字段，全是结构化结果）：
时间 / 机器标识与名称 / 批次 / 篇号 / 货号 / 款目录名 / 图文或视频 / 成功或失败 / 失败原因（截断 200 字）/

**不上行原文日志**是有意的：日志里带本地路径，而且行数会爆表。对账请用本机导出的 Excel——
**本机 `publish-log.jsonl` 才是完整账**，云上那份是给协作看的投影。

## 四条红线（都写成了断言）

1. **关着的时候一次都不联网**——说「数据不出本机」就得真不出。
2. **失败绝不阻断发布**——上行挂掉只记状态、排退避；结果早在本机落盘了。
3. **只给 anon 角色 insert + select**——**绝不给 update / delete**：一旦网页能改，看板上的成败就不值钱了。
4. **幂等**——`Prefer: resolution=ignore-duplicates` + 表上 `(machine_id, ts, seq)` 唯一索引，
   网络重试不会长出重行（否则看板数字会翻倍）。

## 过程中抓到并修掉的两个真问题

1. **游标自愈**：台账被「数据清理」清空后，游标会指到比文件更远的地方，从此一行都推不上去，
   而界面看上去一切正常（显示「已连接 · 0 条待上行」）。现在会自动重置，并把这件事记进状态里让你看得见。
2. **破坏脚本自己留了坏版**（我的 bug，已修）：备份只建一次、第一次还原就把备份删了，
   后面三次破坏全都没得还原，最后一条坏版 `st.offset += 0` 被**留在源码里**，脚本却打印「已还原」。
   现在改成「还原＝写回内存干净副本 + 逐字校验，不一致直接炸」。
