## 四、两个必须告诉你的坑

### 坑 1：换行符把「asar md5 核对」搞成假红（本轮最大发现）

- **现象**：包内 5 个文件（`copywriter` / `copycheck` / `aireport` / `hotwords` / `cloudsync`）的 md5 与仓库源码**对不上**。
- **真因**：`core.autocrlf=true` + 本仓换行符本来就混用 ⇒ `git worktree` 检出时，把仓库里存的 LF
  **转成了 CRLF**；而工作区这几个文件是**我用 Python 写的 LF**（没经过检出）。
  实测证据：`git show HEAD:<file>` == 工作区，且**去掉 `\r` 后逐字节相同** ⇒ **没有任何内容差异**。
- **为什么不算 bug**：JS 源码里 CRLF 与 LF 完全等价；且 **1.0.5 也是这么发的**，线上正常。
- **处理**：把取证方式从「md5 对齐」换成**「在打包用的同一份字节上跑全量回归」** —— 1036 项全绿。
  这比 md5 对齐更硬：跑的就是包里的字节。
- **建议（本次未做）**：加一个 `.gitattributes` 写 `*.js text eol=lf`，以后检出不再转换，md5 就永远对得上。

### 坑 2：本机已装副本**这次没换** asar

- 打包时发现 `D:\bluevbeta\dewu-bluev-publisher` **有 4 个实例正在运行**（PID 42680 / 45144 / 46856 / 47068，另有 `adb`）。
- 按硬规矩「动数据 / 换 asar 前确认无实例在跑」—— **停在原地，没动它**。
- 影响：**没有影响**。程序 `autoDownload` / `autoInstallOnAppQuit` 恒为 `false`，**不会自己偷偷装**。
  你**重启应用后点「检查更新」**即可升到 1.0.6。
- ★ 附带教训：我早先那次「查有没有在跑」是**假阴性**（PowerShell 的 stdout 被吞了，输出没回来）。
  后来用 `tasklist /FI "IMAGENAME eq 得物蓝V素材发布工具.exe"` 才看见 —— 已记进记忆。
