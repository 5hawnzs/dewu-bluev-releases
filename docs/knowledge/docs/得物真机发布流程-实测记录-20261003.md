## 一、为什么之前「抓不到 / 配不出」这张表

| 观察 | 实测结论 |
|---|---|
| 点「抓取页面结构」抓到的是**模拟器桌面**（18:27 那份 dump 里全是「游戏中心 / 浏览器 / 图库 / 设置」） | 抓取时**没有停在得物 App**。程序本身有拦截（停在别的 App 会拦住），但拦下来之后用户并不知道该停在哪一屏 |
| 23:24 那份 dump 有 98 个节点、**一段文字都没有** | 这是程序里 `dumpsys activity top` 备用通道的产物 —— 它**天生拿不到 text**。也就是说：那一轮 uiautomator（连关动画重试）也失败了，表是从「只有 class/id/bounds」的树上拼的，13 步全是猜的 |
| 老定位表第 1 步是 `tapText "发布"` + `⚠ dump 里没找到，需手动确认` | 这行本身就是「没抓到」的自白。得物发布页**根本没有**叫「发布」的入口 |

**本次突破**：把三个系统动画开关（`window_animation_scale` / `transition_animation_scale` / `animator_duration_scale`）置 0 之后，发布页首屏**一次就抓到**（73 个节点、9 个文字节点）。程序里本来就有这个「临时关动画、抓完还原」的机制，所以这条路是通的 —— 之前失败是因为**抓的时候没停在发布页**。
