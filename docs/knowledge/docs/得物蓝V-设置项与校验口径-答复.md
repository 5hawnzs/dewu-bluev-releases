## ① 设置里的「路径」和「文案模型」

### 路径（三行，作用完全不同）

| 设置项 | 存在哪 | 对用户的作用 |
|---|---|---|
| **素材根目录** `paths.source` | `config.json` | ①**所有「选择目录」弹窗的默认起点**；②素材整理 / 合规检查 / 文案生成的默认素材来源；③导入「AI 内容报告」时，报告里「素材路径」列**空的**就用它补。<br>★ 注意：扁平副本 `flat_<时间戳>` 固定建在**源目录同级**，不是建到输出目录 |
| **输出目录** `paths.output` | `config.json` | **所有产物的落盘处，也是唯一的多机汇总抓手**。它会生这些文件：<br>`发布单_<时间戳>.xlsx` · `合规报告_<时间戳>.xlsx/.csv` · `发布日志_<批次>_<时间戳>.log/.csv` · `publish-log.jsonl`（发布台账）· `run-log.jsonl`（执行台账）· `batches/<批次>/copy.json`（批次文案）· `dumps/`（抓下来的页面结构与候选定位表）· `failures/`（失败截图）· `pending-results.json`（Excel 被占用时的暂存）<br>★「品牌统计」页读的就是这里的两份 `jsonl` |
| **隔离目录** `paths.rejected` | `config.json` | 合规检查判为「该隔离」的违规素材（垃圾文件、超规格又修不了的）搬到这儿。**原素材目录不动、不改名** |

**为什么要单独跟你讲「输出目录」**：这个工具是纯本地的，台账写在本地。想让「10 个人发的都汇到一起看」，
唯一的办法就是**把每个人的「输出目录」都指向同一个共享盘/NAS**（台账是一行一条往后追加的）。
三条必须知道的边界：<br>
① 每台机器要各自设一次（配置不跟账号走）；② **只有台账会汇总，品牌清单和提示词不会**；<br>
③ ★★ 共享盘写不进去时程序是**静默跳过**的（不让写日志失败把发布带崩）⇒ 台账可能悄悄丢几条，没有任何提示。

### 文案模型（可选，默认关）

| 设置项 | 作用 |
|---|---|
| 启用 | 「调用模型」/「本地模板（离线）」 |
| 接口地址 / API Key / 模型 | 按 **OpenAI 兼容**的 `POST …/chat/completions` 调（`endpoint` 会自动补 `/chat/completions`），超时 60 秒，单条失败重试 3 次后**回退本地模板** |
| 温度 | 传给模型的 `temperature`，默认 0.9 |

**它的真实作用边界**（这是最容易被误解的一点）：

- **「选择」由代码定死，模型只管「写」**。标题格式 F01–F10、叙事视角、话题组合都是本地代码先排好、
  并保证不重复的；模型只按指定的格式和视角写 `title` / `body` 两段字。
  ⇒ **所以关掉模型流程不会断**：本地模板照样出标题正文（实测日志：`未配置模型接口，使用本地模板填空（选择仍由代码决定）`）。
- **它决定「用谁的提示词」**：system 提示词 = **品牌自己的「文案生成提示词」在前**，程序固定的输出约束（JSON 字段名、20 字/60–120 字上限）**在后**。
  字段名、字数这些**不交给写提示词的人**，否则漏写一句就会让整批 JSON 解析失败，而失败原因看起来很像是「模型不听话」。
- **隐私**：这是**全程序唯二**会把业务内容发到外部的地方（另一处是校验用的 SKU 接口）。不填地址就一个字都不会外发。

**本机当前状态（刚读出来的）**：`copy.llm.enabled = false`、`endpoint` 为空 ⇒ 走本地模板；
但 `copy.concurrency = 8`（界面给的范围是 4–8，取的是上限）。

## ② 模拟器发布里的「抓取页面结构」和「导入 UI 定位表」

先把这两颗按钮在做什么说清：**得物 App 的发布页没法用固定坐标点**。

> 真机实测（2026-10-01，MuMu 12 / 得物 900×1600）：发布页**有两种布局** ——
> 图片是一行多格（缩略图 y≈358），视频是单格（缩略图 y≈255），**差约 100px**。
> 用写死的坐标去点，必然点在空白处。当时就是因此得出了错误的「点不动」结论。

### 抓取页面结构

| | |
|---|---|
| 背后做什么 | `uiautomator dump` 抓当前屏 → 解析成节点（文字 / `content-desc` / `resource-id` / 类名 / 坐标框 / 中心点） |
| 产出什么 | `输出目录/dumps/ui-dump-<时间戳>.xml`（原始结构）**+** `uiMap-<时间戳>.json`（**候选**定位表） |
| 候选表长什么样 | 一次生成**两套**：`steps`（图文）和 `videoSteps`（视频），每步都带 `unverified: true`，是**按关键词猜的** |
| 抓不到时 | 会**说清原因**：页面一直不 idle / 设备没连上 / 锁屏。页面不 idle 时会临时关掉三个系统动画开关重试一次，**无论成败都还原**（不把你设备设置留在改过的状态） |
| 怎么用 | 把 JSON 打开，**按真机截图把每一步改对**（文案可能要改，坐标可能要点选），然后再导入 |

**一句话**：它是「**别猜，去过一遍真实屏幕**」的那一步。

### 导入 UI 定位表

| | |
|---|---|
| 背后做什么 | 把改好的 `uiMap.json` 存进配置（`publish.uiMap`），发布时按它一步步操作真机 |
| 导入时就校验 | `action` 只能 `tapText` / `tapId` / `tapDesc` / `input` / `wait` / `back` / `screenshot`；`value` 不能空；`wait` 必须填毫秒数。**不认识就当场报错并列出可用值** |
| 为什么要前置校验 | 否则要跑到 `publisher.runStep` 才抛「未知步骤类型」—— 那时素材已经推完设备、界面点了一半，白跑一次 |
| ★ 整表替换 | 只给 `steps` 的话，**上一份的 `videoSteps` 会被原样留下**（配置是深合并）⇒ 会出现「导入了新表、视频还在用旧坐标」。所以导入时缺的键**显式置空** |
| 不会被覆盖的 | **「失败恢复动作」（recover）**是在界面上单独维护的，导入定位表不会把它清掉 |

**没配的后果（程序不糊弄）**：

- 真实通道下 `publish.run` 直接抛：`真实通道需要先配 UI 定位表：…`
- **视频条没配 `videoSteps` 会当场失败**，**绝不拿图文那套硬套**（视频发布页和图文不是一套界面）
- 页面上有徽章随时看状态：`定位表 N 步` / `定位表未配` / `视频 N 步` / `视频未配`

**配套的第三样**：「失败恢复动作」= 发布失败后怎么退回干净起点（否则下一条的界面会被残留页面污染）。
它只认 `tapText/tapId/tapDesc/wait` 四种（返回键是 recover 自己先按的，写进来也不会被执行，所以直接报错拦住）。

## ③ 货号颜色校验：以什么为准、跳过能不能推进

### 校验以什么为准 —— 由「设置 → 内容与校验 → 货号颜色」的**模式**决定

| 模式 | 数据来源 | 细节 |
|---|---|---|
| **本地商品池**（默认） | `%APPDATA%\dewu-bluev-publisher\pool.json` | 由「同步商品池」导入 **CSV / TSV / JSON**（至少要「货号」「颜色」两列）。<br>★ **从没导入过就会回落到内置示例数据**（5 个货号），界面上的来源会如实写「示例数据（未同步）」 |
| **接口查询** | 你自己填的 `SKU 接口` | `GET <endpoint>?sku=<货号>`，带 `Authorization: Bearer <API Key>`，12 秒超时。<br>★ **`endpoint` 空着的话会自动回落成本地商品池**（代码里就是 `mode==='api' && !!endpoint`） |

**第二路（默认开启）**：用图片实际提出的主色反查目录里填的色名 —— 取每条素材的前 3 张图，
单张解码失败就试下一张；只有「目录填的色名能归到色系」且「跟图片主色色系对不上」时才报「主色不符，需人工确认」。
（词表外的色名机器不替人做决定。）

**本机当前实测**（`project.json` 里现成的 4 条）：

```
26FW-YB160+冠军白+1  sku=26FW-YB160  declared=冠军白   pool=[冠军白,冠军黑] img=白  → 通过
26FW-YB160+冠军白+2  sku=26FW-YB160  declared=冠军白   pool=[冠军白,冠军黑] img=白  → 通过
26FW-YB160+冠军白+3  sku=26FW-YB160  declared=冠军黑   pool=[冠军白,冠军黑] img=白  → 通过
UWH760085+黑色条纹+1 sku=UWH760085   declared=黑色条纹 pool=[]              img=黑  → 货号 UWH760085 未查到颜色信息，请核对
```
> 商品池里现在只有 **26FW-YB160** 一个货号（`pool.json` 里那条 `"货号": ["颜色"]` 是**表头被当成数据导进去**的假条目 —— 顺手也修了，见下）。

五种判定原文（与真机工具一致）：`通过` / `单色货号，颜色可空` / `多色货号须指定颜色` /
`颜色不匹配` / `货号 X 未查到颜色信息，请核对`。

### 跳过这一步，直接从文案生成到发布，能不能推进？

**能，而且校验根本不在这条链上。** 发布实际读的是这段：

```
素材整理 → 合规检查 → 文案生成 → 导出发布单 → 开始发布
                                    ↑ 发布队列只来自「发布单」这一件事
```

发布循环里唯一跟校验有关的判断是「**这一条在 `verify.rows` 里、且被判定要拦，就跳过不发**」。

- **没跑过校验** ⇒ `verify.rows` 是空数组 ⇒ 什么都拦不住 ⇒ **照常发布**。
- 顺带说清两条依赖：**文案生成必须做**（不做的话发布单里标题/正文是空的），**发布单必须导出**（发布队列是从它来的）。
  合规检查也不拦发布，但它是「把 PNG 转 JPG、超规格压缩」那一步，跳过它图片可能不合规。

### ★ 但原来这里有个坑（已经修掉）

`verify.js` 原来用**同一个 `level` 字段表达两件不同的事**：

| 判定 | 原来 | 含义 |
|---|---|---|
| `货号 X 未查到颜色信息` | `warn` → `pass=false` | **没有数据**（商品池没导全 / 接口超时） |
| `颜色不匹配` / `主色不符，需人工确认` | `warn` → `pass=false` | **确实有错** |

而发布侧写的是 `if (blocked.pass === false)` **一把抓** ⇒ **「查不到」也被拦住不发**。

后果很实在：**商品池只导了一部分时，池里没有的货号全被判 warn ⇒ 整批一条都发不出去**，
界面上只显示「校验未通过」。而设置页和代码注释里都白纸黑字写着「**接口查不到的货号仅告警不阻断**」——
**行为和自己的说明直接打架**。

**本机就是活例子**：上面那第 4 条 `UWH760085`，商品池里没有它。**按旧逻辑，这一条会被扣押不发**；
修完之后它照常发布，只在「校验结论」列留着「未查到颜色信息，请核对」提醒你。

**改法**（把「严重度」和「要不要拦」拆成两个字段）：

| 判定 | `level`（界面染色） | `block`（要不要拦） |
|---|---|---|
| 通过 / 单色可空 | `ok` | `false` |
| **货号查不到**（无数据） | `warn` | **`false`** ← 只告警，照发 |
| 多色货号没填色 | `bad` | `true` |
| 颜色不匹配 | `warn` | `true` |
| 主色不符，需人工确认 | `warn` | `true` |

- 发布侧与发布单侧都改成看 `block`（同一个函数 `verify.isBlocked()`，**只有一处判据**）；
- 「校验统计」里多了一个 `blocked`（真正会被拦下不发几条），日志也一并打出来；
- **老数据兼容**：升级前存在 `project.json` 里的 `verify.rows` 没有 `block` 字段，
  这时**按结论原文回推**（含「未查到颜色信息」→ 放行），而不是退回旧口径 ——
  否则会出现「升级了但还是被旧口径拦住」，用户会以为没修好。
