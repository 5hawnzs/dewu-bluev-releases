# 侧栏固定左侧 + 窗口最小尺寸

日期：2026-10-04 00:0x ｜ 仓库 `D:\work\dewu-bluev-publisher` ｜ 未提交

## 一句话结论

**最小尺寸定为 `960 × 640`。** 侧栏原来有一条「窗口变窄就翻到顶上」的规则，已删掉。

---

## 一、为什么会翻到上面（实测根因，不是猜的）

`src/renderer/styles.css` 末尾原本有：

```css
@media (max-width:900px){
  .body{flex-direction:column}
  .side{width:100%;flex:0 0 auto;flex-direction:row;overflow-x:auto;border-right:0;…}
  .side .grp{display:none}
  .nav{width:auto;flex:0 0 auto;white-space:nowrap}
  .two{grid-template-columns:1fr}
}
```

而主窗口的 `minWidth` **也正好是 900** ⇒ 窗口一缩到最小，视口宽正好 ≤ 900，
**这条断点必然命中**。也就是说「把窗口拖到最小」这个动作 = 必然触发侧栏横排。

探针逐档缩窗口实测：**窗口 940 侧栏还竖着，930 起翻上去。**

---

## 二、最小尺寸为什么是 960

不是拍的，是量出来的：

| 项 | 数值 | 来源 |
|---|---|---|
| 侧栏固定宽 | 186px | `.side{width:186px;flex:0 0 186px}` |
| 内容区左右边距 | 88px | `.pane` 左右各 22 + 表格外框左右各 22 |
| **品牌统计页那张宽表需要** | **660px** | 探针量 `table.scrollWidth` |
| 合计 | 934px | |
| 实测临界 | 940 不横滚 / 930 起横滚 | 逐档实测 |
| **取整留余量** | **960** | |

高度 640：侧栏在 520px 高就不需要滚动；640 让内容区第一屏多露出一块面板。

> 那张 660px 的表是**品牌统计页**的 9 列汇总表（品牌/状态/条数/成功/失败/批次/最近发布/频次/执行人）。
> 它是全部 11 个页签里最宽的一张 —— 拿它定最小宽度，其它页自然都够。

---

## 三、改了什么（3 个文件）

1. **`src/renderer/styles.css`**
   删掉上面那段 900px 断点，换成一段注释：说明为什么删、坏在哪、以及**以后要调小最小尺寸时必须先想的两件事**
   （侧栏要不要横排 / `.two` 要不要单列），并写明「品牌统计表需 660px，窗口窄于 934 就会横滚」。

2. **`src/main/window.js`**
   新增 `MAIN_MIN_W = 960` / `MAIN_MIN_H = 640`，并且：
   - `createWindow()` 里写死的 `900 / 600` → 走常量
   - `setLoginMode(false)` 里写死的 `900 / 600` → 走常量
     （**两处**，以前各写一份，改一处漏一处就会「登录一次之后最小尺寸又变回去」）
   - `clamp(b.width, 980, …)` 的下限 `980` → `MAIN_MIN_W`
     （否则用户缩到 960 关掉再开会被悄悄抬回 980：「我明明缩过，怎么又变大了」）
   - 导出 `MAIN_MIN` 给自检用（避免测试里另写一份数字）

3. **`tools/uicheck.js`**
   新增 8 条断言（见下）。

## 四、新增断言（8 条，全绿）

关键是**行为级** —— 把窗口缩到「应用允许的最小尺寸」，再量：

```
PASS ★ 缩到最小尺寸后侧栏仍是竖排（不是横排贴到顶上）—— 正是用户反馈的那一幕
     → {"vw":947,"vh":579,"sideFlex":"column","bodyDir":"row","sideX":0,"sideW":186,"mainX":186,"mainY":38}
PASS ★ 缩到最小尺寸后侧栏仍在左侧、内容区在它右边（不是上下堆叠）
     → sideX=0 sideY=38 sideW=186 mainX=186 mainY=38
PASS ★ 最小尺寸下没有页签横向溢出（内容不会被裁掉）  → 最大 0px（切了 11 个页签）
PASS ★ 最小尺寸下表格都不横向滚动 ——「960」这个数的来源（品牌统计页要 660px）  → 最大表横滚 0px
```

另外 4 条是源码级：

```
PASS ★ styles.css 里没有「窄屏把侧栏改成横排」的媒体查询
PASS ★ 两处最小尺寸都走 MAIN_MIN_* 常量、没有写死的数字
PASS ★ window.js 导出了主窗口最小尺寸
PASS ★ 最小宽度留得下侧栏(186) + 内容区左右边距(88)
```

> 自检里为了让「品牌统计」页**真的渲染出那张宽表**（空数据下它只有空态，量不到宽度 = 假绿），
> 临时塞了一份假 stats，**跑完必还原**。
> 踩到两个自己绊自己的坑，已写进代码注释：
> ① 桩缺字段（少 `range`）⇒ 渲染层抛异常，把「零控制台报错」那条绊红 ⇒ 桩必须与真实同形态；
> ② 判据写错 ⇒ 并排时侧栏与主区**本来就等高**、主区 y 也**不是 0**（上面有自绘标题栏，实测 38）。
