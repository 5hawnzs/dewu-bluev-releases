# 可编辑词库模块 —— 范围 / 读取链 / 验收口径

> 2026-10-03 · 本次只做**查证**，**未动任何代码**。
> 起因：你问「这个模块是否包含内置热词库？如果修改，标题文案是否会读取修改的内容？」

---

## 一、两个问题的直接答复

**Q1：可编辑词库模块是否包含内置热词库？**
**包含 —— 而且「包含」正是这个模块的定义。** 它不是另建一份新词库，而是**内置词库的编辑界面**：
显示的就是内置那 8 组词，你在界面上增 / 删 / 改 / 加点，动的是**同一个库**，「恢复内置」= 一键回到代码里的出厂基线。

但**有一样东西不进去、也不许编辑**：**10 种句式骨架（T01~T10）**。原因见第二节。

**Q2：修改后，标题文案会不会读取修改的内容？**
**分三种情况，必须说清，否则会得到「改了没反应」的错误结论：**

| 情况 | 会不会读到改动 | 说明 |
|---|---|---|
| **现在的代码（模块还没做）** | ❌ **不会** | `hotwords.js` 是编译期常量 `const GROUPS / const STYLES`，`require` 之后就被缓存，**全仓没有任何一处从配置里读词库**。也就是说：**今天就算你手改了词库文件，标题也不变**（只有改源码才变）。 |
| **做成模块、但只做界面不做读取链** | ❌ **不会**（最危险的假象） | 界面能改、能保存、重启回来还在 —— 看着全对，**但标题永远用旧的**。这是最需要防的坑。 |
| **做成模块 + 把读取链一起改掉** | ✅ **会**（前提是「开着模型」） | 见第三节：**有 3 个读取点必须一起改**，漏一个就出现静默不一致。 |

★ 还有一个**独立于以上三种**的例外，务必记住：
**「关掉模型 / 离线」这条路走的是本地模板 `FORMATS`（F01~F10），它完全不读词库。**
⇒ 改词库对本地模板的标题**零影响**。所以**验收必须在「开着模型」的状态下测**，否则你会以为词库没生效。

★ 「收尾」组**算词**（可编可加），但**它填进哪条骨架的哪个位置由代码定** —— 你只管给词。

### ★ 先把一个容易误会的地方说清：收尾组**在**库里，只是不当「前缀热词」

跑真代码数的（`node -e` 直读 `hotwords.js`）：**全库 8 组 / 64 词**。

| # | 组 | 词数 | 例词 | 算不算「前缀热词」 |
|---|---|---|---|---|
| 1 | 风格 | 12 | 简约百搭 / 老钱风 / 美式学院风 / clean fit | ✅ 算（12 个） |
| 2 | 氛围 | 8 | 韩系氛围感 / 松弛感 / 慵懒风 / 清冷感 | ✅ 算（8 个） |
| 3 | 色感 | 7 | `{色}调穿搭` / `{色}系氛围感` … | ⚠ 整组都是 `{色}` 模板 ⇒ **剔掉后 0 个** |
| 4 | 场景 | 7 | 通勤 / 约会出街 / 周末出街 / 校园 | ✅ 算（7 个） |
| 5 | 人群 | 6 | 少年感 / 韩剧男主感 / 减龄穿搭 | ✅ 算（6 个） |
| 6 | 季节 | 6 | 冬日神器 / 过冬必备 / 换季刚需 | ✅ 算（6 个） |
| 7 | 情绪 | 6 | 一眼心动 / 治愈系 / 情绪价值拉满 | ✅ 算（6 个） |
| 8 | **收尾** | 12 | 太帅了 / 闭眼入 / 谁穿谁帅 / 直接封神 | ❌ **不算** |

**64 = 45（前缀热词）+ 7（色感 `{色}` 模板）+ 12（收尾）**。

- **收尾组确实在热词库里**（就是第 8 组），也**会**喂给模型（`promptBlock()` 输出全部 8 组）。
- 它只是**不进 `copycheck` 那个「前缀热词」子集** —— 因为「前缀热词」这个名单是专门用来抓
  「热词贴在单品前面、句子没收尾」的**标签串**的；收尾组**天生在句尾**，把它算进去只会误判。
- ⇒ **两件事别混**：「在不在库里」（在）／「算不算前缀热词」（不算）。

### 不包含（**明确不可编辑**）
- **10 种句式骨架 T01~T10**。理由：**词是素材、骨架是语法**。骨架里带着「连接字在第几位、收尾在末尾」这类结构信息，
  改坏会**直接产出病句 / 标签串**，而我们的判据只能**事后告警**、拦不住。所以这一层锁死在代码里，
  由 `tools/copytest.js` 的断言钉着（T01~T10 一条不少、不许出现 `+`、不许写死颜色）。
- 外网热词**不会自动进库**：形态是「离线抓取脚本（定时）→ 落 `hotwords-<日期>.json` → 界面显示**来源与日期** +
  逐词勾选 / 删除 → 你点『并入词库』才生效」。默认**不自动并入**。
  ★ **2026-10-03 11:00 用户已定：这一块先不做** —— 本期只做「可编辑 + 恢复内置」。下面这段仅作将来参考，**不进本期范围**。

### 进库的三条红线（界面上要常驻提示）
1. **材质 / 参数词不许进**（鹅绒、充绒量、加厚、防风防水、羊毛含量…）——它们是「这件衣服的客观事实」，
   必须图里看得见或货号有写，词库给不了，让模型自己编就等于造假。
2. **极限词、别的品牌名不许进**。
3. **`{色}` 是占位符，保留它才会跟着本行颜色走**（删掉它就会写死颜色）。

## 三、读取链：改了之后，标题凭什么读到（**3 个读取点，缺一不可**）

```
        词库编辑界面（单开一屏）
        └ 保存到 config.json → copy.hotwords
                    │
        ┌───────────┼────────────┐
        ▼           ▼            ▼
   ① promptBlock()  ② styleOf(i)  ③ PREFIX_WORDS
   copywriter →     copywriter →  copycheck →
   给模型的词表      骨架轮换       判「标签串」
   ⇒ 决定标题用词   （不可编辑）   ★ 最易漏：误报 / 漏报
```

| # | 读取点 | 文件 | 作用 | 漏改的后果 |
|---|---|---|---|---|
| ① | `hotwords.promptBlock()` | `src/main/services/copywriter.js`（拼 system 提示词处） | **把词表交给模型** —— 这是**标题实际用词的唯一来源** | 标题永远用旧词（最核心的一处） |
| ② | `hotwords.STYLES.length` / `styleOf(i)` | 同上（`buildPlan`） | 按行轮换骨架 T01~T10 | 骨架不可编辑，本身不随编辑变；但它与 ① **必须读同一份对象**，否则提示词里出现「骨架清单」与「词表」不同版 |
| ③ ★ | `copycheck` 的 `PREFIX_WORDS` | `src/main/services/copycheck.js`（由 `hotwords.GROUPS` 派生） | 拿着热词表**事后判断**标题是不是「热词贴单品」的标签串 | **最容易漏**：标题用了你新加的词，核对却还在用内置旧表 ⇒ **误报「像标签串」/ 漏报** |

### ★ 一个会让「改了不生效」的隐藏机制
`ALL_WORDS`（`hotwords.js`）和 `PREFIX_WORDS`（`copycheck.js`）都是**模块加载（`require`）时就计算好的常量**：

```js
const ALL_WORDS    = GROUPS.reduce((a, g) => a.concat(g.words), []);          // hotwords.js
const PREFIX_WORDS = hotwords.GROUPS.filter(...).reduce(...).sort(...);       // copycheck.js
```

⇒ **即便把来源改成读配置，只要这两个还是「常量」，就必须重启应用才生效** ——
表现是：**界面上改完是绿的、保存也成功，但这一轮生成的标题还是旧的**。
⇒ 所以它们**必须转成函数 / 取数器**（如 `allWords()` / `prefixWords()`），在**每次生成时**现取。

### 3.4 「能不能转函数」—— 能，而且成本很低（实测调用点）

把两个常量在全仓（`src/` + `tools/`）数了一遍，调用点**极少**：

| 常量 | `src/` 里的真调用点 | `tools/`（测试）里的调用点 | 结论 |
|---|---|---|---|
| `ALL_WORDS` | **0 个** —— `src/` 里**没有任何地方用它**（只定义 + 导出） | `copytest.js` 2 处（查词库有没有混进材质词） | 转成 `allWords()` 几乎零风险：只需同步改测试那 2 处 |
| `PREFIX_WORDS` | **1 个** —— `copycheck.js` 的 `looksLikeWordPaste()` 里 `PREFIX_WORDS.some(...)` | **0 个**（导出在 `copycheck.js` 第 399 行，但全仓无人解构使用） | 转成 `prefixWords()` 只动这 1 处 + 导出名 |

- 两者都是**模块加载期算好的常量**，改成函数后由调用方**每次现取**，改词库立即生效、不用重启。
- `PREFIX_WORDS` 里那个 `.sort((a, b) => b.length - a.length)`（按词长倒序，`startsWith` 才不会被短词抢走）
  **必须保留** —— 转函数时容易漏掉这个排序，漏了就会出现「长词匹配不到」的隐性退化。
- ⇒ 还要注意：`copycheck.js` 里的 `PREFIX_GROUPS`（哪几个组算前缀）是**硬编码的 7 个组名**，
  这没问题 —— 模块只允许编**8 个固定组里的词**，**不允许新增组**，所以这份组名清单不用跟着动。

## 五、验收怎么测（可复算，别只看界面）

1. **正向**：界面加一个**新造的、绝不可能撞车的词**（例：`测试词ZZZ`）→ 保存 →
   跑一批（**开着模型**）→ 断言 `promptBlock()` 的输出里**含这个词**，且模型产出的标题里**出现过**它。
2. **反向**：把同一个词**删掉** → 再跑 → 断言 `promptBlock()` 输出里**不含**它。
3. **同步性**：③ `copycheck.PREFIX_WORDS` 必须**同一轮**就含新词 —— 验法是拿一条「以该新词开头 + 单品结尾」的
   标题喂给核对，断言它**被判成「像标签串」**（如果读的是旧表，这条会**红**，正是要抓的漏改）。
4. **恢复内置**：点「恢复内置」→ 断言词库 == 代码里的 `GROUPS`，且上面 1 里那个测试词**消失**。
5. **红线**：往界面里塞 `鹅绒` / `加厚` → 断言**被拒**（不入库 / 明确报错）。
6. **本地模板例外**：关掉模型跑一批 → 断言标题**完全不依赖词库**（说明这条链本来就不读它，别把「没反应」当 bug）。
