## 一、三处修复

| # | 问题 | 改法 | 效果 |
|---|---|---|---|
| 1 | `catch` 里只记 `String(e.message \|\| e)`，网络错的 message 就是六个字 `fetch failed`，`e.cause` 被丢掉 | 新增**纯函数** `describeErr(e)`：拼 `e.cause.code`（`ENOTFOUND` / `ECONNRESET` / 超时）+ HTTP 状态 | 下次日志能看到**为什么**断，而不是「就是失败了」 |
| 2 | `logbus` 只进内存、成功后 `lastError` 又被清空 ⇒ 磁盘上一条痕迹都没有 | 新增 `errorLogFile()` = 输出目录 `cloud-sync-errors.log`；`appendErrorLog()` 全程 `try/catch`（**best-effort，绝不因写日志抛错影响同步**） | 事后可复盘：每次失败落一行 `fail=… backoff=…s offset=… pending=… err=…` |
| 3 | 「无待上行」那一轮不清 `lastError` ⇒ 一次旧故障的红色标记永远挂着 | 该轮一并清 `lastError`（`fail=0 / nextTryAt=0`） | 界面不再显示「同步失败」僵尸标记 |

### 顺手修掉的两个真缺陷（都属于「会写出假数据」）

- **`pending` 取到了 3 秒缓存** ⇒ 失败日志里可能写出**假数字**。改用本轮**已读过**的 `ledgerRows` 现算；读不到就写 `?`，**不编**。
- **`status()` 根本没有 `fail` 字段**，而断言引用了它（`undefined === 0` 恒为假）——典型的「空==空」风险。改成按真实字段断言。

## 四、下次怎么用

1. 界面冒「云端同步失败」时，先看**输出目录下的 `cloud-sync-errors.log`**（新加的）——里面有 `fail/backoff/offset/pending` 和**真原因**。

   **不是云端的问题**，数据也不会丢（没上行成功的行留在本地台账里，代理回来会补传）。

## 六、⚠️ 事故：演示时误插了 2 条云端记录（未清掉，需要你一条 SQL）

**发生了什么**：为了演示「失败时磁盘上会留下什么」，我用一个不存在的域名去触发失败，
但**拦错了配置读取点**——`cfgOf()` / `explicitOf()` 读的是 `store.get('cloud')` **整个对象**，
我只拦了 `cloud.url` 这一个键 ⇒ `url` 回退到**内置的真实地址**，那次同步**真的成功了**（`uploaded: 2`）。

**后果（已核实）**：线上 `publish_log` 多了 2 行——

| id | ts | item_id | machine_id | kind | result |
|---|---|---|---|---|---|
| 418 | 1760000000001 | DEMO1 | m_279f89ac | 图文 | 发布成功 |
| 419 | 1760000000002 | DEMO2 | m_279f89ac | 图文 | 发布成功 |

- ts 落在 **2025-10-09**（不是今天）⇒ 只影响那一天的统计。
- **我删不掉**：anon key 发 DELETE 返回 HTTP 200 但**影响 0 行**（RLS 静默拦截）；本机全盘扫过，**只有 anon、没有 service_role**。
- 清理语句已备好：`_待清理-云端误插2条-418-419.sql`（含先看 / 再删 / 复查三步，带 `item_id` 双保险）。

**这次暴露的真实隐患（建议修）**：**本机没有「云端隔离开关」**。
`cfgOf()` 的设计是「配置留空 ⇒ 回退到内置地址」，这是为「装上就能连」服务的，但它同时意味着
**任何用真代码路径跑 `syncOnce()` 的测试/探针，只要机器上配置为空，就会打到线上库**。
- 已量清的**正确隔绝做法**（下次探针照这个写）：`store.get = k => k === 'cloud' ? { enabled: false } : realGet(k)`
  —— `enabled: false` 时 `syncOnce()` 直接 `return { skipped: '未启用' }`，**一个网络包都不发**。
- 建议在 `cfgOf()` 里加一个只在测试用的开关（如读环境变量 `BLUEV_CLOUD_OFF=1` 就当作未启用），
  这样以后写探针不必靠「记得拦对键」这种容易出错的手工操作。**等你点头我再动**（那一路会话还在改同一批文件）。
