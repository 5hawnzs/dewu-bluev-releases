# 玻璃（系统亚克力）到底透不透「下面的应用」——本机复测 2026-10-08

**结论（推翻旧说法）**：透。之前那句「**只能透桌面、不能透应用**」是**错的**。
—— 那是 **mica** 的行为，被张冠李戴到了 **acrylic** 头上。

用户观察「下面有应用也能隐隐约约看到」**是对的**。

---

## 1. 官方口径（Microsoft Learn）

- **Acrylic 文档**：
  > "**Background acrylic** reveals the desktop wallpaper **and other windows that are behind the currently active app**,
  > adding depth between application windows…"
- **Mica 文档**：
  > "Mica is specifically designed for app performance as it **only samples the desktop wallpaper once**…"

对应关系（`DWM_SYSTEMBACKDROP_TYPE`）：

| Electron `backgroundMaterial` | DWM 值 | 透什么 |
|---|---|---|
| `'acrylic'` | `DWMSBT_TRANSIENTWINDOW`（Desktop Acrylic / Background Acrylic） | 壁纸 **＋ 后面的其它窗口** |
| `'mica'` | `DWMSBT_MAINWINDOW` | **只有壁纸**（不透明 + 壁纸色调） |

---

## 2. 本机实测（可复算）

环境：Win11 23H2 / 2560×1440（scaleFactor 1）/ Electron **31.7.7**

布局：左半屏放一块**不透明纯品红**普通窗，当「下面那个应用」的替身；
测试窗各拍两次 —— 一次**压在品红窗上**、一次**压在右侧深色的真实应用上**（同一张壁纸没变）。
判据：同一材料、两个位置的窗心读数若明显不同 ⇒ 它真的在采样「窗口背后的内容」。

| 编号 | 材料 | 位置 | 窗心读数 |
|---|---|---|---|
| A1 | `acrylic` | 压品红窗 | **rgb(223,0,223)** |
| A2 | `acrylic` | 压深色应用 | rgb(61,61,61) |
| M1 | `mica` | 压品红窗 | rgb(28,33,37) |
| M2 | `mica` | 压深色应用 | rgb(32,31,37) |
| C1 | 无材料（对照） | 压品红窗 | rgb(0,0,0) |
| C2 | 无材料（对照） | 压深色应用 | rgb(0,0,0) |

**判读**

- `acrylic` 两位置差 = |223−61| + |0−61| + |223−61| = **385** ⇒ 在采样**窗口背后的内容**。
- `mica` 两位置差 = 4 + 2 + 0 = **6** ⇒ 基本不变 ⇒ **只采样壁纸，不透窗口**。
- 无材料对照（同一个透明窗，只去掉 `backgroundMaterial`）恒为 `rgb(0,0,0)`
  ⇒ A 组的颜色**确实是材料带来的**，不是「透明像素被拍成背景」的假象。
- 参考点：品红区 `rgb(255,0,255)`、右侧深色区 `rgb(29,29,30)` ⇒ 底窗确实存在、确实被测试窗盖住。

原始读数：`result.json`；整屏取证：`shots/screen-A1…png`。

## 3. 无效的那一组（诚实清单）

计划里的 **A3「让底窗抢焦点，看 acrylic 在非活动窗口状态下是否塌成实心色」没测成**：
`base.focus()` 把底窗**抬到了测试窗前面**，窗心读到纯品红 `rgb(255,0,255)` —— 拍的是底窗本身。
该组**作废**；「非活动窗口的 acrylic 是否变实心」本轮**未测**（官方文档称会，未在本机复核）。

---

## 4. 旧结论为什么错

旧探针（同日早些时候）留下的唯一数字是「两块窗放在壁纸不同位置 → `rgb(83,83,83)` vs `rgb(64,64,64)`」——
这**恰好落在本轮 A2 那一档的量级**（采样背景）。说明它**从没做过「测试窗压在另一块窗口上」的有效对照**，
「不透其它窗口」是**从「只测过壁纸」推出来的**，不是测出来的。旧产物已删，无法复核其判据。

★ 教训：判「透不透 XX」时，**必须有一组「把 XX 放进去」的对照**，
并且要保证 ① 测试窗是**活动窗** ② 测试窗**在底窗之上**（`focus()` 会把底窗抬到前面）。

---

## 5. 对产品的影响（得物蓝V 玻璃档）

玻璃档用的就是 `backgroundMaterial:'acrylic'` ⇒ 后面有别的应用时，**本来就会隐隐约约透出来**
（外面还压着一层 `rgba(17,18,24,.58)` 的面板，所以是「隐隐约约」）。**这是 Windows 的设计行为，不是 bug。**

若确实想要「只透壁纸、不透应用」，只能换成 `backgroundMaterial:'mica'`——
代价：Mica 是「不透明 + 壁纸色调」，玻璃感会明显变弱（本轮 M1/M2 读数 `rgb(28,33,37)` 左右，几乎看不到背后内容）。
