## 二、为什么这件事之前会填错（真根因）

你的目录里既有「母带」三层结构，也有工具自己产出的扁平副本：

```
D:\_清理备份_20261002-103202\卡宾\20260901\26FW-YB160+冠军白\1\    ← 母带：叶子是序号层，带 `+` 的是父目录
D:\…\flat_20261001-0132\26FW-YB160+冠军白_1                        ← 扁平副本：`_1` 是去重序号
```

工具原来会把扁平副本那一行解析成：

```json
{"color":"冠军白_1"}      ← 实测输出，`_1` 被当成了颜色的一部分
```

**「冠军白_1」这种假颜色填进报告，比空着更坏**（运营会当成真颜色核对）。
同一分钟重跑还会接出 `-2`。

## 三、改了什么（四处）

### 1. 文件夹名解析：新增「可信度」标记，只有一个来源能用

`src/main/services/flatten.js` 的 `parseName` 现在**每个分支都多返回一个 `how`**：

| `how` | 长这样 | 能不能拿去填报告 |
| ----- | ------ | ---------------- |
| `'plus'` | `26FW-YB160+冠军白` / `…+冠军白/1/` | ★ **只有它** |
| `'split'` | 老式三层 `货号\颜色\1` | 否 |
| `'guess'` | `品牌甲\20260904\IMG_5253\1` → 货号=20260904 / 颜色=IMG_5253 | 否（随手命名，**不猜**） |
| `'name'` | 单层名字 | 否 |

新增 `stripTail()` **只摘「分隔符 + 纯数字」结尾、最多两层**（先 `-2` 再 `_1`）：

- `冠军白` / `黑色条纹` —— **不误伤**
- `米白2`（数字是颜色名的一部分）—— **不摘**
- 随手命名的 `IMG_5253` —— **故意不摘**（摘成 `IMG` 反而更像真的货号）

### 2. 报告填空格：只补空格、不覆盖、对不上只点名

`src/main/services/report.js` 新增 `fillGoodsFromLeaf`：

- **只认 `how === 'plus'`** —— 不是真「货号+颜色」的名字，一律不填（**宁缺勿错**）；
- **只填空格子** —— 运营已经填了的值**一个都不动**；
- **对不上就不补** —— 报告里的货号和文件夹名解析出的货号是**两个不同货号**时，
  两边都不改，只在日志里点名：「第 X 行：报告写 A、文件夹是 B，对不上」；
- 补出来的值**写回 xlsx**（新增 `fillGoods()`，每格再判一次是否仍为空）；
  文件被 WPS 占用时会**如实告警「没能写回」**（关掉 WPS 再导入一次即可），
  **本次发布照常用补出来的值**，不影响发布。
- ★ 写回**不占用**「实际执行时间 / 执行结果」那条暂存队列（两个队列混在一起会说不清漏了哪边）。

「文案核对」也提前了一步：**有货号没颜色 ⇒ 告警**；**连货号都没有 ⇒ 判 bad**（发布时关联不到商品）。

### 3. 主题：默认浅色 + 切换按钮搬到顶栏

- **默认浅色**（出厂配置就是 `light`；老配置里的「跟随系统」按**浅色**算，不会又变回跟随系统）。
- 切换按钮放在**最上面标题栏、「项目」的左边**，**点一下就切**浅色/深色。
- 图标用两个 SVG 靠 CSS 切显隐（不换 `innerHTML`），所以**图标和实际主题永远一致**。
- 设置页里原来那个「外观 → 主题」下拉**整块删掉**了，只留一句说明。
- ★ 主题在**建窗口之前**就应用好 —— 否则在深色系统的机器上会先闪一块近黑。

### 4. 文档

`README.md` 新增「货号 / 颜色从哪来」「正确的发布流程」两节 + 「主题（浅色 / 深色）」小节，并把第 6 条「模拟器发布」的入口说明补齐。
