# 得物蓝V · 标题改造：从「商品描述」改成「产品词 + 热门词」词包

> 日期：2026-10-03（第三轮 / 第八次会话）
> 你给的样例：`羽绒服+简约百搭`、`羽绒服+韩系氛围感`、`羽绒服+灰色慵懒风`、`羽绒服+美式学院风`、`蓝调穿搭+羽绒服`、`冬日神器+羽绒服`

## 一、先说结论

**问题不在模型，在我们的提示词。** 查出来两条叠加：

| # | 原因 | 证据 |
| - | ---- | ---- |
| ① | 上一轮我把标题**钉死**成「品类 + 看得见的款式特征 + 颜色 + 风格或场景词」——模型老老实实照做，所以出来的必然是商品描述 | 真机原话 `蓝灰横向绗缝立领羽绒，左胸刺绣🐻` |
| ② | 你那份品牌提示词里写着「格式参考以下 **10 种多样化格式**创作」——**后面那 10 种格式的清单是空的**（原文这一段是张图，转成纯文本时丢了） | 读本机 `config.json` 里 `brands[0].promptWrite`：以「……禁止单一格式重复：」**冒号结尾就没了** |

⇒ 模型既没有可挑的**词**、也没有可套的**形状**，只能把图里的款式特征串成一句。

### 3. 文案核对跟着改口径（不然好标题会被标黄）

- 只有**颜色词紧挨着单品词**才算在声明这件衣服的颜色 ——「燕麦色圆领毛衣」算；「**蓝调**穿搭」**不算**（那是氛围词）。
- **删掉**「标题里没提到颜色就告警」这条 —— `羽绒服+简约百搭`、`冬日神器+羽绒服` 这种好标题本来就不带颜色，
  留着它会把一整列标黄，而那一列的意义就是「一眼看出哪几条要回头看」，全黄 = 没人看。
  **颜色不是必须出现在标题里**；真正要防的是**写错颜色**，这条仍在查。
- **新增**一条：标题堆了 **3 个以上款式特征**（绗缝/立领/刺绣/拉链/口袋/圆领/左胸…）⇒ 提示「像商品描述」。
  被打回的原句正好命中 5 个。

| T09 情绪热词+单品 | 燕麦色 | `温柔暴击+燕麦色针织衫 ☁️` |

**关于那 6 行 `warn`**：全部是**已知的「图片主色」误报**（浅背景压过主体，取出来是「银」），
加上这批数据是我**故意**用同一张图配了不同颜色（军绿/藏青/灰 都配的卡其图）——
**没有一条**是「标题没提到颜色」，说明口径改对了。

### ★ 顺带抓到并修掉的一个真缺陷

第一次跑的时候，**T03 那条声明颜色是「酒红」，标题却写成「羽绒服+灰调高级感」** ——
模型把**格式示例里的「灰」**照抄进来了。⇒ 示例改成占位符 `{色}`，并在提示词里写明「示例里的颜色也要换成**本行**的颜色」。
改完重跑：`羽绒服+酒红调慵懒风🍷` ✓。

## 四、实测证据（可复算）

| 项目 | 结果 |
| ---- | ---- |
| 全量回归 `node tools/run-all.js` | **17 套 989 项全绿**（`copytest` 71 → 90） |
| 定点破坏（`D:\tmp\ai\break-title.py`，10 条 N1~N10） | **10/10 全被抓到**，逐字节还原 + md5 核对通过 |
| 真机验证 | 10 条，用时 ~11.4 s，报告落素材文件夹 |

**★ 自证过程里有两条值得记下来的**：

1. 定点破坏**第一轮只抓到 6/10**，3 条 MISS **全是「断言本身不够硬」**（不是代码没坏）：
   - 「标题约束退回描述」——我的破坏只改了首句，后文里还留着「产品词/热门词」字样 ⇒ 断言照绿；
   - 「颜色声明退回旧判据」——断言只测了工具函数，**没测 `check()` 的行为**，把调用点换掉也抓不到；
   - 「词库混进材质词」——**根本没有这条断言**。补硬后才 10/10。
2. 断言里的**宽松正则会匹配到别的 token**：`/T\d\d/` 从货号 `26FWT75` 里匹配出 `T75`，
   「3 条格式各不相同」于是靠货号也成立 ⇒ 必须锚到 JSON 键上（`/"本行标题格式":"(T\d\d)/`）。
