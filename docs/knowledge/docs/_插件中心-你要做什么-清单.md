## 路线 ①：让我更新「我这边这个站」——你什么都不用做

我这边已经有一份完整的插件中心源码：`pluginhub-site\`（就是从你给的 zip 解出来的那份，我已经改过并部署过）。

我只要做三件事就能出新版，**链接不变**（实测：同一个目录连着部署两次，返回的是同一个地址）：

1. 把 1.0.9 的安装包放进 `pluginhub-site\dl\`（主仓 `dist\` 里现成就有，107,047,202 B）
2. 改 `pluginhub-site\dl\bluev-version.json`（版本号 / 文件名 / 大小 / sha256 / 更新日志）
3. 重新部署

**要做的只有一件事：你说一声「更新到 1.0.9」，我就办。**
办完给你链接，你在群里重新发一次（同事收藏的要换一下）。

---

## 路线 ②：想让「同事收藏的旧站」更新 —— 必须那台设备出面

这个地址是**另一台设备部署出来的**，那个工作区文件夹不在我这台机器上，我没有任何通道写进去。给多少源码都没用——源码是内容，缺的是**上传动作**。

### 做法甲（推荐）：在另一台设备上操作

1. 在那台设备上打开 WorkBuddy，打开原来那个工作区（含 `deploy/` 的那个）
2. 对它说：「把 `deploy\dl\` 里的安装包换成新版，改 `bluev-version.json` 的版本号和 sha256，然后重新部署」
3. 部署完看返回的地址 —— **如果地址没变**，同事的收藏自动生效；**如果变了**，把新地址发群里

### 做法乙（想让我代劳才需要）：把整个工作区文件夹搬过来

不是那个 zip（zip 只是导出产物），要**原始工作区文件夹**：

```
WorkBuddy\
  └── 2026-09-29-10-12-49\     ← 这一层目录名要保住
        └── deploy\
              ├── index.html
              ├── version.json
              ├── dashboard.html / dashboard/
              ├── dl\
              └── assets\
```

- 用 U 盘 / 网盘 / 微信传都行，拷到这台机器任意位置
- **目录名 `2026-09-29-10-12-49` 不要改**
- 拷完告诉我路径，我用同样的方式部署一次，**看返回的地址是不是 `3e2624b1…`**

⚠️ 说实话：**这条不保证成功。** 我只实测过「同一台机器、同一个目录，重复部署 → 地址不变」，没实测过「换一台机器能不能拿到同一个地址」。试一次就知道，不花钱也不破坏东西。

---

## 路线 ③（长远建议）：别再让同事收藏沙箱地址

沙箱地址是会变的，而且寿命不保证。建议：

- 群里只发**一条置顶消息 / 群公告**，内容就是「最新版下载：\<链接\>」，以后换地址只改这一处；
- 或者换成地址固定的托管（对象存储静态站 / GitHub Pages / EdgeOne Pages 之类），一劳永逸。

---

## 一句话让你选

- **只想快点让同事拿到 1.0.9** → 走路线 ①，我现在就做，你什么也不用准备。
- **非要让旧链接继续能用** → 走路线 ②，那台设备得出面（或把工作区文件夹原样搬过来让我试一次）。
