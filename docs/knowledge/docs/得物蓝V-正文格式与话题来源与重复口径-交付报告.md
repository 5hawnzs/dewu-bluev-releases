## 1. ① 热词库：该单开一个模块，但**只让编「词」**（只给判断，没动界面）

### 1.1 「单开模块」——同意你的直觉，理由是两个频率不一样

词库是**低频维护**（隔一阵调一次），文案生成是**高频动作**（每天跑）。
并进「文案生成」页的后果是：改词的时候容易误触生成、跑生成的时候又被词表挡路。

### 1.2 「热词库是否包含标题结构（收尾词组）」——**收尾词组算「词」，但它放在哪由代码定**

- **词是素材、骨架是语法。** 句式骨架（`hotwords.js` 的 T01~T10）里带「连接字放在第几位、
  收尾放在末尾」这种**结构信息**。用户改坏会**直接产出病句 / 标签串**，而我们的核对只能**事后告警**，拦不住。
- ⇒ 模块里只放 **8 组词**：风格 / 氛围 / 色感 / 场景 / 人群 / 季节 / 情绪 / **收尾**。
  **收尾词组属于「收尾」组，可以编、可以加**（`太帅了` / `松弛感拉满` / `一眼心动`…），
  但它**填进哪条骨架的哪个位置由代码决定** —— 这样用户能换词，改不坏句子结构。
- 模块要自带三条红线提示：
  ① **材质 / 参数词（鹅绒 / 充绒量 / 加厚 / 防风防水 / 羊毛含量）不许进库** —— 那些是这件衣服的客观事实，
  得图里看得见或货号有写；词库里给了就等于**教模型造假**；
  ② 极限词、别的品牌名不许进；
  ③ `{色}` 是占位符，填词时**保留它**才会跟着本行颜色走（写死了颜色，实测会被模型照抄到别的颜色上）。

### 1.3 「让模型读小红书 / 得物 / 抖音热词」——**不是现抓，是「抓取 → 入库 → 人工审核 → 才当词用」**

三条理由：

1. 这几个平台**没有公开的热词接口**，只能爬 ⇒ 要对抗风控 ⇒ **随时会挂**。
   挂着的时候必须能**如实退回本地词库**（不能报错，更不能让文案直接没了）。
2. 把抓来的词**直接塞提示词 = 不可控**：可能夹进营销词 / 极限词 / 别的品牌名 ——
   而这些恰恰是核对里要 `warn` 的东西。
3. 它是**离线批处理**（一天跑一次就够），跟「生成文案」这条链**不该耦合** —— 生成时的网络依赖已经够多了。

⇒ 建议排期：**这一轮先做「可编辑的词库模块」**（本地、离线、可控）；
「读外网热词」作为**下一条单独排**，形态是：

```
离线抓取脚本（定时）
  → 落一份 hotwords-<日期>.json
  → 界面里显示【来源 + 日期】+ 逐词勾选 / 删除
  → 用户点「并入词库」才生效（默认不自动并入）
```

★ 还有一条要提前讲明：**外网抓来的词没法验证真假**（“今年流行”这种谁也证不了），
所以它们**永远只能当风格 / 氛围 / 场景词**，不能当材质参数词 —— 与内置词库同一条红线。

## 2. ② 话题：**以程序为准** —— 正文不带 `#`，话题写进「话题1~5」格子

### 2.1 定下来的口径

| | 从哪来 | 写到哪 |
| --- | --- | --- |
| **必带话题** | 「文案生成 → 批次设置」那个输入框（`copy.requiredTopic`） | 固定占**话题 1~N** |
| **额外话题** | **品牌提示词里写的 `#话题`**（你说的「额外话题我会在品牌提示词中写入」） | 接着往后排 |
| **正文** | 模型写的 4~5 行短句 | **一个 `#` 都不带** |

### 2.2 为什么不让正文带 —— 你要的效果其实**没丢**

- 得物这边**只有格子里的话题才点得动**，写在正文里是**死文本**（看着像话题，其实点不了）。
- 而**格子里的话题在得物上本来就是显示在正文后面**的 ⇒
  你要的「正文最后带话题」**这个效果是有的**，只是**由格子实现、不由正文文本实现**。
- 所以那两条写法**不冲突**：品牌提示词里「正文结尾带 5 个话题」那句可以整个删掉，改口径就行。

### 2.3 一个实测抓出来的真缺陷（已修）

第一版我把【品牌提示词里抽的】和【设置页那排通用词】**直接拼在一起**当池子。
真机 10 条里**后 3 条**滑进了 `#男生穿搭 / #OOTD / #秋冬新款`（**你根本没要**）。

修法：`topicPool(brand, min)` —— **提示词里写够了（≥ 本次要的额外个数）就只用它写的**，
设置页的词**一个都不掺**；并把「这次要几个额外话题」提到读池子**之前**算。

现在的池子（真机实测，全部来自你提示词里的「话题列表」）：


## 3. ③ 正文：4~5 行短句（提示词 / 模板 / 判据 三处一起改）

### 3.1 规矩

- **4~5 行**、**一行一句短句（8~16 字）**、**行与行真的换行**；
- 全篇 **1~3 个 emoji，放在行尾**，不要每行都堆；
- 一行一个点：卖点（面料/工艺/版型）→ 氛围感 → 上身体验 → 搭配。

### 3.2 三处一起改（少一处就会自相矛盾）

| 位置 | 改了什么 |
| --- | --- |
| 提示词（`buildSystem`） | 正文段整段重写：4~5 行 / 一行一句 / 真的换行 / emoji 放行尾 + 给**形状示例**（并注明「只学形状，别照抄里面的单品与颜色」） |
| **本地模板**（`localFill()`） | **也改成 4 行** —— 同一套格式规则**不对模板放松**，否则「关掉模型」的产物会被自己的核对判成「没分行」 |
| 核对（`copycheck` ④） | 判据从**「字数」换成「行数 + 单行长度 + emoji」** |

### 3.3 ★ 为什么判据必须一起改（这里有个必踩的坑）

4~5 行 × 8~16 字 ⇒ 全文只有 **35~70 字**，而旧的 `BODY_MIN = 60 字` 是按「一整段」定的
⇒ **完全合规的新正文会被大面积判成「太短」**，整列变黄。
所以本轮把下限**下调到 30**，并新增：

- 行数 **4~5**，**容忍到 6**（`BODY_LINES_SOFT_MAX = 6`）；
  > ★ 为什么要有容忍值：这一列的意义是「让人一眼看出哪几条要回头看」，
  > 卡死 4~5 只会让整列变黄，而**全黄 = 没人看**。
  > 真正要抓的是**又写成一整段**（1~3 行）—— 那条**不受容忍值影响**（判据是 `<4 || >6`，1~3 行照样命中）。
- **单行 > 26 字** ⇒ 提醒（＝又写成一整段了）；
- **全篇 0 个 emoji** ⇒ 提醒；**多于 4 个** ⇒ 提醒。

## 4. ④ 重复：只看**相邻两条**，且**换 emoji 即算不同**

### 4.1 按你的口径实现

- 同一品牌下，**只要 emoji 不一样，文字完全相同也不要紧**；
- 只有**连续 2 条**（标题或正文）一字不差才提醒；
- **隔开几条之后再出现同一句**、或**换个品牌用同一句**，都不算重复。

实现放在 `copycheck.checkBatch(rows)` —— 这是**批级**判据（要能看到「上一条」，单条函数里写不了）：
只跟 `i-1` 比、**比原文（含 emoji）**、第 0 条不报。

### 4.2 ★ 两个「不让它变成假功能」的动作

1. **真接进报告**：在 `aireport.write()` 里**真调一次**，把结论并进「文案核对」列。
   只写个函数 + 给它写单测 ⇒ 报告里其实没有这条结论，用户永远看不到。
2. **行为级断言**：让假模型回**一模一样**的标题/正文，**看落盘的报告文件**里有没有那句话
   ——「函数返回了 2 条」证明不了它进了报告。
