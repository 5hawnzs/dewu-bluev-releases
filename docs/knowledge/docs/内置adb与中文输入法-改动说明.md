## 1. 做了什么

| | 以前 | 现在 |
|---|---|---|
| **模拟器驱动 adb** | 程序里没带，得用户自己去模拟器安装目录翻出 `adb.exe` 填进设置（本机实测：系统 PATH 里没有 adb、也没装 Android SDK）——**新同事的第一道墙** | **随包内置**官方 platform-tools 的 adb。设置里那一格**留空就行**，装完即用 |
| **中文输入法** | 程序只会提醒「去装一个 ADBKeyboard」，不帮装。没它中文标题/正文打不进去 | **随包内置** `ADBKeyboard.apk`。「检查能不能发布」里直接给一个 **「一键装上中文输入法」** 按钮 |
| **视频转码** | 界面写着 `ffmpeg（预留）· 待接入` | **没变，仍未接**。原因见第 3 节 |

**adb 的优先级（从高到低）**：
① 你在设置里**手填**的路径（填了、文件也在 ⇒ 就用它，程序**不会**拿内置的偷偷替掉你的配置）
② **程序内置**的那份
③ 系统 `PATH` 上的 adb（老用户既有的装法不会被断掉）

手填了一个**不存在的**路径时，会自动退回内置那份，并在检查结果里**明说**「你填的那个不存在，已自动改用程序内置的」。
检查结果的「技术详情」里会写清**现在用的是哪一个、是哪来的**。

**「一键装上中文输入法」到底做了什么**（三步缺一不可，实测过）：

```
adb install -r ADBKeyboard.apk      # 装
adb shell ime enable com.android.adbkeyboard/.AdbIME   # 启用
adb shell ime set    com.android.adbkeyboard/.AdbIME   # 设成当前输入法
```

只装不启用 ⇒ 中文广播没人接；不设成当前输入法 ⇒ 字照样进不了输入框。
★ **副作用**：设成当前输入法后，**在模拟器里手动点输入框不会弹键盘**了（ADBKeyboard 本来就是个「给脚本用的」输入法）。
所以这一步**只由你点按钮触发，程序绝不自动做**。想手动打字就换回原来的输入法。

## 3. ★ 关于视频：你说的「不是 mp4 的话，前面的步骤不是已经转过来了吗」——**没有转过**

我把全仓翻了一遍，结论是：**这个程序从头到尾没有转码能力**。

- 全仓**没有** ffmpeg，也没有任何转码相关调用。界面上那行 `ffmpeg（预留）· 待接入` 只是**占位**，从没接上。
- 素材是**原样推给设备**的。
- 合规检查对**视频**只做两件事：**读扩展名**、**读时长**（纯 JS 解析 `moov → mvhd`）。判完是这么处理的：

| 情况 | 判定 | 会自动处理吗 |
|---|---|---|
| `.mp4` 且 ≤ 600 秒 | 合格 | — |
| **不是 `.mp4`**（`.mov` / `.avi` / `.webm` / `.mkv`…） | 「**需手动转 MP4**」，状态 `manual` | ❌ **不会**。程序只提示，转码要人工做 |
| 时长读不出来 | 「人工确认」 | ❌ 不会 |
| 超过 600 秒 | 「只标红不裁剪」（裁剪会改变内容） | ❌ 不会 |

- 关键在代码里这条**不对称**：`compliance.fix()` **只处理 `todo` / `isolate` 两种状态**，
  `manual` 一律不碰。而**图片**的问题都标成 `todo`（转 JPG / 等比缩放 / 压缩）⇒ 会真的动手做；
  **视频**的问题全标成 `manual` ⇒ **只到「标记」为止**。

⇒ 所以：**「一般都是 mp4」是对的**；**「不是 mp4 的在前面的步骤已经转好了」不成立** ——
那些非 mp4 的文件，要么是**人工转好后才放进去的**，要么就是合规检查里那条「需手动转 MP4」一直挂着。

**这也是我一直没内置 ffmpeg 的原因**：现在把它内置进来，等于花 ~77 MB 买一台目前用不上的机器，
而且还带着许可风险（npm 上最省事的那条路 `ffmpeg-static` 是 **GPL-3.0**，跟本工具捆一起发有法律传染风险；
要用得换 LGPL 版，体积翻倍到 ~168 MB）。

**要往下走，你只需要回答一句：你实际遇到的是哪种情况？**
① 素材里确实有 `.mov` / 其它格式（iPhone 录的、供应商给的）；
② 有些 mp4 得物不认（编码问题）；
③ 视频超 10 分钟要截断；
④ 文件太大传得慢。
—— ①②很可能更划算的答案不是内置 ffmpeg，而是**在入口就把它拦下来、说清哪里不合规**（便宜得多、也更可控）。

## 5. 你可以怎么验收（装完新版后）

1. 打开「模拟器发布」页 → 把「adb 路径」那一格**清空** → 点「检查能不能发布」。
   预期：「技术详情」里 `adb 路径` 会显示**程序内置**那一份（形如 `...\resources\adb\adb.exe（程序内置）`），
   而不是报「没找到 adb」。
2. 看「中文输入 ADBKeyboard」那一行。如果设备没装，引导区会出现 **「一键装上中文输入法」** 按钮；
   点它 → 提示装好 → 结果行变成「**已装，且是当前输入法**」。
3. 装完之后，在模拟器里**手动**点输入框：**不会弹键盘**了 —— 这是正常的，不是坏了。
4. 想验证「没内置会怎样」：把那一格填一个不存在的路径（例如 `D:\nope\adb.exe`）→ 检查结果会
   **明说**「你填的 adb 路径不存在，已自动改用程序内置的 adb」。

## 6. 技术细节（给开发看的）

- 内置文件放 `vendor/`（**故意提交进 git**，约 9.6 MB —— 每次打包都必须有，走「构建时下载」会让没网的机器打不出包）：
  - `vendor/adb/{adb.exe,AdbWinApi.dll,AdbWinUsbApi.dll,LICENSE.txt,NOTICE.txt}`（官方 platform-tools，来源/版本/md5 见 `vendor/README.md`）
  - `vendor/adbkeyboard/ADBKeyboard.apk`
- `package.json → build.extraResources` 把它们原样搬到 `resources/adb`、`resources/adbkeyboard`。
  **不能塞进 asar**（asar 是压缩归档，里面的 `.exe` 不能执行）—— 也不在 `build.files` 里。
- `src/main/index.js` 启动时注入路径（打包后 `process.resourcesPath`，开发时仓库 `vendor/`）；
  `adb.js` 的 `resolveAdbChoice({configured, bundled, exists})` 是**纯函数**，测试直接喂输入验判断。
- `uicheck` 会核对**每个内置文件的 md5 与 `vendor/README.md` 里写的一致**，二进制和来源说明不许各说各话。
- 换 adb 版本的步骤写在 `vendor/README.md` 第 3 节。
