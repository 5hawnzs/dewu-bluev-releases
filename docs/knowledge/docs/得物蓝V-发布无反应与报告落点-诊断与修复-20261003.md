## 一、文案生成的报告跑回了「还没处理的文件夹」

### 现象
报告落在了 `E:\bluev_beta\0901_2\TW男装_AI内容报告_2026-10-03T04-01-30.xlsx`
—— 也就是**原始素材目录**（还没处理的那份）。

### 真实原因（代码级）
`src/main/jobs.js` 的 `copy.generate` 里，报告落点写的是：

```js
dir: s0.sourceDir          // ← 每次现场选的那个「源目录」
```

可做完「素材整理」之后，这一批条目其实全在带时间戳的扁平副本里：

| 工程状态里的字段 | 实际值 |
|---|---|
| `sourceDir`（原始素材，**未处理**） | `E:\bluev_beta\0901_2` |
| `flatDir`（整理后的扁平副本，**合规检查就是在它上面跑的**） | `E:\bluev_beta\flat_20261002-2329` |
| `items[0].absDir`（条目真实位置） | `E:\bluev_beta\flat_20261002-2329\3261132007+煤黑色01_1` |

于是出现了你看到的那一幕：**人在带时间戳的目录里干活，报告掉回了原始目录。**

### 修法
新增 `itemsDir()`：**落点一律按 items 实际所在的父目录算**，拿不到才退回兜底值。

```
改前：dir = sourceDir                                    → E:\bluev_beta\0901_2
改后：dir = itemsDir(items) || flatDir || sourceDir       → E:\bluev_beta\flat_20261002-2329
```

## 二、点「发布」没有任何反应

这个有两层原因，**第一层是 bug，第二层是真的没配好**。

### 第一层（bug）：程序悄悄走了「模拟通道」，根本没碰设备

`publisher.run` 第一步就是读通道：

```js
const mode = (state.publish && state.publish.mode) || 'mock';   // ← 读不到就默认 mock
```

而 `publish.mode` 是「连接模拟器」时写进去的。**导入 AI 内容报告时被整块冲掉了**：

```js
// src/main/jobs.js（改前）
publish: { rows: ..., batch, connected: false, running: false, ... }   // ← 整块替换
```

`mode` / `device` / `probe` 三个键**一起消失** ⇒ `mode` 读成 `undefined` ⇒ 默认 `mock`
⇒ 发布跑的是「演练节奏」，**一个字节都没往设备上推**。

证据（`C:\Users\Administrator\输出\得物\run-log.jsonl`，04:03:07 那次）：

```
开始发布（模拟通道）：30 条（图文 0 · 视频 30），预计 75 分钟
模拟通道不接触设备，只演练节奏/重试/回写；要真发请先「连接模拟器」并点「检查能不能发布」通过
```

而同一批的工程状态里，`publish` 的键是：
`rows / batch / connected / running / startedAt / reportFile / reportSheet / reportDir / brandId / brandName`
—— **没有 mode、没有 device**。时间线也对得上：02:47 连接过（写了 mode），之后导入报告把它冲掉了。

**更糟的是**：模拟跑完，结果被写成 `发布成功`（和真发一模一样），界面一片绿、Excel 回写也是「发布成功」。
所以你看到的不是「没反应」，而是「**界面说成功了、设备上什么都没发生**」。

### 修法（三处）
1. `report.import` 改成 `Object.assign(旧 publish, {...})`，保住 `mode/device/probe`；也不再把 `connected` 顺手重置成 false。
2. 模拟通道的结果**不再冒充真发布**：记 `模拟成功`（橙标），不写「审核中」，统计里也不算真发布。
3. 点「开始发布」时，只要当前不是真实设备通道，**先弹一句确认**（写清「不会真的发到得物」+ 怎么连设备），不再默默跑。

### 第二层（真的没配好）：UI 定位表是「没抓到」的产物

你的定位表 13 步全部标着 `unverified: true`，第 1 步是：

```
{"name":"打开发布入口","action":"tapText","value":"发布","hint":"⚠ dump 里没找到，需手动确认"}
```

这行就是「没抓到」的自白。查两份抓取产物：

| 抓取时间 | 产物 | 真相 |
|---|---|---|
| 10-02 18:27 | `ui-dump-*.xml` 里全是「游戏中心 / 浏览器 / 图库 / 设置」 | 当时停在**模拟器桌面**，压根不在得物里 |
| 10-02 23:24 | 98 个节点、**一段文字都没有** | 这是程序 `dumpsys` 备用通道的产物 —— 它**天生拿不到 text**。说明那一轮 uiautomator 也失败了 |

得物发布页首屏是**持续动画页**，`uiautomator dump` 要等 idle，所以抓不到。
**但**：把三个系统动画开关置 0 之后，我这次**一次就抓到了**（73 节点）。程序里本来就有这个「临时关动画、抓完还原」的机制 —— 之前失败是因为**抓的时候没停在发布页**。

### 顺带把真流程实测出来了（本次核心成果）

按你给的那条路，逐跳真机验证：

```
底部「我」(tab_user) → 右上角「主页」(tvGoHomePage) → 「发布新动态」(rlPublish)
```

另外一个关键点：中文走 ADBKeyboard 广播，**广播只认当前有焦点的输入框** ⇒ 填标题/正文**必须先点一下输入框**，老表少了这一步。
