## 第 ① 条：必带话题的分隔符

### 改前：根本没有分隔符，写多个会变成一个话题

实测（用你本机的真实配置跑出来的）：

```
本机 copy.requiredTopic = "#TW男装"      ← 单值
本机 copy.extraTopics   = 5

输入 "#A #B"  →  生成的话题数组 = ["#A #B", "#TW男装", "#男生穿搭", "#OOTD", "#秋冬新款"]
                 topic1 单元格    = "#A #B"        ← 整串算一个话题
输入 "#A，#B" →  topic1 单元格 = "#A，#B"          ← 顿号/逗号也没用，都不拆
```

为什么这是**真问题**而不只是不好看：得物的话题字段是「一格一个话题」，且发布时是
**输入 → 等联想 → 点选**（`uimap.js` 里那一步写明了「得物不认纯文本话题」）。
把一个不存在的整串喂进去，**联想里点不出来**，现场表现像「话题选错了」，查起来很绕。

### 现在的规则（已实现）

**分隔符**（可混用，连续写几个也只算一次）：

| 分隔符 | 例子 |
|---|---|
| 空格 / Tab / 换行 | `#TW男装 #男生穿搭` |
| 英文逗号 `,` | `#TW男装, #男生穿搭` |
| 中文逗号 `，` | `#TW男装，#男生穿搭` |
| 顿号 `、` | `#TW男装、#男生穿搭` |
| 分号 `;` `；` | `#TW男装; #男生穿搭` |
| 竖线 `\|` | `#TW男装\|#男生穿搭` |

规则细节：

- **自动补 `#`**：写 `TW男装, 男生穿搭` 也行（得物的话题联想要靠 `#关键词` 触发，少了 `#` 直接点不出来）
- **去重**：`TW男装, #男生穿搭, TW男装` → 两个
- **必带话题固定排在话题最前面**（话题1、话题2…），额外话题接在后面
- 界面上那个输入框的标签从「**话题数**」改成了「**额外话题**」，旁边写清了分隔符与上限

### 顺带修掉一个更隐蔽的问题：第 6 个话题被静默丢弃

发布单只有 **话题1~话题5 五个格子**（`sheet.js` 的 26 列里就这么定义的）。
而**你本机现在的设置正好踩在这上面**：

```
本机：必带 1 个（#TW男装） + 额外 5 个
旧版 → 凑出 6 个话题：["#TW男装","#男生穿搭","#OOTD","#秋冬新款","#质感生活","#日常搭配"]
       发布单只写前 5 个 ⇒ 第 6 个「#日常搭配」**从来没进过发布单**，而且没有任何提示
```

现在：**少给并明确告警**（不是默默丢掉）：

> 发布单只有 5 个话题列（话题1~话题5）：必带 1 个 + 额外 5 个放不下，每条只带前 5 个话题

⇒ **你如果想带满 6 个话题**，现在只能：要么把「额外话题」调成 4（回到 5 个），
要么告诉我要不要**扩到 6 列**（改 `sheet.js` 的 26 列结构 —— 会动发布单格式，得你点头我才动）。

代码位置：`src/main/services/copywriter.js`（`parseTopics` / `normTopic` / `MAX_TOPIC_COLS` / `topicCombos`）

## 第 ② 条：执行日志导出

### 改前：能导，但会**悄悄少一大截**

执行日志（`run-log.jsonl`，任务级：谁、什么时候、跑了哪个任务、哪个品牌、成没成、多久）
本来就有一个出口 —— 品牌统计页的「**导出 xlsx**」的第 4 张工作表。

但它有个没写在任何地方的硬上限。实测（写 260 条 run-log 后导出）：

```
写入 run-log 条数 = 260
stats.query 返回 logs.length = 100        ← 界面用，只取最近 100 条（这一条合理）
导出文件 = 品牌发布统计_20261002-0239.xlsx
「执行日志」工作表数据行 = 100            ← ★ 导出也只有 100 条，且界面上一句不提
```

`stats.query` 的 `logLimit` 默认 100，导出时**没有关掉**它。
后果就是：拿去做**月度对账**会少一大截，而且看起来完全正常 —— 这种「错得没声音」的账最坏。

### 现在：两个出口，都条数完整

**出口 A：品牌统计页 →「导出执行日志」（新按钮）**

一次生成两个文件（落在输出目录，和合规报告、发布统计同一个地方）：

| 文件 | 给谁 | 内容 |
|---|---|---|
| `执行日志_20261002-024329.log` | 给人看 | 文件头 6 行（导出时间 / 筛选条件 / **本次导出 N 条** / **日志文件里共 M 条** / 日志文件路径）+ 每条一行 |
| `执行日志_20261002-024329.csv` | 给 Excel | 表头：`时间,品牌,执行人,账号,任务,批次,级别,说明`，**带 BOM**（Windows 双击不乱码），逗号/引号按 CSV 规则转义 |

实测（同一批 260 条）：

```
-- 本机实测 --
log  里：# 本次导出：260 条
        # 日志文件里共：260 条（两者不一致 = 上面的筛选条件筛掉了一部分）
csv  行数 = 261（含表头），带 BOM = true
转义示例：2026-10-02 02:43:29,未标品牌,张三,zhang,模拟器发布,归属自检_批,信息,"第 260 条, 带""引号"""
xlsx 「执行日志」表数据行 = 260     ← 顺手也修掉了截断
```

**两处口径是共用的**（`stats.mapRunLog` 一个函数，屏幕与导出都走它）——
避免「屏幕上写的原因」和「导出文件里写的原因」哪天悄悄不一致。

**文件头为什么写两个条数**：只写「本次导出 3 条」的话，过几天没人说得清
「是这天真只有 3 条，还是被筛掉了」——这正是我们踩过的坑，所以两个数分开写并解释一句。

**文件名为什么带秒**：排障时会反复导，精确到分钟的话第二次会**悄悄覆盖**第一次。

**出口 B：原来那张 xlsx 的第 4 张表** 也改成不截断了（166 条 → 166 行，实测）。

另外一个既有的出口没动：模拟器发布页的「**重导出日志**」导的是
`publish-log.jsonl`（**逐条**发布结果，按批次分段的 `.log` + `.csv`）。
两个日志分工没变：`publish-log` = 逐条结果（算数量/频次），`run-log` = 任务级流水（执行日志）。

代码位置：`src/main/services/stats.js`（`exportRunLog` / `query({allLogs:true})`）、
`src/main/ipc.js`（`stats:exportLog`）、`src/renderer/app.js`（按钮 + 文案）

## 第 ③ 条：品牌统计这个界面，还有什么意义？

这条我给你一个不绕弯的答案：**它有意义，但它的意义是「这一台机器的账」，不是「全公司的账」。**

### 它的数据从哪来（就两个文件）

```
本机实测：
  输出目录 = D:/卡宾/输出
  publish-log.jsonl   存在, 5012 字节, 21 行      ← 「条数 / 成功 / 失败 / 频次」按它算
  run-log.jsonl       存在, 17228 字节, 63 行     ← 「执行日志」按它算
```

两个文件都是**本机这个输出目录**里的。程序里**没有任何**拉取/接收其他电脑记录的机制
（我把 `publish-log` / `run-log` 的全仓引用都过了一遍：只有本机读、本机写、本机导）。

所以：
- **只在单机上发** ⇒ 品牌统计完全准确，还能回答「哪个品牌最近没在发」「谁在发」「哪天断过」
- **多台电脑各用各的本地目录** ⇒ 管理员的这台就只看得见自己这台发出去的。**这就是你现在的情况**

### 想让管理员收齐所有电脑：把各台的「输出目录」指到同一个位置

这是**现有功能就能做到**的，不需要开发：

1. 找一台常开的机器（或 NAS）建共享文件夹，例如 `\\192.168.1.10\得物蓝V输出`
2. **每一台**机器：设置 → 路径 → 输出目录 → 改成那个共享路径
3. 各台照常发布；两个 jsonl 是**同一个文件**、各自追加写 ⇒ 品牌统计天然汇总
   （程序支持 UNC 路径：`winpath.toLong()` 会把 `\\主机\共享` 转成 `\\?\UNC\主机\共享`）

映射盘（`Z:\`）用起来更顺，但**只在登录会话里有效**；无人值守/服务方式跑的时候会掉，
UNC 更稳。网盘同步目录（如同步盘）也能用，但同步冲突的风险由你承担，不建议。

### ★ 但有一个必须知道的坑：共享盘掉了，统计会**悄悄少数据**

`publish-log` / `run-log` 都是「**追加写、写失败不报错**」的：

```js
// sheet.appendLog（runlog.append 同款）
} catch (e) { /* 写日志失败不阻断发布 */ }
```

这个取舍本身是对的（不能因为日志写不进去就把发布搞挂）。可一旦输出目录是共享盘、
盘掉线 / 没权限 / 被安全软件拦，结果就是：**发布照常成功，统计悄悄少数据，界面一切正常**。
——那正是「界面骗人」的一种，所以我加了一颗按钮让你能**当场问一句**：

**品牌统计页 →「检测输出目录」**，实测三项全查、只报事实：

```
输出目录可建可删文件                ✓ / ✗（共享盘掉线、无写权限在这里现形）
发布日志 publish-log.jsonl 可追加打开  ✓ / ✗
执行日志 run-log.jsonl     可追加打开  ✓ / ✗
```

- 检测方式：① 在目录里建一个临时文件再删掉 ② 用**追加方式打开**那两个 jsonl
  （与真写日志同一条打开路径），**一个字节都不写** ⇒ 不污染台账（这条有断言钉住）
- 不通过时把**原始错误码与原文**一起显示（`ENOTDIR ...` / `EPERM ...`），不翻译成模糊话
- 只查配置里那个输出目录，**不收前端传的路径**（免得变成任意路径探测器）

另外，品牌统计页现在**明确写着**这句话，不用再猜：

> ⚠️ 这一页统计的是**本机这个输出目录**里的记录：别的电脑各写各的目录，这里看不到。
> 要让管理员的统计收齐所有电脑，就得把各台的「输出目录」都指到**同一个共享位置**；
> 但日志是「写失败也不报错」的，共享盘一掉就会悄悄少数据 —— 所以改完先点「检测输出目录」确认写得进去。

### 「执行日志」区的显示也改准了

屏幕上从来只列最近 100 条（一屏放不下），但标题以前写「执行日志（最近 100 条）」，
会被当成「一共就 100 条」。现在拆成两个数：

> 执行日志（**显示最近 100 条 / 共 166 条**）+ 一句「导出执行日志会把 166 条**全部**导出」
