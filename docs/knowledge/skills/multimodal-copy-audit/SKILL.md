# 让 AI 文案真的「看图写」，并产出可核对的一致性报告

用户对「AI 生成的文案」最常见的两条抱怨，根因往往**都不在提示词**：

> 「一看就是 ai 做的，不真实」 —— 多半是**图根本没发出去**，或者模型压根没被调用。
> 「怎么核对文案、货号、颜色对不对」 —— 一次几十条，没人能逐条盯，需要**机器先筛一遍**。

本文是这两件事的做法与证据口径。实测环境：Electron + Node 22（`fetch`/undici），
案例仓库 `dewu-bluev-publisher`（得物蓝V 发布工具）。

---

## 0. 第一原则：先证明「模型真的被调用了」，再谈文案质量

一次真实投诉排查（2026-10-02）里，**三个原因叠加**，用户一条都没看到：

| 因 | 表现 | 怎么发现的 |
| - | ---- | ---------- |
| 配置里接口地址是空串，而代码 `if (!endpoint) throw` | 每次生成都抛异常 → 被 `catch` → **静默回退本地模板** → 界面显示「已生成」 | 直接读用户机器上的 `config.json` |
| 只把「货号 + 颜色 + 话题」当文字发给模型，**一张图都没发** | 标题只能是「颜色 + 固定句式」 | 读 `callLLM` 的 `messages` 构造 |
| 用户填的模型名不是接口认的 id | `POST /v1/chat/completions` **HTTP 400** | 真调一次接口，把错误原文读出来 |

⇒ **别从「提示词写得不好」开始查。先查「这次到底联没联网、发没发图、模型名认不认」。**

## 1. 「图真的发出去了吗」——用假模型服务当探针（行为级断言）

**不要**用「源码里有没有 `image_url` 这几个字」来断言。**起一个假 HTTP 服务收请求**，
把收到的 base64 解开、**真的解码成像素**：

```js
const seen = [];
const srv = http.createServer((req, res) => {
  let raw = ''; req.on('data', c => { raw += c; });
  req.on('end', () => {
    if (/\/models$/.test(req.url)) return send(200, { object:'list', data:[
      { id:'deepseek-flash', name:'DeepSeek-V4.1-Flash', input_modalities:['text','image'] },
      { id:'deepseek-v4-pro', name:'DeepSeek-V4-Pro',    input_modalities:['text'] } ]});
    const body = JSON.parse(raw || '{}');
    const content = body?.messages?.[1]?.content;
    const images = Array.isArray(content) ? content.filter(p => p?.type === 'image_url') : [];
    seen.push({ model: body.model, images, hasImage: images.length > 0 });
    send(200, { choices:[{ message:{ content: JSON.stringify(reply) } }] });
  });
});
// 断言（这才是「图发出去了」的证据）：
const b64 = seen[0].images[0].image_url.url.split(',')[1];
const px  = jpeg.decode(Buffer.from(b64, 'base64'));   // 真解出像素
assert(px.width * px.height > 0);
```

再补三条：发的是配置指定的张数；图已缩到上限内；是 **data URL 内联**（不是本地路径、不是外链）。
外加**负向对照**：把图片从请求里摘掉，这条断言必须**变红**（证明它不是空转）。

> 同理，「关掉模型时不联网」要断言**一次请求都没发**（`seen.length === 0`），而不是只看返回值。

## 2. 「静默降级」是最坏的失败模式 —— 要让它变成硬失败

**坏味道**：`catch` 之后「顶一个兜底产物」，界面照旧显示成功。
用户拿到的是一堆模板货，却以为那是模型写的 —— 事后几乎无法察觉。

**改法（三档，从硬到软）**：
1. **开模型时先 preflight**：没 key / 地址空 / **网络层不通**（`fetch failed`、DNS、超时）
   ⇒ **立刻抛错，一条都不发**（别让每条素材各撞一次墙）。
   - ★ 判「网络层不通」的写法：错误里没有 `返回 \d{3}` 就是没拿到 HTTP 响应
     ⇒ `if (!/返回 \d{3}/.test(e.message)) why = '连不上接口'`。
   - ★ 全失败时，错误信息里要带上**第一条的原始错误**，否则「一条都没生成出来」等于没说。
2. **单条失败**：如实记 `status:'未生成' + 原因`，**不顶上兜底**；最后汇总告警。
3. **明确关掉模型时**：产物里**逐行**标出 `genSource: '本地模板'`，界面上也要说清。

> 「兜底」不是不能有 —— 是**不能让它在用户不知情时发生**。

## 3. 配置的两条通用规矩

### 3.1 「留空 = 跟随内置」，且**读时兜底、绝不写回**

别把内置地址「补进」用户的 `config.json` —— 那叫**固化**，以后换服务商顶不动。

```js
const own = String(c.endpoint || '').trim();
return { endpoint: own || llmdefaults.endpoint,
         endpointSource: own ? '本机配置' : '跟随内置' };   // 界面上把来源说出来
```
内置文件里**只放地址与模型 id，绝不放任何凭据**。

### 3.2 模型名要**按 `/models` 清单解析**，不要原样发

显示名（`deepseek v4.1 flash`）和接口认的 id（`deepseek-flash`）常常不一样，原样发就是 400。
三段解析：**id 精确匹配 → 显示名归一化（去空格/点/横线/下划线）→ 落到内置兜底 id**；
并从 `input_modalities` **读回「这个模型收不收图」**（收不收图要如实告诉用户）。

### 3.3 布尔值要按**真值**判

界面上存下来的常是**字符串** `'false'`，而 `'false' !== false` 是 `true` ⇒「不送图」会被读成「送图」。

```js
const bool = v => !(v === false || v === 'false' || v === 0 || v === '0' || v === '');
```

## 4. 一致性报告：机器先筛一遍，人只看被标出来的那些

### 4.1 列名与「上游那份」逐字对齐 ⇒ 反向闭环

用户手里已有一份人工维护的报告模板时，**列名一个都别改**（连顺序都对齐）。
好处：报告写完能被自己的导入器**直接吃回去**当发布单，`生成 → 核对/改 → 导入 → 发布` 无需转格式。

★★ **写完立刻用下游那个读取器自己读一遍**（自证）—— 列名写歪一个字会被当场发现，
而不是等到用户导入时才报「表头缺列」。

```js
async function verifyReimport(file) {
  const rep = await report.readReport(file);          // 下游真读取器
  return { ok: !!rep.rows.length, rows: rep.rows.length, sheet: rep.sheetName };
}
```
自己的附加列（生成来源 / 核对结论 / …）放在**后面**，读取器按列名取值、不认的直接忽略。
另开一张**说明表**时，表名别含「报告」二字（很多读取器靠 `/报告/` 找表）。

### 4.2 结论分三档，且**拿不准的写「需人工确认」**

| 档 | 含义 | 例子 |
| -- | ---- | ---- |
| `bad` | 客观错，没什么可争的 | 货号混进了标题正文；用了模板套话 |
| `warn` | 不一致 / 要人看一眼 | 颜色对不上、超字数、没 emoji |
| `ok` | 一致 | —— |

**★ 这是提示，不是判决。** 色名不在词表里、图取不到主色 ⇒ 一律写「需人工确认」，**绝不替人下结论**。

### 4.3 ★★ 别让它误杀正常内容（否则那一列会被用户学会无视）

实测踩过的三类误杀：

1. **颜色核对按「正文全扫」⇒ 误杀**。正文里出现别的颜色是**正常的**
   （「黑色小熊刺绣」「搭一条浅蓝牛仔裤」—— 刺绣和裤子本来就不是这件衣服的颜色）。
   ⇒ **只扫标题**（标题才是「这件衣服什么颜色」的声明），且**只要有一个颜色对得上就不报**。
2. **色名只认词表**。电商叫法（「冠军白」「樱花粉」）不在词表里 ⇒ 全推给人工，那一列就废了。
   ⇒ 先精确匹配，再退一步认它**含哪个基础色词**（最长优先）→ 落到色系。
3. **长词被短词抢先**。「勃艮第红」会先被「红」命中 ⇒ 按**长度降序**匹配。

### 4.4 报告要落成「带时间戳、绝不覆盖」的文件

```js
fileName = `${safeBrand}_AI内容报告_${yyyy-mm-ddTHH-MM-ss}.xlsx`;   // 秒级
// 同一秒撞名 auto 加 -2（报告是事后核对的唯一凭据，覆盖了就没了）
```
落点优先用户**当次操作的那个业务文件夹**（用户原话「你应该在该文件夹生成」）；
写不进去才退到输出目录，并且**要用告警把「换地方了」说出来**。

## 5. 实测挖出来的 11 个坑（都很隐蔽）

### 5.1 ★★ 模型会把换行写成**字面的** `\n`（两个字符）

真机 3 条里就有 1 条中招（另外两条是真换行）—— 这种串发到平台上是**死文本**。
⇒ 统一归一，且**不许动别的字符**：

```js
function unescapeNewlines(s) {
  return String(s == null ? '' : s)
    .replace(/\\r\\n|\\n|\\r/g, '\n')   // 字面转义 → 真换行
    .replace(/\r\n?/g, '\n');           // 真 CRLF → LF
}
```
断言要**行为级**：让假模型真回一段带 `\n` 的正文，看**落盘产物**里的到底是什么
（不是只测那个函数）。

### 5.2 ★ 宽容解析器别把**中文标点**改掉

「JSON 解析失败就退到宽容替换」的写法，如果**无条件**跑
`s.replace(/，/g, ',').replace(/：/g, ':')`，模型写的中文标点会全变半角。

```js
function extractJson(s) {
  try { return JSON.parse(s); } catch (e) { /* 只有这里才允许宽容 */ }
  ... // 去 markdown 围栏、去尾逗号、全角引号当分隔符
}
```
**先原样、失败才宽容**。

### 5.3 ★ 图片主色会被**浅色背景**压过

「实拍图主色」常用于反查颜色填得对不对。但整张图取色时，
浅色背景（百叶窗、白墙）面积更大 ⇒ 主体色被压过。
实测：「雾霾蓝」羽绒服测出「银」，报「需人工确认」。

⇒ **这是 `warn` 不是判决**：不拦流程、不改产物，只提醒人核一眼。
★ 改法至少两种（只取中心区域 / 中性色不参与判定），**没有数据说哪种更好就别改**，
把它写进文档当已知行为，而不是当 bug 反复重修。

### 5.4 ★ `stripTrailingTopics` 的 token 必须「遇标点就停」

平台话题是**独立格子**，正文尾巴上重复一串 `#话题` 是点不动的死文本，要去掉。
但正则写成「`#` 后面直到空白」会把正常句子一起删掉：

```js
// ❌ 会把「#小故事，讲给你听。」整段当话题删掉
const TOKEN = '#\\S+';
// ✅ 一个话题 = # + 汉字/字母/数字，遇到标点就停
const TOKEN = '#[^\\s#，。！？、：；,.;:!?()（）\\[\\]【】"\'“”‘’…—\\-]+';
```
起点要认三种：**行首 / 空白 / 句末标点**（实测模型就写成「…套上刚好。#男装」，连空格都没有）。

### 5.5 ★ 假 HTTP 服务不关 ⇒ 测试进程**永不退出**

断言中途抛异常时，服务器还占着事件循环 ⇒ 上层（定点破坏脚本 / CI）会一直等。
**实测挂死 18 分钟。**

```js
let srvRef = null;
// ...
})().catch(e => {
  try { if (srvRef) srvRef.close(); } catch (x) {}
  process.exit(1);          // ★ 硬退出，别指望事件循环自己空掉
});
```
上层再加第二道保险：`subprocess.run(..., timeout=240)`。

### 5.6 ★★ 报告里空着的「货号 / 颜色」怎么补 —— 来源必须**分级**，且只补空格

用户的实际流程是「先生成 AI 报告（此时货号/颜色还可能空着）→ 再按**素材文件夹名**补上」。
补的时候有三条不许越过的线（2026-10-03 实测踩全了）：

**① 来源要分级，只有一个来源可信。** 解析文件夹名时必须**同时**返回一个「可信度」标记，
而不是只返回解析结果 —— 否则「随手命名的文件夹」会被当成真货号：

| 标记 | 长这样 | 能否拿去填 |
| ---- | ------ | ---------- |
| `'plus'` | `26FW-YB160+冠军白` | ★ **只有它** |
| `'split'` | 老式三层 `货号\颜色\1` | 否 |
| `'guess'` | `品牌甲\20260904\IMG_5253\1` → 会被读成 货号=20260904 / 颜色=IMG_5253 | 否 |
| `'name'` | 单层名字 | 否 |

★ **最后一档故意不「猜」也不摘后缀**：`IMG_5253` 若被摘成 `IMG` 反而**更像真的货号**。

**② 工具自己产出的扁平副本，后缀会被当成颜色。** 实测
`…\flat_20261001-0132\26FW-YB160+冠军白_1` ⇒ 解析出 `color = "冠军白_1"`
（同一分钟重跑还会接出 `-2`）。⇒ 摘后缀要**只摘「分隔符 + 纯数字」结尾**、最多两层：

```js
// 先摘 -2（去重），再摘 _1（序号）
const m = head.match(/^(.*?)[_-](\d+)$/);
```

这样 `冠军白` / `黑色条纹` 不误伤，`米白2`（数字是颜色名的一部分）也**不摘**。

**③ 只填空格、不覆盖；对不上就只点名。** 报告是运营的账本：

- 已经填了的值**一个都不动**；
- 报告里的货号与文件夹名解析出的货号**是两个不同货号**时，**两边都不改**，
  只记一条「第 X 行：报告写 A、文件夹是 B，对不上」的告警；
- 补出来的值要**写回 xlsx**（不写回 = 用户下次打开还是空的），
  且写回前**每一格再判一次是否仍为空**（防并发写坏）；文件被 WPS 占用要**如实报「没写回」**，
  不能假装成功（本次发布仍用补出来的值，不影响发布）。

### 5.7 ★★ 标题写成了「商品描述」——**根因几乎总在提示词，不在模型**

实测（2026-10-03）：用户拿真机生成的标题来投诉 ——「你这个标题就是纯描述产品是什么，
我要的是产品+热门词：`羽绒服+简约百搭`、`羽绒服+韩系氛围感`、`蓝调穿搭+羽绒服`、`冬日神器+羽绒服`」。
模型当时产出的是 `蓝灰横向绗缝立领羽绒，左胸刺绣🐻`。

查下来模型**没有任何过错**，是提示词把它钉死的：

| 因 | 说明 |
| -- | ---- |
| ① 我们把「看图」直接写成了「描述」 | 提示词原话「标题只能来自你在图里真实看到的东西：**品类 + 款式特征 + 颜色 + 风格词**」⇒ 模型照着串，出来的必然是商品描述 |
| ② 上游提示词引用了清单，**但清单是空的** | 品牌提示词里写着「格式参考以下 **10 种多样化格式**创作：」——**冒号后面什么都没有**（那段原文是张图，转成纯文本时丢了）。模型既没有可挑的词、也没有可套的形状 |

**修法（三条，缺一不可）**：

1. **把「看图」和「写什么」拆开**：看图只用来**认准「这是哪件单品、什么颜色」**（事实锚点），
   标题的形状另说 —— 写成 `单品词 + 热词` 的词包。
2. **把清单补成内置的**：上游引用了外部清单就必须**在代码里兜一份**（`hotwords.js` 的 7 类词库 + 10 种格式），
   否则「引用了一个不存在的清单」这种缺陷**在源码里看不出来**（提示词里明明写着「参考 10 种格式」）。
3. **「用哪一种」交给代码轮换**，并**随 user 消息发过去** —— 只写在 system 里，模型会整批用同一个形状。

**三个容易踩的坑**：

- ★★ **格式示例里不许出现「写死的具体值」**。实测：T03 的示例我写的是 `羽绒服+灰色慵懒风`，
  真机跑一条**酒红**的货，模型把示例里的**「灰」照抄**进标题 ⇒ `羽绒服+灰调高级感`（错的颜色）。
  改成占位符 `{色}` 并在提示词里写明「示例里的**颜色也要换成**本行的颜色」才对。
  ⇒ 规则：**示例只提供形状，凡是可以从输入推导出来的字段（颜色、品类、性别…）一律用占位符**。
- ★★ **「像不像 AI」这类判据只能用客观可数的东西**。想查「标题有没有热词」必然误杀 ——
  模型会自己造词（「松弛感」「少年感」）。改成**数款式特征词**（绗缝/立领/刺绣/拉链/口袋/圆领…）：
  堆到 3 个以上就是商品描述。被打回的原句正好命中 5 个，可复算。
- ★★ **收紧一条判据的同时要问「会不会把好结果标黄」**。本轮同步**删掉**了
  「标题里没提到颜色 ⇒ 告警」—— 新写法下 `羽绒服+简约百搭` 这种好标题本来就不带颜色，
  留着它会把一整列标黄，而那一列的意义正是「一眼看出哪几条要回头看」，全黄 = 没人看。
  同时把「颜色声明」收紧成**只有颜色词紧挨着单品词才算**（「燕麦色圆领毛衣」算、「蓝调穿搭」不算），
  既保住了「写错颜色」的告警，又不会把氛围词当成颜色声明。

### 5.8 ★★ 「产品词 + 热门词」里的 `+` 是**示意**，不是标题的字 —— 词包直贴会出病句

**紧接着 5.7 的下一轮**（同一天，用户第二次打回）：

> 「我的 **+ 号是为了让你知道什么类型和什么类型合并，不是让你直接加进标题里**，
>   而且目前你的标题有明显的语病，如你生成的『少年感灰针织毛衣』，
>   如果能变成『**少年感灰针织毛衣太帅了**』+ emoji；
>   或者你上次的『军绿调穿搭夹克』，如果能变成『**军绿调穿搭夹克 松弛感拉满**』」

⇒ 两条独立缺陷，都别漏：

| 缺陷 | 表现 | 修法 |
| ---- | ---- | ---- |
| ① 把用户样例里的 `+` 当成了**字面量** | 我照着写「`单品词 + 热词` 的词包」，`sample` 里也带 `+`，模型**照抄进标题** | 示例里**一个 `+` 都不留**；提示词明写「`+` 只是示意，标题里一个字都不许出现」 |
| ② **词包直贴 = 标签串** | `少年感` 直接贴 `灰针织毛衣`，**没有收尾** ⇒ 用户判为「有语病」 | 把「词包公式」改成「**句式骨架**」：每条骨架**自带连接字或收尾** |

**核心招式 —— 句式骨架（结构上防病句）**：不要给模型「A + B」的填空式，要给「一句念得通的话」的骨架。
例：`{人群词}{单品}{收尾}` → `少年感灰针织毛衣太帅了`；`{单品} {氛围短语}` → `军绿调穿搭夹克 松弛感拉满`；
`{风格词}的{单品}` → `简约百搭的羽绒服`；`{场景}就穿{单品}` → `通勤就穿军绿夹克`。
这样**只要模型照着骨架填，就产不出标签串** —— 比事后校验可靠得多。

配套要做的三件事：

- **词库补一个「收尾」组**（`太帅了 / 闭眼入 / 谁穿谁帅 / 真的绝了 / 不稳错 / 很能打 / 质感在线…`）——
  用户要的「太帅了」本来就该是词库里的词，之前 7 类里没有这一类。
- **判据加一条「拼接符号」**（`+ ＋ ﹢ & | ｜ · •`）：客观、可复算，**没有误杀空间**。
- **判据再加一条「标签串」**（启发式，宁可不报也不误杀）：① 以热词开头；② 以单品词结尾；
  ③ 全文无连接字/标点/空格，且长度 ≥ 6 字 ⇒ 三条**同时**成立才报。
  `LINKERS` 表**故意不收「搭」**（「简约百搭」「穿搭」里都有它，收了会大量漏判）。
  **必须测反向对照**：用户给的两个正例（`…太帅了`、`… 松弛感拉满`）**不许**被点名 ——
  只测「病句被报」= 只验负向 = 假通过。
  **已知过报（属预期，要在交付里说清）**：`简约百搭羽绒服` 这种名词短语也会被提醒补收尾 —— 是提醒不是判决。

**顺带挖出来的一个潜伏 bug（不是这一轮引入的）**：`hasEmoji` 用**带 `g`** 的正则做 `.test()`，
而带 `g` 的 `.test()` **会推进 `lastIndex`** ⇒ 连判两次一真一假。
实测：10 条真机标题全带 emoji，连着判一遍报出「4 条没有 emoji」。
它当时**恰好没露头**（`check()` 里 `hasEmoji` 前面刚调过 `replace(带 g 的正则)`，会把 `lastIndex` 归零）——
**「恰好被上一句重置了」= 定时炸弹**。修法见 `win-sandbox-scripting` §17.5。

### 5.9 ★★ 「正文要写成 4~5 行」这类**格式要求**，判据该数「行数」而不是「字数」（2026-10-03）

用户给的是「4-5 行、每行一句、少量 emoji」这种**形状**要求。把它落成判据时有三个连续的坑：

1. **度量口径要跟着格式一起换**。旧的 `BODY_MIN = 60 字` 是按「一整段」定的；
   4~5 行 × 每行 8~16 字 ⇒ 全文只有 **35~70 字**，那条下限会把**完全合规**的新正文全判成「太短」，
   整列变黄。⇒ **改了格式，就要同步检查旧的「字数类」判据还成不成立**（本轮把它下调到 30）。
2. **容忍值比死卡重要**。判据是「4~5 行」时，模型写 6 行该不该报？
   这一列的意义是「让人一眼看出哪几条要回头看」，卡死只会**全黄**，而**全黄 = 没人看**。
   ⇒ 做成「要求 4~5 行、**容忍到 6**」，真正要抓的是**又写成一整段**（1~3 行）——
   判据写成 `行数 < 4 || 行数 > 6`，所以 1~3 行**照样命中**，容忍值不会把主目标也放过。
3. **别只对模型侧生效**。产品里通常还有一条「本地模板（离线）」兜底路径。
   只把提示词改成 4~5 行、模板没改 ⇒ **关掉模型时**产出的东西会被自己的核对判成「没分行」（自相矛盾）。
   ⇒ 改格式时**把模板一起改**，并给模板单独钉一条断言（本轮：`localFill()` 也是 4 行）。

另外两个小口径：**单行超长**（本轮 > 26 字）＝「又写成一整段了」，比总字数更能说明问题；
**emoji 数量**要「0 个 ⇒ 提醒、> 4 个 ⇒ 提醒」，别只判有没有。
数 emoji 记得**另起一份不带 `g` 的正则**（带 `g` 的 `.test()` 会推进 `lastIndex`，见 `win-sandbox-scripting` §17.5）。

### 5.10 ★★ 「批级」判据（重复 / 分布）不能只做成工具函数 —— 必须**真接进报告**，且要有**行为级断言**

用户放宽重复口径后要判的是「**相邻两条**是否一字不差」：
这需要看到「上一条」，所以**单条核对函数里根本写不了**，得另开一个 `checkBatch(rows)`。

两个必须做的动作：

- **真接进产物**：在写报告的入口（本轮 `aireport.write()`）里**真调一次**，把结论并进「文案核对」列。
  只写个 `checkBatch()` 并给它写单测 ⇒ 报告里其实**没有这条结论**，用户永远看不到 ⇒ **假通过**。
- **行为级断言**：让假模型回**一模一样**的标题 / 正文，然后**看落盘的报告文件**里有没有那句话。
  （只断言「`checkBatch()` 返回了 2 条」是不够的 —— 那证明不了它进了报告。）

★ 判「与上一条一致」要**比原文（含 emoji）**。用户的口径是「**换一个 emoji 就算不同**」，
所以**别顺手归一化掉 emoji** —— 归一化等于把放宽的口径又改回严的。

### 5.11 ★★ 「采样行数 < 池子长度」时，**滑动窗口会掩盖池子被污染**

本轮的坑：话题池本应只用「品牌提示词里写的 `#话题`」，但第一版把「提示词抽的」和「设置页通用词」**拼在了一起**。

如果断言只取 3 行（池子有 10 个词），`pick(arr, k, start)` 永远从开头往后取、**绕不回开头**，
混进来的尾部的词**永远不会被采样到** ⇒ 断言全绿、真机上是 10 条里**后 3 条**滑进了没要的词。
⇒ **断言样本数必须多过池子能给的个数**（本轮取 **8 行 > 7 个**），让窗口被迫绕回开头；
再补一条「设置页那几个词一个都不许出现」的点名断言。

★ 同类的还有「**优先级**」型需求（提示词写的优先、不够才补本地）：断言要**同时**验
「提示词里的都在」（顺序对）与「本地池的词只在不够时才出现」，只验一半会漏掉整条优先级逻辑。
