# 从源码生成「功能全景」可视化文档

## 何时用

- 「给这个项目做个持续更新的功能可视化文档」「要看起来高级一点」
- 需要一个**能对外展示、且改完代码重跑一次就自动跟上**的总览页
- 有人反复问「这项目到底有哪些功能 / 现在什么版本 / 哪些操作要管理员权限」

**不要**用它代替 README：README 是给改代码的人看的，这个页面是给**看结果的人**看的（老板、测试、客户、新同事）。

## 第一原则：两层数据，绝不混

| 层 | 内容 | 维护方式 |
|---|---|---|
| **自动读** | 版本号、页签/路由、IPC/接口通道数、源码文件数行数、测试套件清单、git 版本线、内置二进制体积 | **一律不许手写**，每次生成时重读 |
| **人工写** | 业务流程分几步、每步的关键约束、红线规则、渠道对照表 | 写在生成器顶部的常量里，随文档一起进版本库 |

**判据**：凡是「源码里已经有一份」的数字，出现在生成器里就是 bug。
反过来，「这功能为什么这么设计」这种源码里没有的，写死是合理的。

产出两份：`index.html`（单文件、离线可看、可直接发人）+ `data.json`（机器可读快照，方便别人对账）。
再加一个 `--snapshot <测试输出.txt>` 开关：复用已实测的测试数字，**不重跑**（重跑要几分钟且会污染环境）。

## ★★★ 最值钱的教训：权威事实别从「人写的说明」里猜

**症状**：版本线显示 12 个版本，看起来很正常，编号也连续。**实际漏了 5 个。**

原先按提交说明的「开头形状」打分（以 `发 vX.Y.Z` / `release` / `chore(发版)` 开头才算发布）。
实测（2026-10-05，17 个版本的真实历史）：

| 版本 | 为什么被漏/错 |
|---|---|
| `1.0.12` | 提交说明是 `fix(发布): 中文/含空格文案改走 B64…` —— **通篇没版本号** |
| `1.0.2` | 版本号写在**句尾括号**里：`…（v1.0.2）` |
| `1.0.0` / `1.0.1-beta.1` / `-beta.2` | 说明里**根本没有版本号** |
| `v1.0.4` | **挂错提交**：真身是 `86d095d "云端协作（阶段1）…"`，而标题写着「发 v1.0.4」的 `94ed453` 其实没动版本号 |
| （反向）| `docs: 同步 v1.0.2 口径…` 这种**补档**会被当成「发布」 |

⇒ **「提交说明里出现过版本号」既不充分也不必要。** 一份能自证的数字被换成了猜测，而它**表面完全正常**，
只有拿真实历史逐条对账才看得出来 —— 这类错误最危险。

**正确做法：读产物自身。**

```bash
# 谁把版本号改成它，那一次提交就是该版本的落地点
git log -p --format=$'\x01%h\t%ad\t%s' --date=short -- package.json
# 然后逐行取 hunk 里的新值：
#   /^\+\s*"version":\s*"([^"]+)"/         (JSON)
#   /^\+version\s*=\s*["']([^"']+)["']/    (pyproject / setup.cfg)
#   /^\+\s*<version>([^<]+)<\/version>/    (pom.xml)
```
路径按仓库改（`package.json` / `pyproject.toml` / `Cargo.toml` / `pom.xml` / `build.gradle` / `VERSION`）。
用 `\x01` 当提交分隔符（`%s` 里可能带 `|` 和 tab，用 `|` 分列会串行）。

**推广到一切事实**：能读**产物/配置文件/接口定义**的，就不要读**人写的散文**（提交说明、注释、README）。
散文是给人看的，不保证一致。

**排序用真 semver 比较**：`split('.').map(Number)` 在 `1.0.1-beta.2` 上得到 `NaN`，比较直接失效。
要：数字段逐位比 → 无 prerelease > 有 prerelease → prerelease 字典序。

**读不到时兜底要"标明来源"，不许假装准**：浅克隆等情况读不到 diff，退回启发式，
但要把 `timelineSrc: 'subject-heuristic'` 写进 `data.json`，并在页面上明写「⚠ 本次退回启发式，可能不准」。

## ★ 自指陷阱（任何"描述自己的文档"都躲不掉）

1. **`git status` 会把刚生成的产物算成"已修改"**
   ⇒ 页面永远显示「工作区有 1 个未提交改动」，而那 1 个就是它自己。纯噪声。
   **修**：算 dirty 时过滤掉输出目录（`filter(l => !l.includes('docs/visual/'))`），
   过滤掉的条数单独说明，别默默丢掉。

2. **文档显示的 `HEAD` 永远比实际提交早一代**（提交文档本身会改哈希），无限回归 ⇒ **无解**。
   **修**：只能标明「**生成时**：main @ abc1234」，别让读者当实时值。
   同理，数字读的是**工作树**，若另有会话/同事在同时改代码，行数会漂 ⇒ 页面必须带 `generatedAt`。

## ★ 正则「前瞻吃掉下一条」导致计数偏少

```js
// 错：[\s\S]{0,40} 会跨过逗号吃到**下一条**记录，导致某些条目被吞
/ipcMain\.(handle|on)\(\s*'([^']+)'\s*,\s*([\s\S]{0,40})/g     // 实测 51 条
// 对：真值 53 条
```
**校验法（必做）**：用一条**更简单**的正则（只匹配到通道名就停）另跑一遍，两套结果必须**等长**；
不等就 diff 出差集，看是谁被吃了。**别只跑一套正则就相信数字。**

同类坑：`[\s\S]{0,40}` / `.*?` / 非贪婪跨行匹配，在"多条记录挤在一行/相邻"时都会过界。

## ★ 排版：先算容器宽度，再定栅格

- 容器 `max-width:1240px` + 左右 padding 30px ⇒ 内容宽 **1180px**。
- KPI 用 `repeat(auto-fit, minmax(Xpx, 1fr))` 时，能放几列 =
  `floor((1180 + gap) / (X + gap))`。
  **`190px` ⇒ 只能放 5 列，6 张卡会单独换行掉一颗**（很显眼地难看）。
  改成 `172px` 才够 6 列。（`floor((1180+12)/(172+12)) = 6`）
- 定宽列（如版本号列）要按**最长可能值**定宽：`96px` 会把 `v1.0.1-beta.2` 从词中间折断 ⇒ `124px`。
- 暗色主题：`--bg` 深、`.kpi` 用 `linear-gradient(160deg, panel2, panel)` 加边框，
  比纯色卡显"高级"；强调色只用在「当前/管理员/红线」三种徽章上。

## 验收（别只看源码觉得没问题）

```bash
TMP=/c/Users/Administrator/AppData/Local/Temp/fmcheck; mkdir -p "$TMP"
cp out/index.html "$TMP/fm.html"
# 1) 区块齐不齐 + JS 有没有报错（stderr 必须 0 字节）
"/c/Program Files/Google/Chrome/Application/chrome.exe" --headless=new --disable-gpu --no-sandbox \
  --user-data-dir="$TMP/chrome" --virtual-time-budget=6000 --window-size=1440,1000 \
  --dump-dom "file:///$TMP/fm.html" > "$TMP/dom.html" 2>"$TMP/err.txt"
wc -c < "$TMP/err.txt"      # 必须 0
for s in flow pages arch ipc pub qa redline tl; do
  printf "%s=%s " "$s" "$(grep -c "id=\"$s\"" "$TMP/dom.html")"; done
```
- **`--dump-dom` 要传 `file:///` 的 Windows 路径**（Git Bash 的 `/c/...` 形式 Chrome 不认）。
- 想量整页高度：往 `</body>` 前注入
  `document.documentElement.setAttribute('data-page-h', String(document.documentElement.scrollHeight))`，
  再 `grep -o 'data-page-h="[0-9]*"'`。
- **整页长图**：headless **不能滚动**。给 `body` 加负 `margin-top:-Npx !important` 生成三份副本，
  各截 `--window-size=1440,2600`，拼起来看。（`--screenshot` 只截视口。）

## 提交与并发

- 生成器与产物**一起进版本库**（否则别人无法更新）。提交时**逐路径 add**（`git add docs/visual`），
  **不要 `git add -A`** —— 同一工作区可能另有会话在手改源码，`-A` 会把别人的半成品带进去。
- 若仓库有「打包只收 `src/**`」之类的白名单，文档目录天然进不了包，不会被污染交付。

## 检查清单

- [ ] 每个数字都能在源码里指出来（版本号 / 页签 / 通道 / 行数 / 套件 / 体积）
- [ ] 版本线来自**产物自身**（`package.json` 等），不是提交说明；读不到时有 `timelineSrc` 标注
- [ ] `dirty` 已排除输出目录自身
- [ ] 页面标了「生成时」+ `generatedAt`
- [ ] KPI 列数**算过**容器宽度，没有孤立换行的卡片
- [ ] 无头渲染：区块齐 + **stderr 0 字节**
- [ ] 提交时**逐路径 add**，不是 `git add -A`
