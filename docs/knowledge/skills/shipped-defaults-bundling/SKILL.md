# 出厂资产内置（「装上即用」）—— 读时兜底，绝不写回

## 0. 先问这一句

**「这份资产，换版本时需不需要能被推下去？」**
需要 ⇒ **只能做「读时兜底」**。不需要（一次性的常量）才谈得上写进默认值。

用户嘴上说「直接固化」时，**要的是结果（装上即用），不是那个实现**。做完告诉他：
「装上就有；以后你换了新的，重发包各台自动跟上」——这比解释机制有用。

## 1. ★★ 两种做法的区别（这是本技能最贵的一条）

| 做法 | 新装机 | 换新版本重发包 | 界面 |
| --- | --- | --- | --- |
| 写进 `store.defaults()` | ✅ 有 | ❌ **顶不动** | 看不出来（显示的还是旧值） |
| **读时兜底、绝不写回** | ✅ 有 | ✅ **自动跟随** | 如实（还能标出来源） |

**为什么写 defaults 会固化**：配置存成 `userData/config.json`，每次 `store.set()` 都会把**整个内存对象**落盘；
默认值一旦进了内存对象，就会跟着落盘。而这类文件**卸载都不删** ⇒ 以后包的默认值再变，本机那份旧值仍然优先。

**为什么读时兜底能跟随**：本机那个键**始终是空的**（谁也没写过它）⇒ 每次升级都重新按“空 ⇒ 用内置”算一遍。

## 2. ★ 单一兜底出口 + 判据只能是 `undefined`

```js
// 只在「本机根本没有这个键」时兜底；返回的是**内存视图**，cache 不动
function withBuiltinMap(c) {
  if (!c || !c.publish || c.publish.uiMap !== undefined) return c;
  return Object.assign({}, c, { publish: Object.assign({}, c.publish, { uiMap: uimapdefaults }) });
}
function get(key) { const c = withBuiltinMap(load()); /* …再按 key 取 */ }
```

- **为什么必须一个出口**：这份资产通常有 3 个读取方（后台任务 / 业务服务 / 渲染层）。
  各改各的，必然出现「发布能跑、界面却写着『未配置』」——**界面骗人**，用户会来问。
- **为什么判据是 `=== undefined` 而不是「空就兜」**：
  - 显式 `null` = 「我就是要没有这张表」——回归里正是用它验「未配 ⇒ 必须报错」。兜了它 = 那条断言**假绿**。
  - 本机自己导入/抓过（键存在）= 一律以本机为准，完全不兜底。
- ★ 写回路径要**逐一核对**：`store.set()` 是不是只接受字段级 patch？渲染层保存是不是只提交表单字段？
  有没有人 `store.set(store.get())`（**整体回写**）？有的话，内置值就会被顺手写进配置文件 = 又固化了。

## 3. ★ 大表：绝不手抄，用脚本生成 + 断言逐字节相等

手抄 40~80 行结构化数据一定出错，而且**出错时看不出来**。做法：
1. 写一个生成工具（放 `tools/`，长期保留）：从源头（本机配置 / 导出的 json）读出，**原样**序列化成一个模块文件；
2. 生成时跑**守卫**（见 §4），不过关就 `exit 1`，绝不生成一张可能错的表；
3. 在回归里断言 **`JSON.stringify(内置表) === JSON.stringify(源表)`** —— 这条把「手抄/漏字段」永远钉死；
4. 工具做**幂等自检**：连跑两次 `sha1sum` 必须相同（否则说明有 `Date.now()` 之类的漂移）。

## 4. ★ 环境戳：不匹配要**硬错**，不要静默出错

内置资产常常绑定一个环境（屏幕坐标系 / 版本号 / 分辨率 / 表结构版本）。
**没有戳，运行时就判不出「这份资产是在另一个环境里量的」** —— 而典型表现是**不报错的**（如写死的点击坐标点偏、`input tap` 越界 rc=0）。

```js
// 生成时：优先用源表自带的戳；没有才推断，且必须过「唯一性」自检
if (!fitsIn(w, h)) { console.error('★ 有坐标落在坐标系之外 ⇒ 不许猜，退出'); process.exit(1); }
if (alsoFitsInSomeSmallerCommonSize()) { console.error('★ 戳不唯一 ⇒ 不许写，退出'); process.exit(1); }
```

- **唯一性自检**：候选戳必须“解释得唯一”。若几个常见档都能装下 ⇒ 这个戳是**猜的**，
  宁可不带（运行时退回逐点越界校验，**宁可少拦，不误拦**）。
- **不许编造**：戳只能来自源数据或实测（如 `dumpsys window displays` 的 `cur=`）。推不出来就说推不出来。
- ★ 源资产里的说明文字（备注/note）可能是**过期口径**（例：note 写着 A 分辨率，而坐标早已是 B）。
  **以机器可读的戳为准**，并在注释里写清这个差异，别让后来人按注释改。

## 5. ★ 凭据内置：讲清代价 + 会连累老用例

- **代价当面说清**：包里带 key = 谁拿到包谁能刷额度 ⇒ 只发内部、额度设上限、出事直接换。
- 实现同样走「本机填了以本机为准，留空才落回内置」，绝不写回配置文件（否则换 key 顶不动，见 §1）。
- ⚠️ **必查**：既有的「没配 key ⇒ 必须失败、不许静默降级」用例。内置 key 之后，
  **「框里空着」不再等于「没配」** ⇒ 那条用例变成**假绿**。改法：用例里**临时清掉内置值**再跑，并 `try/finally` 还原：

```js
const D = require('../src/main/llmdefaults.js');
const saved = D.apiKey; D.apiKey = '';          // 把「内置也没有」这个状态造出来
try { /* … 原来的负向断言 … */ } finally { D.apiKey = saved; }
```
（断言里写清为什么这么改，否则下一个人会“顺手”把 stub 删掉。）

## 6. 自证清单（每条都要能复算）

- [ ] **新装机**（临时 userData/空配置）读出来 = 内置资产（比对步数/条数/字段数，不是「有对象就行」）；
- [ ] **不写回**：读过之后改一个无关设置、等过防抖，**配置文件里不含**该资产的任何字面量；
- [ ] ★ **反向对照**（防恒真）：显式写入一份 ⇒ 配置文件里**必须**能查到。
      没有这条，「不写回」的断言可能是恒真的（比如读的是另一个文件）；
- [ ] 显式 `null` 不被顶掉；本机值优先于内置；
- [ ] 与环境戳相关的三条：同环境**不误报** / 异环境**必报** / 读不到环境信息时**不当判据**；
- [ ] **双边破坏验证**（见技能 `bilateral-fix-verification`）：摘掉兜底 ⇒ 对应断言必须红；还原 ⇒ 绿且 sha 与破坏前一致。

## 7. 沙箱坑（Windows / 本机环境）

- 跑 Electron 套件前 **`env -u NODE_OPTIONS`**：本机 `NODE_OPTIONS` 常带 `--use-system-ca`，
  Electron 会 `--use-system-ca is not allowed in NODE_OPTIONS` **直接退 9**（不是代码问题，别去改代码）。
- 直接跑 `electron.exe` 前 **`unset ELECTRON_RUN_AS_NODE`**（否则被当 node 跑，报 `bad option: --xxx`）。
- 断言数**每次实测重取**，别凭记忆（新套/新断言会让总数变；用「基线 + 新增」交叉核对更可信）。

## 8. 交付边界

- 树里有**另一路会话**未提交的改动 ⇒ **不提交、不从脏树打包**（见技能 `concurrent-workspace-safe-release`）。
- 诚实列「没做/待办」：没改的界面文案（hint 里可能还在写「未配置，请导入」）、没更新的文档索引、待用户拍板的项。
