# 图像判定标签的标定：先判维度，再定阈值

## 何时用
- 用户说「新增一个 XX 类目 / 标签」，判断依据是一句**视觉描述**（「首图只有一只手并且手里拿着东西」）。
- 已有的图像分类**误判多、置信度低、要多少条待确认**，需要重调阈值或换口径。
- 需要给一个「AI 判定」的结果一个**能写进文档的数字**（精确率/召回），而不是「效果不错」。

## 第 0 步（最容易跳过、也最贵）：先判「它是不是一个类目」

**判据：拿真实数据做一次「并列竞争」实测。** 把这个新维度当成第 N+1 个类目塞进同一个
softmax，跑一遍已有数据，看它抢走多少：

```python
# _probe_xxx.py —— 只读，不改任何东西
# 1) 已有的 types 提示 + 新维度提示，一起算 per-prompt 嵌入
# 2) 对每张图取「类内 top-k 池化」后的相似度，argmax 当预测
# 3) 对比：现役预测分布 vs 并列后的预测分布
```

**实测案例（得物主图，159 张，2026-09-21）**：把「手持」当第 8 类并列 → 抢走
**23%（37/159）**，且**全部单向被抢、无一条反向**：

| 类目 | 现役 | 并列后 |
|---|---|---|
| 其它 | 61 | **37** |
| 家居生活 | 17 | **12** |
| 球鞋 | 25 | **22** |
| **手持** | — | **37** |

判定标准：

| 现象 | 结论 |
|---|---|
| 抢走的比例 **>10%**，且**单向**（只有新类抢别人） | 它**不是**同类维度 → 做成**正交标记（flags）** |
| 双向流动、比例小、语义确实互斥 | 才是真类目 |
| 只在「其它」里分走一部分 | 更像「其它」内部的子类细化，先看语义 |

**根因句式（想清楚这句再动手）**：
> 它描述的是「**怎么拍的**」（拍摄形式），类目描述的是「**拍的是什么**」（内容品类）——
> 一支口红的图可以同时是「美妆护肤」和「手持」。

**架构结论**：做成 flags —— 与类目**正交、可叠加筛**；数据落在 `raw` 的 4 个键上
（`<key>` / `<key>_conf` / `<key>_low` / `<key>_at`），**零 DDL、绝不碰 `content_type`**。

## 第 1 步：选判定口径 —— 绝对相似度几乎总是不够用

直接拿提示的**绝对** cosine 排序，往往头几名混进完全无关的东西（实测混进过
情侣合影 / 吊灯 / 香蕉 / 平板展示），而且分数挤在一条窄带里（0.199~0.283，区分度极差）。

**采用：对比式**
```
score = mean(top-k( sim(正提示) )) − mean(top-k( sim(负提示) ))
```
- `top-k` 复用类目那套池化（`POOL_TOPK=2`），**别另起一套**；
- 负提示要覆盖真实干扰源（人/脸/房间/纯产品图/地上的鞋衣/截图），**各 ≥4 句**；
- 实测对比（同一黄金集）：

| 口径 | 阈值 | 精确率 | 头部召回 |
|---|---|---|---|
| 只用绝对相似度 | 0.2500 | 70.0% | — |
| 对比式 · 只减 2 条负向 | 0.0456 | 88.2% | 55.6% |
| **对比式 · 减全部 6 条负向** | **0.0218** | **88.0%** | **81.5%** |

⚠️ 阈值与提示词都写进**配置文件的 flags 段**（可调不改码），代码里的常量只作兜底
（`f.get("阈值", HH_MIN)`）。测试要断言「脚本常量 == 模块阈值」，两处不一致 = 库里存的分数与判据对不上。

## 第 2 步：出「带编号对照图集」，请人逐格目视判读

**没有人的判读，就别谈阈值。** 生成器模板（Pillow）：

```python
# 每格 250px，4 列 × N 行；格左上角写「排名#id + 分数」，让人能对上号
# 输出 _sheet_1.png ... + _sheet_idx.txt（rank / id / score / 现役类目）
```
- 前 **48 名全看**（阈值大概率落在这段的分数带里），再从**尾部随机抽 24 张**估召回；
- 黄金集 JSON：`{items:[{rank,id,y,note}], '标定结论':{阈值,待确认阈值,实测:{...}}}`，
  `y` = `1/0/null`（**null = 看不准，剔除不参与**）；
- ✅ **三种标签都必须真的出现过** —— 否则标定是在单类样本上做的，要写一条断言锁住这点。

## 第 3 步：扫全曲线选阈值（别只看精确率）

**真实翻车**：最初按「精确率 92.3% 好看」选了 0.0480 → dry-run 只判出 **2 条** ——
精确率漂亮但**召回≈0 = 等于白做**。改按 F1 视角扫全曲线后才取到 0.0218。

```
阈值      判出   真   精确率   头部召回
```
- 给出「保守点 / 采用点 / 激进点」三个参考，让用户能自己平移；
- 报告里**必须写明**「精确率是在标定集自身上测的，不是保证值」；
- 输出「疑似档」（`low ≤ score < min`）时，**要单独给出该段的精确率**（实测只有 43%），
  并在界面上写「只作参考」。

## 第 4 步：落地为 flag（零 DDL）+ 两条通道分离

```python
# 只写 flag 的 4 个键，先读该行 raw 再合并：raw = dict(raw0)
# 幂等：已有 <key>_conf 即跳过 → 重复跑不产生漂移
# 没有主图/图下不下来 → 跳过并计数，**不写假值**（不把「没算」写成 False）
```

**★★ 两条通道必须分开**（否则早期老记录永远补不上标记）：

| 通道 | 参数 | 语义 |
|---|---|---|
| 内容类目 | `--refresh --only-missing --push` | 只标没标过的；人工修正过的永不被覆盖 |
| 独立标记 | `--flags` | 补**所有**还没算过的（含老记录），幂等 |

合并的两种后果都不可接受：并进 `--only-missing` → 老记录被跳过、标记永远补不上；
走全量重跑 → few-shot 会把**已有的**类目改掉（有漂移风险）。

再给一个 **`--hh-golden`（以库为准）**：读库里已存的分数重扫阈值曲线 →
**改阈值不用重跑模型**（分数已经在库里了）。

## 第 5 步：诚实性（这一层最容易写假值）

- **未知 ≠ 否**：没算过（字段不存在）与「明确不是」（`false`）**都不能被这个筛选项捞出**；
- 疑似档必须带 `?`，tooltip 明写「只作参考」+ **该段真实精确率**；
- 前端要有**护栏**：`typeNames()` 排除、写配置前剔除、默认类目表不含 ——
  否则「人工修正」会把 `content_type` 写成这个标记名，或采集端拿它去筛 `content_type`（一条都筛不到）；
- 指纹（`dataSig()`）要带上它 —— 它是**另一个进程**写的，不进指纹就是「标完了页面没反应」。

## 踩坑清单（都真实踩过）

1. ★★ **离线标定脚本与「读生产库」两把尺子不一致时，以读库为准。**
   实测：离线报 91.7%（24 条），读库报 **88.0%（25 条）**；根因是黄金集里有**重复 id**
   （同一 id 出现两次）→ 离线去重后分母变小。**自检脚本自己也会有误差。**
   统一口径时，脚本注释、配置模块、黄金集三处**都要改**。
2. ★★ **标定脚本的口径必须与实现一致。** 实测：标定按「只减 2 条负向」扫曲线，实现却是
   「减全部 6 条」→ 首次 dry-run 只判出 2 条，白折腾一轮。**改口径后重扫，别沿用旧曲线。**
3. **别按「精确率好看」选阈值**（见第 3 步）。
4. **首次真跑别用小 timeout**：要重新下载全部图片，900 秒不够 → 后台跑 +
   `PYTHONUNBUFFERED=1` + `-u` + 写文件（否则被 SIGTERM 杀掉且输出被缓冲吞掉，什么都看不到）。
5. **读库时确认列在哪**：想读点赞量写了顶层 `like_count` → `42703 column does not exist`；
   这类项目常见「全部业务字段都在 `raw` jsonb 里」。
6. **反向断言别用裸关键词**：`/content_type/` 会命中 **`content_types.json`**（配置文件名）
   与日志文案。改成「写字段三形态」判据（`raw["x"]` / `"x":` / `x =`），
   并加一条**反向自证**（人为塞一行必须变红）。
7. **测试桩要跟得上**：被测函数新增了 `isHhKey()` 之类的内部调用 → harness 里报
   `xxx is not defined`；读 DOM 控件的桩返回 `null` → `null.value`。
   （判据：错误信息里的名字是**你自己的桩/辅助函数名**就是桩的问题，别改产品代码。
   细则见技能 `headless-ui-selftest` 踩坑 13。）
8. **人工确认样本会灌进 few-shot**：注意样本不均衡（实测首次 `--learn` 得到 15:1），
   而判定取「每类最像的那张」→ 样本多的类天然占便宜，下一轮有偏移风险。
