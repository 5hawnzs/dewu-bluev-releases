# 从栅格截图复刻矢量 Logo

**核心原则：不要凭眼睛画圆角。** 栅格图里每个像素都是证据 —— 量出来、拟合、再渲染回去逐值对账。
下面这套流程实测可以把「用户给的 256px 图标」复刻到 **最大偏差 1.25px/256（≈0.5%）**。

> 反面教材：按印象写一个 `M512 0C793.6 0 1024 230.4 1024 512...` 的 "squircle"，
> 那个控制点偏移 `0.5523*R` 其实是个**正圆**，渲染出来四个角全是圆弧，和原图完全不是一回事。
> 必须先量，再拟合。

## 0. 环境（Windows 沙箱）

- Bash 每条命令都要自己 `export PATH=`，含 `PortableGit/cmd:/usr/bin:/bin` 与托管 runtime 绝对路径。
- **本机没有 PIL**，也不一定允许联网装。用 `scripts/png_probe.py`（纯标准库 PNG 解码，支持 8bit 灰度/RGB/RGBA、非隔行）直接读像素。
- 渲染/截图用本机已装 Chrome 的无头模式（见 §4）。

## 1. 先量轮廓：拿到「原图的真实几何」

要看三样东西，**都要数字，不要"看起来"**：

1. **容器外轮廓**（圆角轮廓）—— 逐行取「第一个不透明像素的 x」。
2. **标记本身**（比如那个字母/图形）的 bbox 与笔画宽度。
3. **主色**（渐变两端各取一点）。

```python
# scripts/png_probe.py 已封装好；典型用法
import sys; sys.path.insert(0, 'scripts')
from png_probe import load_png
w, h, ch, px = load_png(r'C:\path\icon.png')

def alpha(x, y): return px[(y*w+x)*ch+3]
def left_inset(y):                      # 逐行左内缩 = 该行第一个不透明像素
    xs = [x for x in range(w) if alpha(x, y) > 200]
    return min(xs) if xs else None

for y in [0,1,2,3,4,6,8,12,16,24,32,48,64]:
    print(y, left_inset(y))
```

同时把 **标记（白色像素）的 bbox** 和若干条水平扫描线上的「白色游程」也打出来，
用来反推端点、顶点、笔宽 —— 这样改版时才能**沿用原几何**而不是重画一个"差不多"的 V。

## 2. 反拟合圆角参数（而不是拍脑袋）

把角部曲线当**超椭圆**：`|u|^n + |v|^n = 1`（u、v 是从角点向外归一化的坐标）。
对给定的 `(R, n)`，在行 y 处的左内缩是闭式的：

```python
def inset(y, R, n):
    if y >= R: return 0.0
    a = 2.0 / n
    s = (1.0 - y / R) ** (n / 2.0)      # sin t
    c = math.sqrt(max(0.0, 1.0 - s*s))  # cos t
    return R * (1.0 - c ** a)
```

然后在 `R ∈ [40, 64]`（256 画布）扫描，取「与实测表最大偏差最小」的那组。
实测一例：`R=52.75, n=1.84`，最大偏差 **0.75px**；
按印象取的 `R=52, n=1.7` 偏差 **2.5px** —— 肉眼看不出来，但渲染回栅格对账时会被抓住。

**必须同时拟合 R 和 n**：只调 n 会拿一个错的 R 去补偿，角部形状整体走样。

## 3. 超椭圆角 → 三次贝塞尔（避开参数化退化）

⚠️ **踩坑**：直接按解析参数 t 做 Hermite 会失败。
`x = R(1-cos^a t), y = R(1-sin^a t)`（a=2/n）在 **t=0 和 t=π/2 处速度都趋 0**（指数 2/n-1 = 0.176 > 0），
导数向量退化成 0，Hermite 的两个控制点会塌到端点上，曲线直接画错。

**正确做法：先做弧长参数化，再按弧长等分做 Hermite。**

```python
# 见 scripts/squircle.py：corner_segments()
pts  = [raw(pi/2*i/N) for i in range(N+1)]     # 稠密采样
cum  = 前缀弧长
at(u)   -> 由弧长比例二分回查点位
tan(u)  -> 有限差分求单位切向量
seg: P1 = P0 + T0*L/3 ;  P2 = P3 - T1*L/3     # L 是该段弧长
```

每角 **K=3 段** 实测「贝塞尔 vs 超椭圆」偏差 **0.314px/1024**，足够。
K=3 → 整条路径只有 M/H/V/Z + 12 条 C，**在设计工具里可编辑**（不要用几百点折线糊）。

拼四个角：绕画布中心旋转模板 `(x,y) → (C-y, x)`，
**注意区分「点」和「方向」** —— 点要减去中心再转、再加回；方向只转不平移。
拼完自检四个角终点必须是 `(1024,R) (R,1024) (0,R) (R,0)`。

## 4. 渲染回栅格逐值对账（这一步不能省）

⚠️ **不要直接 `chrome --screenshot=xxx.png file:///x.svg`** ——
Chrome 对「独立 SVG 文件」会做自适应缩放（默认 body 外边距 + 视口适配），
量出来的轮廓会整体偏移/缩放，看起来像"画错了"，其实是被缩放。

**正确做法：包一层 HTML，去掉外边距，1:1。**

```html
<!DOCTYPE html><html><head><meta charset="utf-8">
<style>html,body{margin:0;padding:0;overflow:hidden;background:transparent}
svg{display:block}</style></head><body>
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 1024 1024"
     width="1024" height="1024"><path d="..." fill="#0F7D60"/></svg>
</body></html>
```

```bash
"/c/Program Files/Google/Chrome/Application/chrome.exe" --headless --disable-gpu \
  --hide-scrollbars --force-device-scale-factor=1 --default-background-color=00000000 \
  --window-size=1024,1024 --screenshot=out.png "file:///C:/path/probe.html"
```

对账断言（**双向**）：
- 逐行内缩，重绘值/4 与原图值之差 **≤2px（原图尺度）**；
- **单调性**：角部内缩必须单调不增。非单调 = 曲线画反/自交 —— 这是「一眼看出不对」的那个信号。

> 实测数据：修好之后 max 偏差 1.25px / 单调性 PASS。
> 修好之前 max 偏差 20.25px 且单调性 FAIL —— 见下面这个 bug。

## 5. ★ SVG path 守卫：抓「数字粘连」

**症状**：路径看着完全正常，Chrome 也不报错，但渲染出来**左上角的圆角被啃掉一块**（其余三个角都对）。
逐行量轮廓会发现内缩**非单调**（202→173→…→27→38→55→…→0）。

**根因**：用 Python 拼接长 path 字符串时漏了一个空格：

```python
"...C55.8 81.1 81.1 55.8" + "110.3 36.1C139.4 ..."
#                          ↑ 少了空格 → "55.8" + "110.3" == "55.8110.3"
```

`55.8110.3` 被解析成 `55.811` 和 `0.3` —— **仍是合法数字**，
于是那条 C 少了一个参数、贝塞尔控制点被顶错位，浏览器照样画，**静默变形**。

**守卫（每次生成 SVG 后必跑）** —— 按命令切分、检查每条命令的参数个数：

```python
ARITY = {'M':2, 'L':2, 'H':1, 'V':1, 'C':6, 'Z':0}
_CMDS = ''.join(ARITY)
def validate_path(d, label):
    bad, covered = [], 0
    for m in re.finditer(r'([%s])([^%s]*)' % (_CMDS, _CMDS), d):
        cmd, argstr = m.group(1), m.group(2)
        covered += m.end() - m.start()
        toks = argstr.split()
        for t in toks:
            try: float(t)
            except ValueError:
                bad.append('%s: 非法数值 token %r（两段数字粘连）' % (label, t))
        n = ARITY[cmd]
        if n == 0:
            if toks: bad.append('%s: %s 不应带参数' % (label, cmd))
        elif not toks or len(toks) % n:
            bad.append('%s: %s 参数 %d 个，不是 %d 的整数倍' % (label, cmd, len(toks), n))
    if covered != len(d):
        bad.append('%s: %d 个字符未被命令覆盖' % (label, len(d)-covered))
    return bad
```

**必须带自检**（否则守卫可能本来就是死的）：构造一个坏样例喂进去，断言它一定报错。

```python
_BROKEN = re.sub(r'(?<=\d) (?=[\d.])', '', SQ, count=1)   # 抹掉第一个数字间空格
assert _BROKEN != SQ
assert validate_path(_BROKEN, 'SELFTEST')                  # 必须非空
assert not validate_path(SQ, 'SQ')
```

> 这条自检抓出过一次**误报**：守卫本身漏了 `L` 命令，
> 于是合法的 `M300 308L512 728L724 308` 被当成 `'308L512'` 报错。
> **先确认守卫对"合法样本"不报错，再去信它对"可疑样本"的报错。**

**根治写法**：不要手写拼接，用 `' '.join([...])` 或生成器输出，
并且在写盘前 `assert io.open(p,'rb').read().count(b'\r') == 0`（换行符守卫见技能 `win-sandbox-scripting` §10）。

## 6. 改版时的设计准则（别把原稿的优点一起改掉）

用户说「太简单了」指的是**缺层次**，不是**形状不对**。所以：

- **几何沿用**：端点/顶点/笔宽按第 1 步量出来的数值直接用，一像素都别动。
- **只加层**：材质（折叠/双面）、结构（徽章环/底盘）、光影（渐变/辉光/星芒）各加一层就够。
- 三个方向各出一版，**同一套几何**、不同层次 —— 这样用户是在"选气质"，不是在"选形状"。
- 小尺寸测试行（72/48/32/20）一定有，logo 的真正考场在那里。
- 顺便给**去底板的纯标记**（浅底/深底两版），启动页和水印位要用。

**收尾前的自检**：把每个概念的 1024 PNG 单独打开看一遍。
实测踩过的两个坑：
- 用「模糊暗椭圆」做折痕 → 顶点附近出现一块**污渍感**的灰绿斑，去掉、只留笔画投影才对；
- 星芒压在字形的笔帽上 → 看起来像**渲染缺陷**，必须挪到空白处。

## 7. ★ 交付：文件写对了 ≠ 用户看见了

**踩过的坑**：文件全部落盘、校验全过、附件也 `deliver_attachments` 了，
用户下一句还是「**为啥没看到你的图**」。
预览面板（`preview_url`）和附件回传在部分客户端/会话里会**静默不显示** —— 不是失败，是没有回执。

**交付顺序（三件一起做，别只做一件）**：

1. **先内联渲染进对话**（最高优先级）。用 `read_me(modules=["art"])` + `show_widget`，
   把矢量稿**原样**嵌进聊天流。这是唯一"确定在用户正在看的那个界面上"的通道，
   而且用户能立刻看到，不用点开任何东西。
2. 再把**图**用 `open_result_view` 打开（PNG 类走这个；HTML 才走 `preview_url`）。
3. 最后 `deliver_attachments` 给源文件。

**内联不是手抄 SVG** —— 手抄必然抄错。用 `scripts/inline_preview.py`：
从磁盘读文件 → 正则抽出若干份 SVG 的**内容体**（去掉外层 `<svg>`）→ 自动把
**出现 ≥2 次的 `d` 串抽成 `<defs>` 里的 `<path id=pN>` + `<use href="#pN">`**。
实测三个 1024 画布的概念稿 13KB → 9KB，且**一个字符都没重写**。

```python
# 关键两步（完整见 scripts/inline_preview.py）
seen = {}
for key in order:
    for d in re.findall(r'\bd="([^"]+)"', bodies[key]):
        seen[d] = seen.get(d, 0) + 1
shared = {d: 'p%d' % i for i, (d, n) in enumerate(sorted(seen.items())) if n >= 2}
# 然后 b.replace('<path d="%s"' % d, '<use href="#%s"' % pid)
```

注意：
- `<use>` 放在**页面顶部的独立 `<svg width=0 height=0>`** 里，各卡片 SVG 用 `href="#pN"` 引用即可（同一文档跨 SVG 引用有效）。
- id 用 `p0/p1...`，**不要用各文件自带的 `a-`/`b-`/`c-` 前缀以外的东西**去重命名，会撞车。
- 卡片外框给**具体色值**（暗底 `#161A1F` + 描边 `#2C343C`），别用主题变量 —— 用户是暗色 IDE。
- 字号 ≥11px、字重只用 400/500（Visualizer 规范）。

**顺手把原稿也放进对比行**（第一张），用户才能"对比"而不是"看单张"。

### 坑 1 ★★：「共用字面量」—— 全局替换必然误伤

`#FFFFFF` 在一份 logo 里通常同时出现在**至少三处**：高光层、渐变端点、内圈细描边。
而「正笔面」渐变往往是 `#FFFFFF → 某淡色`。

于是 `#E6FFF6（淡色）→ 墨色` 这种替换会留下 **stop 0 仍然是白的**，
得到一条 **白→墨的渐变臂** —— 渲染出来是"上白下黑"的污渍感，
**不报错、不崩、只有一个字面量没被替换掉**。实测就栽在这。

**对策**：渐变**整块重写**，不要只换 stop 里的颜色字面量。

```python
om = re.search(r'<linearGradient id="%s-front"[^>]*>.*?</linearGradient>' % k, s, re.S)
s = s[:om.start()] + front_block(k, v['front_stops']) + s[om.end():]
```

配一条守卫 + **双向自检**（先造坏样例证明它会红）：

```python
_broken = base.replace('stop-color="#E6FFF6"', 'stop-color="#04393B"', 1)
assert 'stop-color="#E6FFF6"' not in _broken          # 坏样例真的造出来了
try:
    check_front(_broken, 'a', WANT_INK, True)
    raise SystemExit('FAIL 守卫没抓住「白→墨」')
except AssertionError as e:
    print('反向自检 PASS:', e)
check_front(base, 'a', WANT_ORIG, False)              # 正向必须放行
```

### 坑 2 ★：小图被画成 1024px

母版根标签已带 `width="1024" height="1024"`。再 `re.sub` 插一对 → **重复属性**，
浏览器取**第一个** ⇒ 一个标着 72px 的小尺寸测试图，实际按 1024px 渲染，排版全崩。
必须先删旧的：`re.sub(r'\s+width="\d+"\s+height="\d+"', '', svg, count=1)`。

### 换色必然要重新验对比度，而且要**双向取最差**

底色变了，原先"白字在深底上"的结论全部作废。按 WCAG 相对亮度算，
**底色渐变按 userSpaceOnUse 参数解析取值**（不要截图采样，会有抗锯齿噪声），
正/背笔面各自取「所有端点色 × 所有采样点」的**最小**值。

实测一例（得物极光蓝 `#01C2C3` 当底）：
| 方案 | 正面对比 | 结论 |
|---|---|---|
| 品牌原色底 + 白 V | **2.47:1** | 低于 3:1 图形底线，看着像不能用 |
| 同底 + 墨 V `#063537` | 4.67:1 | 保住品牌色又能读 ✅ |
| 品牌色压深一档 + 白 V | 4.46:1 | 保守可用 |

> 教训：**"用品牌原色当底"和"保留白色笔面"这两个要求会打架。**
> 一旦算出低于 3:1，不要硬凑 —— 把「压深底色」和「翻成墨色」两条路都做出来给用户选。

### ★★ 但「最差值采样」很容易采到标记根本压不到的地方 —— 别急着宣判不能用

上表那个 **2.47:1** 的取值点是渐变**最亮的角部**（`#01C2C3`），
而**那个角在字形的包围盒之外** —— 测的是一个真实世界不存在的组合。

正确的量法分两层：

1. **矢量名义值**：所有端点色 × 所有采样点取最小（上表那步，用来判风险）；
2. **等效对比度**：把图标**真渲染成目标像素尺寸**，另渲染一张**只有字形的白剪影当遮罩**，然后
   - 底色 = 「字形包围盒内、遮罩 alpha < 12」的像素的**中位色**；
   - 笔面 = 「遮罩 alpha 最高」那批像素里的**最亮值**；
   - 两者算 WCAG 对比度；同时也报"对区内最亮处"作为悲观界。

实测（同一份稿）：

| 尺寸 | 实际笔宽 | 笔面峰值覆盖 | V 区底色中位 | 对中位底色 | 对区内最亮处 |
|---|---|---|---|---|---|
| 20px | 1.88px | **100%** | `#0AA0A1` | **3.20:1** | 2.70:1 |
| 32px | 3.00px | 100% | `#08A2A4` | 3.13:1 | 2.50:1 |
| 72px | 6.75px | 100% | `#09A1A2` | 3.17:1 | 2.56:1 |

⇒ 结论整个翻转：名义最差 2.47:1，**实际压在字形下面的底色是 `#09A1A2` 一带、实测 3.1–3.2:1，
而且缩到 20px（笔宽只剩 1.88px）笔画中心覆盖度仍是 100%，没有糊**。

两条可复用的判据：
- **「均匀渐变底上的标记」必须按标记自己的包围盒取底色**，不能全局取最差值；
- **「小尺寸会不会糊」看的是笔画中心覆盖率**（遮罩 alpha 峰值 / 255），不是矢量对比度。
  笔宽 ≥1.8px 时覆盖率仍能到 100%。

> 教训：**先把「名义最差」和「实际有效」分开报**，再下"能用/不能用"的结论。
> 直接拿名义最差去否掉一个方案，会白白砍掉用户真正想要的那个方向。

## 9. ★★ 交付 App 图标资产（一个 App 真正缺的往往不是启动页）

用户说「这是 App，没有启动页和加载态」时，缺的是**图标资产**。四条平台硬约束，每条都踩过：

### 9.1 iOS 1024 **不能有 alpha**，而且必须给**满幅方形**

- App Store 拒收带 alpha 的 1024 图标 ⇒ 落盘时走 **RGB（color type 2）**，不要 RGBA。
- iOS **自己**裁连续圆角 ⇒ 给带 squircle 轮廓的版本会在四角留透明缺口。
  母版那个连续圆角只用在「应用内 / 分享卡 / 非 iOS 的展示场景」。
- 方形版把轮廓 path 换成 `M0 0H1024V1024H0Z`，并**去掉内圈细描边**（它只对 squircle 成立）。

守卫（必须在**渲染缓冲区**上判，不能只看落盘文件 —— 把 RGBA 压成 RGB 会顺手把透明度抹掉，
坏图也能"通过"）：

```python
def opacity_pass(w, h, buf):                    # buf 是渲染出来的 RGBA
    return min(buf[i] for i in range(3, w*h*4, 4)) == 255
# 正向：方形满幅 1024 → PASS（alpha 最小值 = 255）
# 反向：给 squircle 版 → 四角 alpha = 0 → 必须 FAIL
```

### 9.2 Android 自适应图标：三层素材 + **33dp 安全圆**

- 交付 **背景层 / 前景层 / 单色层** 三份（108dp 画布），加 `mipmap-anydpi-v26/ic_launcher.xml`。
- **不要**贴死某一个蒙版做成成品图 —— 各家 ROM 蒙版形状不同（圆形 / squircle / 圆角方形）。
- 安全区：**直径 66dp ⇒ 108dp 画布上半径 33dp**。换算 `1dp = 1024/108 = 9.4815px`，
  故 33dp = **312.9px**（1024 画布）。
- **字形墨迹必须含投影一起算**。圆帽端点的外沿半径 = `dist(端点, 中心) + 笔宽/2`。
  实测母版 V：`√(212²+204²) + 48 = 342.21px = 36.09dp` —— 直接塞进去会被裁。
  缩放系数 = `(312.9 − 投影外扩) / 342.21`，投影外扩按 `2.2σ + dy` 估。
  实测缩到 **0.8173**，量得含投影外沿 **30.09dp**（余量 2.91dp）。
- 投影要**另建小号 filter**：母版的大投影缩到前景层后会吃掉安全区余量。
- 守卫：渲染前景层 → 量「alpha > 8 的像素离画布中心的最大距离」→ 换算 dp → 断言 ≤ 33。

```python
def safe_pass(w, h, buf, dp_canvas=108, limit=33.0):
    _n, far, _p = stats_alpha(w, h, buf)
    return far / w * dp_canvas <= limit, far / w * dp_canvas
```

### 9.3 通知栏小图标：系统**只取 alpha** 上色 ⇒ 必须交纯白剪影

彩色母版直接不能用。同一份剪影在深/浅状态栏由系统上色，所以**只交一份白色的**，
字形控制在 **24dp 网格的 ~88% 方形安全区**内（`d` 按中心缩放）。

```python
def notif_pass(w, h, buf, tol=0):               # 不透明像素必须全是 255,255,255
    return all(buf[i] == 255 and buf[i+1] == 255 and buf[i+2] == 255
               for i in range(0, w*h*4, 4) if buf[i+3] > 0)
# 反向：拿彩色母版直出 → 抓到 887 个非纯白像素 → 必须 FAIL
```

### 9.4 Android 13+ 主题图标 = **单色层**，同样只取 alpha

和前景层共用同一份几何与缩放，只是把笔画全刷成 `#FFFFFF`、**去掉 filter**
（投影在这种层里没意义，还会污染安全区测量）。

### 9.5 目录结构（直接能用的那种）

```

### 9.6 渲染策略：一张表放多个尺寸，一次截图再按坐标裁

逐个尺寸起 Chrome 太慢。把**同一变体的多个尺寸**用 `position:absolute` 铺进一页，
记下 `(name, x, y, size)`，**一次截图**后按坐标裁。实测 8 张表 45 个尺寸 15 秒。
裁剪用纯 Python（`crop_rgba`），**不要**自己写缩放 —— 让浏览器在目标尺寸原生栅格化，
质量最好且不会二次采样。

### 9.7 正 / 负两组夹具，用**同一套构建函数**渲染

守卫的正向样本和坏样例都必须来自同一个 builder，否则你证明的是"另一个东西"：

'bad': [

  ('bad-ios-圆角',  1024, wrap(TILE + vgroups(), DEFS, 1024)),   # 四角透明
  ('good-square-1024', 1024, ck('square', 1024)),                # 对照组
]
```

每条关键守卫都要在坏样例上跑红过一次，再去信它在正品上的绿灯。实测 32 项检查全部这样过。

## 10. ★ 格式化残留守卫：`%%` 会静默写进产物

**症状**：安全圆守卫**全绿**，但产物里的 `x="-45%%"` 不是合法长度 ——
Chrome 会**丢弃整个属性**、改用默认过滤区（`-10%/-10%/120%/120%`）。

**根因**：用 `%` 格式化拼字符串时写了 `%%`，后来把格式化那一步删掉了，字面 `%%` 就留在产物里。

```python
FG_SH1 = '<filter ... x="-45%%" ...>'      # 本来是给 '%' % pfx 用的
...
inner = vgroups(FG_SCALE, f1='v2-fsh1')    # 这一步改了，格式化没了 → %% 原样落盘
```

**为什么最阴**：默认过滤区（10% 余量）恰好比投影外扩大一点，
所以守卫照样绿 —— **绿得不是同一个理由**。实测修前 29.89dp / 修后 30.09dp，
且修前修后渲染逐字节差 **1.05%（最大通道差 255）**，确实有视觉后果。

**守卫**：扫描所有产出的 SVG，禁止 `%%`，并逐个 `float()` 校验长度属性。

```python
def numattr_problems(txt):
    bad = []
    for m in re.finditer(r'<(?:filter|feDropShadow|feGaussianBlur|feOffset)\b[^>]*>', txt):
        for k, v in re.findall(r'\b(x|y|width|height|dx|dy|stdDeviation)="([^"]*)"', m.group(0)):
            probe = v[:-1] if v.endswith('%') else v
            try: float(probe)
            except ValueError: bad.append((k, v))
    return bad
```

**通用化**：**一切"给格式化/模板引擎留的转义"都要在产物上再验一遍**。
`%%`、`{{x}}`、`$VAR`、`\n` 字面量都会这样静默漏出去。

## 11. ★ 超高清导出：三个「测量陷阱」会把好图判成坏图

导出本身很简单（同一份 SVG，改根标签 `width/height` + 调 device-scale-factor），
难的是**证明它没坏**。下面三条全是实测踩出来的**假警报** —— 每一条都曾把正确的产物标成 FAIL。

### 陷阱 1：拿「替换前后字符串是否相同」当守卫
目标尺寸恰好等于源尺寸（1024）时，`re.sub` 的结果与原文**逐字节相同**，
`s2 != s` 这个断言会**把成功的替换判成"没替换"**。
```python
# ✗ s2 = re.sub(pat, new, s); assert s2 != s     # 目标 == 1024 时必然假报错
s, n_sub = re.subn(r'(<svg[^>]*?)\swidth="1024"\s+height="1024"',
                   r'\1 width="%d" height="%d"' % (css, css), s, count=1)
assert n_sub == 1                              # ✓ 数「真的换了几处」
```
**通用化**：守卫要断言的是**「动作发生了」**，不是「结果看起来不同」。

### 陷阱 2 ★★：同一行比 x —— 近平切区把偏差放大十几倍
连续圆角在顶端是与水平线**相切**的。那里竖直方向半个像素的量化误差，
会被放大成好几个水平像素。实测同一张图在 2048 / 4096 / 8192 下的「横向偏差」
是 **0.95 / 1.10 / 2.60 px**，看着像"越导出越歪"；换算回 1024 坐标系其实都是 **~0.3**。
⇒ 别比同一行的 x，改量**边界点到理想曲线的最短距离**：
```python
d = min(hypot(px - x, py - y) for x, y in 理想曲线的密集采样点)
```
换算成法向距离后，三个尺寸同时落到 **0.45–0.50px** —— 稳定到可以当回归基线。

### 陷阱 3：理想曲线的**采样密度**决定误差下限
法向距离的误差上限 = **采样间距的一半**。笔直段只按整数 y 取点时，
8192 下光采样间距就贡献 `0.4 × 8 = 3.2px` 的假偏差（实测就是这么误报的）。
⇒ 采样间距必须满足 `间距 × N/1024 ≪ 容差`（本例：曲线 6001 点/段、直线间距 0.02）。
**这是「测不准」不是「东西坏了」**，下结论前先自查这一条。

### 尺寸怎么选（统一窗口宽度、只调 dsf）
| 输出 | 窗口 | dsf | 实测体积 |
|---|---|---|---|
| 2048 | 2048 | 1 | 2.0 MB |
| **4096** | 2048 | **2** | 6.4 MB |
| 8192 | 2048 | 4 | 18.6 MB |

比"直接开一个 8192 的窗口"稳，不受窗口尺寸上限影响。**每一档都要验**：
① 画布尺寸 ② 四角透明 ③ 中线左右铺满（= 没有留白、没有缩放错）
④ 笔宽 = `96/1024×N`（证明是**等比缩放**不是拉伸）⑤ 边界到理想曲线的法向距离。

**反向夹具**：让 SVG 保持自带 `width="1024"` 塞进 2× 窗口 ⇒ 图形只占左上角 1/4，
几何守卫必须红（实测法向距离 **187.6px**、中线中点 alpha=0）。实测 28 项全绿。

### 大图读取要「只解需要的行」
8192×8192 RGBA 全量解出来是 **268 MB**，不能整张读。
PNG 过滤器是链式的（Up/Paeth 依赖上一行），所以只能顺序往下走，
但用 `zlib.decompressobj().decompress(data, max_length)` 可以**只解到需要的最后一行**：
```python
need = (w * 4 + 1) * (max_wanted_row + 1)
while len(out) < need:
    src = d.unconsumed_tail or data
    out += d.decompress(src, need - len(out))
    if not d.unconsumed_tail:
        data = b''
```

---

### 品牌色怎么取（别猜）

按这个顺序，每一步都留证据：
1. **官网 HTML 内联色**（`curl` 首页，`grep` 全部 `#RRGGBB` 按频次排）—— 最可能是主题 token；
2. **无头 Chrome 截图官方页**，对**扁平 UI 元素**（按钮填充）采样 —— 无光照偏差；
3. **实物照片采样**（包装/物料）—— 只能用来**确认色相**，照片有涂层 + 光照，
   数值不可当标准值用（实测箱子照片 `#9BD6D7` vs 官网 token `#01C2C3`，色相同为 180°）。
4. 拿不到就**如实说拿不到**，填 `—`，绝不编一个"看起来像"的值。

## 12. ★★ 透明底字母版：「去掉底板，把颜色填进字母」

用户的话往往就是这一句：**「去掉底色，把颜色填充到 V 上，除了字母有颜色，其他为透明底」**。
它和 §8「只换底色」是**相反的改版**：§8 改的是**谁在字母下面**，§12 改的是**谁在上色**。

### 12.1 做法：只「换写者」，绝不重画路径

正确做法不是重新画一个 V，而是**从已定稿母版里把字母的那两条 `path` 原样抠出来**，
只把 `stroke=` 换掉，其余一个字节都别碰：

```python
# 母版里字母是两条 fill="none" 的 path（描边字形）
back  = re.search(r'<path[^>]*d="M300 308L512 728L724 308"[^>]*/>', svg).group(0)
front = re.search(r'<path[^>]*d="M300 308L512 728"[^>]*/>',       svg).group(0)
```

**几何不变的证据**（不是"我看着一样"）：把两条 path 的 `stroke=` 抠掉再比——

```python
def strip_stroke(s):                    # 只留几何，去掉上色指令
    return re.sub(r'\s*stroke(?:-width|-linecap|-linejoin)?="[^"]*"', '', s)

check('几何指纹 = 母版',
      [strip_stroke(x) for x in re.findall(r'<path[^>]*/>', out)] ==
      [strip_stroke(back), strip_stroke(front)],
      '两条 path 抠掉 stroke 后与母版逐字节一致')
```

### 12.2 「底板真的没了」要用**禁用词扫描**证明，而且扫描本身要双向

只断言"我想要的都没了"是不够的，要断言"母版里那些我不想要的东西，一个都不在"。
维护一张**禁用词表**，并且**先扫母版（必须脏）再扫产物（必须干净）**——
否则禁用词表写错了（词根本不在母版里）你也会全绿：

```python
BANNED = ['M211 0H813',            # 底板矩形
          '<filter', 'filter="url', # 投影/模糊
          'v2-bg', 'v2-spec', 'v2-vig', 'v2-sh1', 'v2-sh2', 'v2-blur',
          '<circle', '<ellipse', '<radialGradient',   # 星芒 / 高光 / 暗角
          'stroke-opacity', 'fill="#']                # 任何实心填充
```

- 对母版跑：**必须命中**（`check('母版含底板', any(t in master for t in BANNED))`）；
- 对三份产物跑：**必须全部为 0**。

⚠️ `fill="#` 进禁用词表意味着**产物里一个字面填充都不许有**——
这正好也把「偷偷加一块白色底」堵死了。

### 12.3 透明底必须验「导出图真的带 alpha」

Chrome 无头截图默认给不透明背景，要显式指定：

```
--default-background-color=00000000
```

但**别信参数，要读 IHDR**：读 PNG 第 25 字节的颜色类型，`ct == 6` 才是 RGBA：

```python
def png_info(path):                 # 只读前 33 字节，不解码
    raw = io.open(path, 'rb').read(33)
    assert raw[:8] == b'\x89PNG\r\n\x1a\n'
    assert raw[12:16] == b'IHDR'
    return struct.unpack('>IIBB', raw[16:26])   # w, h, bitdepth, colour_type
```

判定链（三条都要，缺一条就可能"看起来透明其实不是"）：
1. `ct == 6`（带 alpha 通道）；
2. 画布**四角** alpha 全 `== 0`；
3. **反向夹具**：故意画一个满幅不透明矩形 ⇒ 上两条必须变红。

### 12.4 ★ `png_scan` 必须能吃 **ct=2（RGB）**，否则反向夹具会崩在半路

真实现象：满幅不透明的夹具导出来是 **RGB（ct=2）**，而解码器只写 `assert ct == 6`
⇒ 反向夹具直接抛异常，测试脚本挂掉，你以为"夹具没红"。

**正确处理不是"不支持就报错"，而是合成 alpha=255 再往下走**——
因为这个夹具的**缺陷本身就是「没有 alpha」**，把它当异常抛掉等于把要证明的东西扔了：

```python
bpp, stride = (4 if ct == 6 else 3), w * (4 if ct == 6 else 3)
...
if ct == 6:
    rows[y] = cur
else:                                # RGB：补 alpha=255，让「本该透明却不透明」可测量
    e = bytearray(w * 4)
    for x in range(w):
        e[x*4:x*4+3] = cur[x*3:x*3+3]
        e[x*4+3] = 255
    rows[y] = bytes(e)
```

**通用化**：解析器遇到"比预期更差"的输入时，倾向于**降级解析并继续**，
把缺陷交给断言去判——而不是在解析层抛异常（那会让整组守卫静默失效）。

### 12.5 ★★ 颜色是**搜出来的**，不是挑出来的

"填什么蓝"不该凭手感。对透明底字母，真实约束是**一条带**：
字母的每一个颜色都要在**所有会放的背景**上满足 WCAG 非文本对比度 ≥ 3:1。
关键是**背景未知** ⇒ 必须**双向取最差**（浅墨压深底、深墨压浅底，都要 ≥3:1）。

做法：在品牌色相族里暴力枚举，留下交集非空的相对亮度带：

```python
# 色相族 H 178°–190°、S 55–100%、V 24–83% ⇒ 实测 14053 个候选
pool = [c for c in candidates if min(contrast(c, bg) for bg in BGS) >= 3.0]
lo, hi = min(t[0] for t in pool), max(t[0] for t in pool)   # 实测 [0.153, 0.265]
```

实测结论（**这就是要讲给用户的实话**）：品牌真相色 `#01C2C3` 的相对亮度 **0.425**
**高于**这条带的**上限 0.265**，所以它**在白 / 浅灰底上物理上就不可能达到 3:1**：

| 稿 | 背臂 | 前臂渐变 | 三底最差 | 白底 |
|---|---|---|---|---|
| L1 本色 | `#04787B` | `#0A8C8E → #01C2C3` | **2.21:1 ← 不达标** | 2.21:1 |
| L2 深锚 | `#007D79` | `#008A85 → #009994` | **3.11:1** | 3.51:1 |
| L3 纯填色 | `#008A94` | 平色 `#008A94` | **3.74:1** | 4.15:1 |

⇒ 交付时**如实写**：L1 最"得物"但只能放深底；白/浅灰底用 L2 或 L3。
**别为了好看把 L1 的实测值藏起来。**

### 12.6 ★★ L2 的「折痕」会被搜索算法吃掉——要显式补回中间档

搜出来的带是 `[#007D79, #008A85, #009994]`。如果前臂渐变直接取"暗端 → 亮端"
（`#007D79 → #009994`），实测 Δlum 只有 **0.04** ⇒ 缎带折痕在视觉上**整条糊掉**，
看起来像一个纯色 V。

⇒ 把**中间档 `#008A85`（S=100%）当前臂起点**，与背臂 `#007D79` 的 Δlum 拉到 **0.0701**，
折痕全程可见。**"颜色合规"和"层次还在"是两个指标，都要单独测。**

同理 L1：母版那条前臂渐变的**暗端与背臂同色**（都是 `#04787B`），
直接沿用 ⇒ 字母上半截折痕**消失**。⇒ 向前臂起点换成比背臂亮一档的 `#0A8C8E`。

### 12.7 「对比度最差值」的表头别写反

`front` 声明是 `[(0, 亮色), (1, 暗色)]` 还是反过来，不能靠猜。**先按亮度排序再贴标签**：

```python
ends = sorted((h2r(c) for _, c in v['front']), key=lum)
# 表头写「渐变暗端 / 渐变亮端」，不要写「起点 / 终点」
```
（踩过：把 `ends[0]` 当成亮端，打出来「亮端 5.28 / 暗端 2.21」正好是反的。）

## 13. ★★ 内联片段：`show_widget` 的结构性限制

### 13.1 `symbol` + `use` 去重（顺带把重复 id 一起解决）

同一份字母要在评审板里出现二十来次。直接内联 ⇒ 每次一份 `id="L1-front"`，
**20 个重名 id**。HTML 规范要求 id 唯一，而 `url(#L1-front)` 按**第一个**匹配项解析——
当时所有副本颜色碰巧一致所以看着没事，但两个变体一旦共享 id，就是**真的上错色**
（已用浏览器实证：不是"视觉哈希碰撞"，是真的取到了另一份渐变）。

解法：每个变体只留一份 `<symbol>`，其它位置用 `<use href="#…">`：

```python
# 实测：片段 19.9KB → 11.8KB；id 从 20 个重名降到 5 个，22 处引用全部对得上
frag = '<symbol id="%s" viewBox="%s">%s</symbol>' % (pid, vb, inner)
frag = '<use href="#%s" x="0" y="0" width="%d" height="%d"/>' % (pid, s, s)
```

自证（写盘前 `assert`，别靠肉眼）：

```python
_ids  = re.findall(r'id="([-\w]+)"', HTML)
_refs = re.findall(r'href="#([-\w]+)"', HTML) + re.findall(r'url\(#([-\w]+)\)', HTML)
assert len(_ids) == len(set(_ids)), '有重复 id'
assert set(_refs) <= set(_ids), 'dangling 引用：%s' % sorted(set(_refs) - set(_ids))
```

### 13.2 ★★ setup 块必须放在**末尾**，否则 `show_widget` 直接拒收

**实测报错**：`"widget_code must contain exactly one <svg> element."`

原因：那张 `<svg width="0" height="0">` 符号表如果放在**开头**，整个片段就以 `<svg>` 起头，
校验器按"单个 SVG"去解析，于是报"有多个 `<svg>`"。

```python
# setup（符号表）放在末尾：内联 SVG 的 <use> 是渲染期按 id 解析的，前向引用没问题；
# 这样片段以 <div> 开头，渲染器按 HTML 处理，而不是当成单个 <svg> 去校验。
return body if renderer is None else (body + SETUP)
```

前向引用是合法的，**顺序改了画面不会变**——但要**证明**它没变：
把 `<use>` 版与直连版各渲染一次做逐像素比对，实测 **0 / 4012800**。

### 13.3 每次交付都要跑的两组 0-diff 自证

| 自证 | 为什么 | 实测 |
|---|---|---|
| `<use>` 版 vs 直连版 | 证明"剥 id 改引用"没改画面 | 差异 **0** / 4012800 |
| 断行前 vs 断行后 | 证明为了可读性加的换行没改版面 | 差异 **0** / 4012800 |

（换行安全的前提：容器是 flex，纯空白文本节点不生成 flex item。）

### 13.4 `%` 格式化残留守卫（承接 §10）

评审板 / 片段里大量 `%`-拼接，**占位符比参数多**时会打出 `%d` 字面量而不报错。
写盘前固定加两道：

```python
assert not re.search(r'%\d?\$?[ds]', HTML), '有未替换的占位符'
assert '%%' not in HTML, '片段里有 %%'
```
（本轮真踩到：`'%dpx;height:%dpx' % (box, svg_of(...))` ——**少一个参数**，
`%d`/`%s` 直接印进产物。）

## 14. ★★ 反向夹具：怎么保证"3 个坏样例都真的红了"

这一轮的关键方法论（可迁移到任何守卫集）：

### 14.1 别用「弱夹具」，要用**点对点**夹具

**踩过**：夹具是「让 SVG 自带 `width="1024"` 塞进 1024 画布」——
字母本来就占 ~52% 画布，**所有包围盒守卫照样通过**，
只有 `verify()` 内部一个 `assert` 炸了，而 `check()` 根本没记下来 ⇒ **"新红 0 条"**，
假绿。**这说明夹具在测的东西，和守卫在守的东西，不是同一件。**

⇒ 换成三个**定点**夹具，每个都指名道姓要某条守卫变红：

| 夹具 | 故意做坏什么 | 必须变红的守卫 |
|---|---|---|
| A 底板复辟 | 把底板矩形塞回去 | 包围盒 左/右/上/下 + 中线两笔宽 |
| B 笔宽缩水 | `stroke-width` 96 → 80 | 中线两笔宽（实测 `0..1023(1024px)` vs 理论 `343..451`）|
| C 满幅填色 | 整块不透明矩形 | ct=6 + 四角 alpha + 包围盒四边 |

```python
def red_for(tag, svg, want, label, note):
    shoot('bad_' + tag, svg, 1024, 1, os.path.join(TMP, '_lt_bad_%s.png' % tag))
    before = len(FAIL)
    verify(path, 1024, '坏样例' + label, VARIANTS[0])
    hit = [f for f in FAIL[before:] if want in f]
    check('%s -> %s 变红' % (label, want), bool(hit), note)
```

### 14.2 ★★ 成绩要**按颜色分开算**，否则夹具的红会污染真实结论

夹具的红是**证据**，不是缺陷。跑完必须把两者分开打印：

```python
real = (len(PASS), len(FAIL))       # 真实产物到这里为止的成绩——先快照
...                                  # 再跑三个坏夹具
print('真实产物：%d 项通过，%d 项失败' % real)
print('反向夹具：3 个故意做坏的样例，共 %d 条如期变红（这些红是证据，不是缺陷）'
      % (len(FAIL) - real[1]))
```

**实测口径（本项目）**：真实产物 **73 PASS / 0 FAIL**；3 个夹具如期贡献 **14 条红**。

## 15. ★★ 落到 Windows / Electron：打包图标 + 界面内联 SVG

矢量稿定稿后最容易漏的一步是**「界面里那两个小 logo 没跟着换」**。

### 15.1 ★★ 先消灭「三份来源」：让图标**从界面标记生成**

> 原版做法是「三份来源 + 写断言绑住」。**2026-10 实测改进为「唯一来源」**，更省事也更难错。

一份标记在一个桌面应用里通常是三处：

| 位置 | 形态 | 谁在读 |
|---|---|---|
| 标题栏内联 `<svg>` | 页面里手写的一段 | 渲染层 |
| 登录卡内联 `<svg>` | 同一段（尺寸不同） | 渲染层 |
| `build/icon.ico` | 二进制 | 打包器 → exe / 安装包 / 快捷方式 |

⇒ **只改一处**是最常见的错，而且**界面上看不出来**（标题栏和登录卡不会同屏出现）。

两种写法，**优先第一种**：

| 写法 | 做法 | 能抓住什么 |
|---|---|---|
| ★ **唯一来源**（推荐） | `build/icon.ico` **由 `index.html` 里那段 `<svg>` 生成**：读 `index.html` → 正则取出 `<span class="logo">` 内的 SVG → 去掉 `width/height`、补 `xmlns`、设 1024 → 光栅化 → 出 7 个尺寸 | 「图标与界面不是同一个标记」**从结构上不可能发生** |
| 各自维护 + 断言绑住（退而求其次） | 两处内联 SVG 逐字比较 + ico 结构自查 | 只能抓「两处不一致」，**抓不到**「图标是另一个标记」 |

★ 取 SVG 的正则 —— **找不到必须抛错**，绝不要 fallback 到「另写一份默认 SVG」（那等于又变回两份来源）：

```js
const m = html.match(/<span class="logo"[^>]*>\s*(<svg[\s\S]*?<\/svg>)/);
if (!m) throw new Error('在 index.html 里找不到 <span class="logo"> 内的 <svg> —— 标记结构变了？');
// 再补 xmlns、把 width/height 换成 1024（SVG 若原本没写 width/height 也要能处理）
```

这样 `<span class="logo">` 一旦被改名/换标签，脚本会**立刻炸**——这正是想要的。
脚本再配 `--source <外部文件>` / `--out <目录>` 两个参数：换源用来对比、换出目录用来做「不污染 `build/`」的验收。

### 15.2 紧致 viewBox：不改这里，小尺寸会又小又细

母版画布 1024×1024，字母标只占中间约一半（实测 bbox `252,260 → 772,776`）。
`viewBox="0 0 1024 1024"` 放到 17px ⇒ 笔画只有 **1.6px**；换紧致框 ⇒ **3.1px**。

```js
// 由 path 端点 ± stroke-width/2 算出，不是猜的：
// path = M300 308 L512 728 L724 308, stroke-width=96, linecap=round
// 圆帽端点会外扩，所以四边都要减这个 48，否则圆头被切掉
const BBOX = { x: 252, y: 260, w: 520, h: 516 };
```

### 15.3 ★ 同页两个内联 SVG 的渐变 `id` 必须不同

`url(#lgLogo)` 按**第一个**匹配解析（同 §13.1）。同一页写两个 `id="lgLogo"`
是**无效 HTML**，第二个会静默引用第一个 —— 两个变体颜色不同时就是**真的上错色**。
⇒ 用 `lgLogo` / `lgGlogo` 这种按位置区分的 id，并在注释里写明为什么。

### 15.4 手写 ICO：就三块，但守卫要**按尺寸独立解码**

```
ICONDIR      6 B      : reserved=0, type=1, count=N
ICONDIRENTRY 16 B × N : w,h(256 记 0), colorCount=0, reserved=0, planes=1, bitCount=32,
                        bytesInRes(4), imageOffset(4)
之后是每条的 PNG 数据（Vista 起允许直接内嵌 PNG，不必用 BMP+掩码）
```

守卫**不要只断言「文件存在」**：用 `pngjs`（或任何独立解码器）把每条**单独解出来**，
断言「签名是 `\x89PNG`」且「**解出尺寸 == 声明尺寸**」。实测 7 个尺寸全绿。
> 256 那条要排在最前：Windows 优先挑最大的。

### 15.5 小尺寸可读性要**出图看**

把 16/24/32/48/64 并排铺在**白底和深底各一张**，肉眼确认「16px 还认得出」。
（深底单独看，理由同 §12 的双向取最差。）

### 15.6 ★★ 断言不能只查「有 path」

旧的「方底 + 白 V」**也有 path**。所以要**同时**钉住形状和「不是旧的」：

```js
ok('两处 logo 是同一份矢量', JSON.stringify(title.ds) === JSON.stringify(gate.ds));
ok('是新字母标而不是旧方底白V',
   title.rects === 0 && title.ds.length === 2 && title.ds.includes(EXPECTED_D));
```

> ★ **但绑 `EXPECTED_D` 这种写法有代价**：每次换 logo 都要改断言，改着改着就会改成「恒真」。
> 换个更好的口径：只留**与具体图形无关**的几条 ——
> 「两处 `path` 逐字相同」+「ico 结构可解、尺寸齐全」+「**ico 角像素 == 界面标记颜色**」（§15.10）。
> 这样断言**一次写好、换 logo 不用动**，而"换了 logo 忘重新生成图标"照样会被抓住。
> 实测把旧断言换成这一组后，48 项全绿，且六条定点破坏各只红一条。

### 15.7 ★★ 选择器写错，会让断言「以不一致的形式」变红

登录卡那个 `span` 只有 `class="glogo"`、**没有 id**。断言里写成 `#glogo` ⇒ 查到 `null`
⇒ 「两处一致」直接 FAIL —— **看起来像 logo 坏了，其实是断言自己没找到元素**。
破案点就在 extra 里那个 `登录卡 null`。

⇒ 两条纪律：**① 选择器写完先确认元素真的存在**；
**② 失败信息里把查到的对象整个打出来**（`标题栏 {...} / 登录卡 null`），
否则「查不到」和「真不一致」在输出里长得一模一样。

### 15.8 ★★ 行为级验证：三个定点夹具，看**「只红哪几条」**

| 夹具 | 做坏什么 | 必须红 | 必须**不**红 |
|---|---|---|---|
| A 塞回旧方底 | 标题栏 SVG 加一个 `<rect>` | 新字母标 | 两处一致 |
| B 只改标题栏 | 只改**第一处** `d` 的末段 | 两处一致 + 新字母标 | ico 结构 |
| C ico 改坏 | ICONDIR 的 type 由 1 改成 2 | ico 结构 | 两处一致 + 新字母标 |

**「只红哪几条」比「红了没有」更能证明断言在查东西** —— 三条互不干扰，才说明它们各查各的；
如果拆了一个却全都红（或全都不红），先怀疑还有别的防线 / 断言根本没查到。
实测：基线 43/0 → A 42/1 → B 41/2 → C 42/1，源码逐字节还原 ✔、无残留备份 ✔。

**2026-10 又跑了一版**（唯一来源 + 行为级断言）：基线 **48/0**，六条破坏
（只改标题栏那处 `path` / 改界面底色使 ico 对不上 / 图标脚本改回读外部文件 /
检查按钮名改回术语 / 去掉「下一步动作」引导块 / 技术详情默认展开）
**各只红 1 条**，其余不动，源码逐字节还原 ✔。

### 15.10 ★★ 行为级断言：拿 ico 的**角像素**去对界面标记的颜色

「脚本是从界面读的」是个**代码级**事实 —— 改个写法/注释就能骗过它。
真正抓得住「换了 logo 却没重新生成图标」的是**行为级**那一条：

解出 `icon.ico` 里**最大尺寸**那张 PNG → 取**四角附近像素** → 和界面标记的底色
（`rect@fill`，没有 rect 就取第一条 stroke 的颜色）比，**每通道容差 ≤8**：

```js
const close = [0,2,4].every(i =>
  Math.abs(parseInt(htmlHex.slice(i, i+2), 16) - parseInt(icoHex.slice(i, i+2), 16)) <= 8);
ok('打包图标的底色与界面标记一致（换了 logo 没重新生成图标就会红）', close,
   `界面 ${htmlColor} / ico #${icoHex}`);   // 失败信息里两个值都打出来
```

★ 这条断言**与具体图形无关**（不绑 `d` 字面量、不绑 rect 有几个）⇒
下次换 logo **不用改断言**，只要记得重跑生成脚本。实测：只改界面底色、不重生成 ico ⇒ **只这一条红，其余全绿**。
（反面：绑死 `d` 的那种断言，每次改版都要跟着改，很容易被改成「恒真」。）

### 15.9 Electron 侧的两个事实

- **不设** `BrowserWindow({icon})` 也行：打包后窗口/任务栏图标来自 **exe 里的图标资源**
  （由 `build/icon.ico` 决定）。⇒ **别在开发模式（`npm start`）里验收图标**，那儿永远是 Electron 默认图标。
- 打包前**清掉 `dist/` 里旧版本的包**：发版脚本常有「dist 里只许有 1 个安装版 exe」的防呆闸门，
  升版本后新旧共存会被直接拒绝（实测就是被这条拦住的）。
- ★ 另：**换了图标内容就必须升版本号**，哪怕只是图标。同版本号重推 ⇒ 已装那版的机器
  「检查更新」会说「已是最新」，**收不到新包且不报错**。
