# Windows 端到端测试手册（雷电模拟器 + WorkBuddy）

> 目标：在 **Windows + 雷电模拟器** 上把整条链路跑一遍，确认没有整体性问题：
> 素材整理 → 合规检查 → AI 文案生成 → 货号颜色预检 → 发布单 / 导入 AI 内容报告 → 自动发布 → 结果回写。
>
> 配套文档：`docs/HANDOFF.md`（设计与硬约束、真机口径）、`README.md`（模块说明）、本文件（动手测什么）。
> 回归现状：**10 套 294 项断言全绿**（`node tools\run-all.js`）。
>
> 预计耗时：环境 + 回归 ≈ 20 分钟；手动全流程 ≈ 40~60 分钟（发布环节每条 65~80 秒，按条数算）。

## 4. 手动全流程（每步：操作 → 预期 → 出问题看哪里）

启动（免登录）：
```
:: PowerShell
$env:BLUEV_NO_LOGIN=1; npm start
:: cmd
set BLUEV_NO_LOGIN=1 && npm start
```

### 4.1 设置（页签 7）
- **操作**：填「输出目录 / 隔离目录」（都用绝对路径）；看「外部依赖」表；到「账号与安全」把出厂口令 `admin / BlueV@2026` 改掉（★ 2026-10-02 起**登录页与卡片都不再提示这组口令**，得自己知道）。
- **预期**：图片引擎显示 `sharp + libvips（含 HEIC）`；HEIC 解码「可用」。
- **出问题**：若显示「jpeg-js + pngjs（纯 JS 降级）」→ HEIC 会转不了，检查 `npm install` 是否装上了 sharp。

### 4.2 素材整理（页签 1）
- **准备**：`D:\你的素材目录\20260901\` 下，**每一条内容一个子文件夹**，例如
  `D:\你的素材目录\20260901\26FW-YB160+冠军白\1\`（里面放图片）。
- **操作**：「选择目录」→ **选到批次目录 `D:\你的素材目录\20260901`** →「生成清单」→「开始整理」。
- **预期**：
  - 清单：「N 个叶子目录 · M 个文件」；
  - 整理后生成 `D:\你的素材目录\flat_<时间戳>\`，每个叶子叫 `26FW-YB160+冠军白_1`、`_2`…（层级路径用 `_` 连接）；
  - 日志出现「原素材完全不动：20260901 保持原样，只建扁平副本」「已建硬链接 N 个」；
  - **原目录一个字没动**（重点验这个）。
- **出问题**：看日志里的 `扁平副本目录：...` 是不是在源目录同级；跨盘会从硬链接退化成实体复制（正常）。

### 4.3 合规检查（页签 2）
- **操作**：「开始检查」→「处理可自动项」；再试一次「检查父目录」→「导出报告」。
- **预期**：规则 = 必须 JPG / ≥1764 像素² / 边长 150~1500 自动等比缩放 / 视频**必须 `.mp4`**（非 mp4 会自动转，见下）且 <600s；垃圾文件隔离到 `_rejected`；
  导出后输出目录出现 `合规报告_<时间戳>.xlsx`（`汇总` + `明细` 两个表）和 `.csv`。
- **重点验**：一张**完全合格**的 JPG 只能显示为「合格」，**不能被移进 `_rejected`**。
- **重点验（非 mp4 视频，2026-10-02 新增）**：丢一个 `.mov` / `.m4v` 进素材目录 → 检查结果里它应是
  「**转 MP4**」且统计落在「**可自动处理**」；点「处理可自动项」后目录里出现同名 `.mp4`，
  原 `.mov` 被移除，且**这条素材仍然算视频**（不会被当成图片）。
  再丢一个坏文件（改名成 `.mov` 的文本）→ **必须报错**，不许出现「转好了」的假象，也不留半成品。

### 4.4 AI 文案生成（页签 3）
- **操作**：「选择素材目录并启动任务」→ 选 `D:\你的素材目录\flat_<时间戳>`（或批次目录）→ 再启动**第二个**批次。
- **预期**：
  - 「运行中的批次」里**同时**出现两行，各有进度/已用时；
  - 「查看详情」能看到该批次这一步的日志；「取消任务」「全部取消」可用；
  - 产物落到 `输出目录\batches\<批次名>\copy.json`，两个批次互不覆盖。
- **出问题**：批次名形如 `20260901_20260930153012`；重复启动同一批次会被拒（提示「正在处理中」）。

### 4.5 货号颜色预检（页签 4）
- **操作**：「同步商品池」（导入 CSV `货号,颜色` 两列即可）→「开始校验」。
- **预期判定文案（对齐真机）**：`颜色匹配` / `单色货号，颜色可空` / `多色货号须指定颜色（共 N 色：…）` / `货号 xxx 未查到颜色信息，请核对`；
  ★ 2026-10-02 起**只有「多色货号没填颜色」会拦住发布**：查不到货号、颜色不匹配 / 主色不符**都只告警**，
  发布单里那些行仍是「待发布」（颜色填错也能发，发布端按货号搜出来**默认选第一件商品**）。

### 4.6 发布单（页签 5）—— **两条路都要测**

**路 A：导入「AI 内容报告」**（真机链路的产物）
- **准备**：一份 26 列 xlsx，表头含 `素材路径 / 素材来源 / 标题 / 文案 / 内容类型 / 好物1_货号 / 好物1_颜色 …`
  - `素材路径` 是**绝对路径**（如 `D:\你的素材目录\20260901`）；**空着就会追问一次「这一批的素材目录」**；
  - **行数必须等于该目录下的叶子文件夹数**（一条内容 = 一个叶子）。
- **操作**：「导入 AI 内容报告」→ 选文件（必要时再选目录）。
- **预期**：提示「报告已导入：N 条待发布（用报告里的标题文案 X 条 · 本地生成 Y 条 · Z 条暂不发布）」；
  页面出现「当前批次来自 AI 内容报告」区块（含报告路径、表名、批次名、条数）。
- **故意验一次对不上**：把报告删掉一行再导入 → 应报
  「「D:\…」下有 N 个叶子文件夹（…），但报告里有 M 行指向它，对不上」→ **这是设计如此（不猜）**。

**路 B：导出我们自己的发布单**
- **操作**：「导出 xlsx」→ 预期输出目录出现 `发布单_<时间戳>.xlsx`（26 列），校验未通过的行标红。

### 4.7 模拟器发布（页签 6）—— 最容易卡的一段

1. **设备管理**：添加设备（序列号 `emulator-5554` + 账号名）→「检测在线」→「选用」。
2. **点「检查能不能发布」**（旧名叫「驱动自检」）：先看结论那一行 ——
   **绿色「一切就绪」**才可以真发；红色会**直接写出下一步该点哪里**（不是一堆术语）。
   术语明细收在「技术详情」折叠里：adb 路径（**含「是哪来的」**：你手填的 / 程序内置 / 系统 PATH）/
   设备在线 / 分辨率 / 得物包名 / uiautomator / screencap / ADBKeyboard（已装并启用 / 装了没启用 / 未安装）；
   任何一项红 → 系统会退回「模拟通道」（只演练节奏，不真发）。
   - **中文输入法没装或没启用**时，这条引导下面会直接出现**「一键装上中文输入法」按钮** —— 点它即可，
     它会自动重跑一次检查，结果行会变成「已装，且是当前输入法」。
   - 「adb 路径」那一格**留空**就是「自动」：优先用程序内置的那份（装完即用），找不到再退系统 PATH。
     只有想强制用某一个 adb（比如模拟器自带的）时才填完整路径；**填了就以你填的为准**，
     程序不会拿内置的偷偷替掉它。填了一个不存在的路径时会自动退回内置，并在检查结果里**明说**。
3. **抓取页面结构**：先把模拟器**停在得物发布页** → 点「抓取页面结构」→ 输出目录 `dumps\` 出现
   `ui-dump-<时间>.xml` 和 `uiMap-<时间>.json`（后者的 steps 是**按关键词猜的候选**）。
   **「得物发布页」到底是哪一屏、怎么去**（真机实测 2026-10-01 / 10-02，MuMu 12 / 得物 900×1600）——
   有**两条**路，都通向同一个发布页 `media.publish.activity.TotalPublishProcessActivity`（首屏是**选素材的相册**，
   顶部 全部/照片/视频 三个页签，缩略图 `imgThumb` **没有文字**，只能按坐标点）：
   · ★ **推荐**：底部「我」→ 右上角「主页」→「发布新动态」（3 跳；入口 `com.shizhuang.duapp:id/rlPublish`
     **有文字**，起点是固定底部导航，不是内容流）；
   · 备用：动态流**右上角那个相机图标**（`com.shizhuang.duapp:id/ivCamera`，1 跳，但 **text 与 content-desc 都是空的**）。
   ★ 首页自己的 tab 栏里**也有一个「视频」**（`tvTabTile`）—— 抓成首页会得到一份错坐标的表，
   而且不会当场报错。程序会在抓之前把「你现在停在哪一屏」打出来：停在别的 App 上直接拦下，停在得物但不是发布页只告警。
   ★ 图文与视频**位置一样**（2026-10-02 实测）⇒ 只抓这一次图文页就够，`videoSteps` 留空会复用 `steps`。
   ★ 发布页首屏是**持续动画**页，`uiautomator dump` 永远等不到 idle（实测连续十几次全报 could not get idle state）；
   程序会自动改用 `dumpsys activity top` 备用通道 —— **id / 坐标 / 是否可点都有，但没有文字**（界面会明说）。
4. **改对定位表**（必然要手改的一步）：打开 `uiMap-<时间>.json`，把每步的 `value` 改成你 App 版本里真实的
   按钮文本 / `resource-id` / 描述；用「失败恢复动作」配上失败后要执行的收尾动作。改好后「导入 UI 定位表」。
5. **开始发布**，预期日志（对齐真机）：
   ```
   开始发布（真实设备通道）：N 条，预计 X 分钟
   按 60 秒间隔，57s 后执行
   行 2[图文] 发布完成，已回填时间 15:34:41（耗时 65.2s）
   批量发布完成，总耗时 86.6s
   发布结束：共 3 条 / 1 失败，成功 2（真实设备）
   ```
6. **失败**：该行在表格里标红 + `输出目录\failures\` 有截图，行上有「重跑」；日志会写清
   「找不到「xx」；当前可见文本：…」（说明缺哪个节点，别猜）。
7. **重导出日志**：输出目录出现 `发布日志_<批次>_<时间戳>.log` / `.csv`。
8. **结果回写**（两条路分别验）：
   - 路 A（报告）：打开那份报告 xlsx，看 **B 实际执行时间 / C 执行结果** 是否落字；被卡的视频行应写「校验未通过：含 N 个视频…」；
   - 路 B（发布单）：打开 `发布单_*.xlsx` 看「实际执行时间 / 执行结果 / 审核状态」列。
   - **占用演练**：先用 WPS 打开该 xlsx → 再跑发布 → 应看到「报告仍被占用，N 条已暂存，下次再试」，
     且 `输出目录\pending-results.json` 里有内容；关掉 WPS 再跑一次导入或发布 → 自动补写。

### 4.8 打包（最后一步）
```
set ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/
set ELECTRON_BUILDER_BINARIES_MIRROR=https://npmmirror.com/mirrors/electron-builder-binaries/
npm run dist:win
```

#### 隐患 1（最危险）：`adb.dump()` 会拿**上一个页面**的结构冒充本页

- `uiautomator dump` **失败时不写文件** —— 实测：先在文件里放 47 字节哨兵 `<hierarchy>SENTINEL_FROM_HOME_PAGE</hierarchy>`，
  点开发布页后连续 6 次 dump 全部 `ERROR: could not get idle state.`，**哨兵一字未动**（仍是 47 字节）。
- 原实现 = 「共用一个远端路径 + 抓完直接 `cat` + 不检查 dump 的返回」⇒ 失败时 `cat` 出来的是**上一页**，
  `/</` 校验照样通过 ⇒ 返回给调用方。
- **后果不是报错，而是静默点错**。定点破坏还原成改前版后实测（P6+P9）：
  抓不到结构时它**拿着上一页的坐标连点 5 次**（`input tap 162 160 …`），并把结果标成「**发布成功**」。

**修法（两条独立防线 + 一条兜底）**：

| # | 做什么 | 位置 |
| --- | --- | --- |
| ① | 抓之前先 `rm -f` 远端文件 —— 失败时不会留下任何可被误读的旧内容 | `adb.dumpOnce()` |
| ② | 检查 `uiautomator dump` 是不是真的回了 `dumped to`；不是就走失败通道，并由 `dumpEx()` 带回**原因** | `adb.dumpOnce()/dumpEx()` |
| ③ | 报「页面一直不 idle」并**临时关掉三个动画开关重试一次**，无论成败都在 `finally` 里**还原** | `adb.dumpEx()` |

报错文案也从「uiautomator dump 失败：确认设备在线且没锁屏」（**误导**）改成带上真因
（「当前页面一直不 idle（得物发布页会这样）」+ 原始输出）。

#### 隐患 2：得物发布页**长期不 idle**

- 进 `TotalPublishProcessActivity` 后 `ERROR: could not get idle state.`，
  实测**连续 60 次（约 10 分钟）全失败**；wakefulness=Awake、无残留 `uiautomator` 进程。
- **单变量 A/B（同一页面、同一秒）**：`animator_duration_scale=1` → 失败、0 字节；
  只把它置 `0` → **立即成功、24263 字节**；页面不离开、还原为 `1` → **仍然成功**。
- ⚠️ **别把它写成「关动画是标准解法」**：另一次实测在动画=1 时同一页面也能抓到（页面自己稳定后就不受它影响），
  关动画只是**打断当前那个循环动画**的手段，不是根因。所以代码里做的是「重试兜底 + 还原」，不是「无脑关动画」。

### 追加（2026-10-01）：登录页去留白（窗口收缩 + 窗口尺寸回归）

**问题**：未登录时窗口是正常大窗（1280×820），登录卡片只占中间 340×372，**留白占比 87.4%**。

**改法**：`src/main/window.js` 增加登录门几何管理 ——
