# 清相册遗留问题复查（2026-10-12）

## 已确认并修正

- 最终目录校验原先用 `No such file or directory|not found` 判断目录缺失。行为复现证明，设备未找到、ls 命令不存在、其他路径不存在也会进入建目录分支。现仅接受 ls 明确报告目标目录不存在，其他失败继续拦截。
- ADB 返回对象原先丢失进程终止信息。现保留 killed、signal 和 timeoutMs；最终 ls 校验失败且无 stderr 时，错误信息包含限时及终止信号，或退出码。
- 读取失败仍禁止继续发布；未增加自动删除、重试或跳过校验。

## 继续排查：超时叠加与批次连续失败

- 核对本地构建 03、06、07 的实际 app.asar：三者都有空目录提前退出和旧最终 ls 校验；只有 06/07 有媒体删除重试。之前的媒体库修复没有覆盖目录命令超时路径。
- 云端最新记录仍停在 DESKTOP-JNASAVD 的 569 秒失败，没有新增现场诊断数据；任务表没有客户端构建号，不能确定该机器的具体构建。
- 在内存中恢复原目录执行顺序并模拟设备命令均超时：旧流程执行四条目录命令，超时预算共 180000ms；修改后在首条 find 中断时返回，只执行一条，超时预算为 60000ms。这是指令预算对照，不是故障设备的实测耗时。
- 目录初次 find/rm/ls 被终止时停止后续清理；最终 ls 被终止也返回明确错误码。发布层收到 ALBUM_IO_INTERRUPTED 后仅将当前条记失败，停止本批次，其余条保持待处理，不再抓失败截图叠加设备等待。
- 新增真实发布函数行为测试：三条输入只清理一次、只记录一条失败、另外两条保持排队，并验证无推图及截图。

- 新增只读诊断脚本 `tools/album-diagnose.ps1`，逐项八秒限时，区分 ADB 响应、目录读取、递归文件读取和四张 MediaStore 表查询。本机实测全部成功：目录读取约 62ms，递归读取约 65ms，四表查询各约一秒；它不是故障机器。

## 同轮回归发现的登录窗口问题

gatetest 单独复跑仍有两项失败，窗口为 340×200，不能解释为一次负载波动。登录页 requestAnimationFrame 的量高回调可能晚于 auth:ui-ready 返回，fitGate 又把已恢复的窗口切回登录模式。渲染层现在用版本号作废旧量高回调，并在切主界面前取消旧版本；隐藏登录页时也不再发送量高消息。

修复后原 20 项登录窗口检查通过，另增加延迟量高回调的行为用例；最终完整回归另存 `audit-regression-20261012-complete.log`。

故障设备只读诊断命令（Windows PowerShell；AdbPath 填那台电脑安装目录中的 resources/adb/adb.exe，Serial 填实际设备串）：

```powershell

```

脚本不清理文件、不强停得物、不重启 ADB，只生成本机 `album-diagnosis.json`。
