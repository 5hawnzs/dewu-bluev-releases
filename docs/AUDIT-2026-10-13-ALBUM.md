# 2026-10-13 发布拦截链路复核

> 历史诊断：适用 1301，不代表当前版本状态。当前验证结论见 [VERIFICATION.md](VERIFICATION.md)。

适用构建：1.1.1 / 2026101301。故障设备 rich 的 2026101209 云端记录显示：清理素材文件阶段，媒体查询返回完整视频行，同时 stderr 为 Segmentation fault，退出码 139；单次约 1.2～1.4 秒，批次耗时 32.1 秒。不能据此断定崩溃发生在关闭游标阶段。

## 确认并修正的遗漏

1. 媒体查询已处理没有 stderr 的 139，但没有处理同时携带精确崩溃提示的返回。仅在 139 且未被终止时移除该提示，保留其他错误；完整记录继续用于删除，不视为空表。空表必须明确返回 No result found。
2. 全盘清理后的重扫存在同类误拦。扫描返回需具有完整 Bundle 格式；之后仍查询四张媒体表，扫描结果本身不代表清空。
3. 服务自愈原先没有继承清理总截止时间，可能额外启动两轮 20 秒命令。重连与原命令重试现在共享截止时间；创建素材目录也共享预算，超时归为清理中断。

4. 提交后系统桌面或权限弹窗也可能被当成退出发布流程，过早开始下一条清理。现在非得物前台不能放行；未知前台继续等待，超时暂停后续。

## 限制

- 本机模拟器只读查询未重现 rich 的崩溃，因此现场格式验证通过不等于故障设备已恢复。
- 完整行的格式校验不能证明崩溃命令枚举了整个游标；因此不能因收到记录就判空，必须删除后得到明确空结果并再次复查。
- 提交按钮已点击、页面返回与账号侧实际发表及平台审核是不同层次；现有结果口径不代表后台审核结果。
- 设备长期离线、权限被拒或媒体服务持续无有效回显时仍须拦截，不能安全强行继续。
- 不改用户模拟器、不提交真实帖子、不自动安装或重启本机应用。
